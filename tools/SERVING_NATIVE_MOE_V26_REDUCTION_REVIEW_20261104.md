## Private addresses and contributor coverage

The payload address is indexed by `(phase, CTA, boundary, warpgroup, token-tile, lane-component)`. There are two boundary regions per CTA and phase; a contiguous CTA stage range can intersect at most two partial units. Whole units produce their epilogue directly and need no payload. The boundary selector is0 when the unit contains the CTA's original range start, otherwise1. This remains correct when phaseA executes the trailing partial first. A short range wholly inside one unit uses only boundary0; an empty range writes neither.

The owner scans from the original first-stage CTA (`pd.slot`) through the CTA containing the unit's last stage. It reconstructs the exact cost-weighted boundaries, carries `g1` forward as the next `g0`, and skips empty/nonintersecting ranges before deriving a payload pointer. All contributors to a split unit are necessarily partial: a CTA containing the whole16-stage unit would leave no stage for another contributor. Every selected pointer therefore has a producer. Increasing CTA order is increasing original K-stage-range order despite rotated execution.

## Publication, consumption and reuse

The original `WGSDFIN=2` policy remains: phaseA finishes on the last arriving contributor; phaseB's first-stage CTA waits for all other stage counts. No fixed phaseA owner or new wait dependency was introduced.

Each of the128 warpgroup lanes stores its own private vectors before entering the existing warpgroup `bar.sync`. Its leader then publishes the stage count with the original GPU-scope release/acquire atomic protocol. PhaseA's final `atom.acq_rel` and phaseB's acquiring count read establish completion before the owner reads payloads. A second warpgroup barrier distributes that synchronization to the reading lanes. The unchanged GPU acquire fence remains before the reads. PTX observation order explicitly permits an intervening chain of atomic RMW operations, so the aggregate count is not merely evidence for the last contributor's stores. The per-lane stores are ordered through the warpgroup barrier and transitive synchronization. [NVIDIA PTX memory model](https://docs.nvidia.com/cuda/archive/13.0.2/parallel-thread-execution/index.html#memory-consistency-model).

There is no private-payload clear after consumption. A CTA writes each boundary at most once per phase; phaseA and phaseB have separate regions. A counter keyed by a unit's first-stage CTA cannot represent another split unit in that phase during the same call: the only split unit starting in that CTA is its trailing boundary (or its sole short unit). Therefore the leader's counter reset does not enable a new producer to overwrite data while other owner lanes finish their loads. Reuse occurs only in a later call under the inherited explicit serial-workspace contract, after the current grid and stream dependencies complete. Shared overlapping workspace use remains unsupported. Cooperative admission and actual GPU execution must still be checked.

This is a source-level CUDA memory-order argument, not a hardware race detector or formal GPU proof. Missing arrivals, wrong range ownership, or early overwrite would invalidate it; the focused source/CPU checks target those conditions. CPU success alone cannot establish the new compiler resources, device numerical agreement, graph concurrency, or speed.
