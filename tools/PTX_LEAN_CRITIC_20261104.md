# Independent review: source-bound MULDEC proof

**GO for the limited source-level unsigned32 verifier.** This does not certify the complete kernel or establish a speedup. The direct runtime speed effect is exactly **0%**: neither the kernel nor its launch changes. The useful result is a reusable rejection gate for wrong bit manipulations before a GPU experiment.

I independently inspected the final proof, source extractor, fresh-build path, proof contract and upload integration. The final `Dq4.lean` compiled directly with Lean 4.35.0. I then ran the complete verifier on exact incumbent `247888acca10f50d8c5db283676ffd93334869467f4632e4a320b34cb20c9ef0`; it returned `proved_fragment` in 9.142 seconds. All seven base and four generated theorem audits used only `propext`, `Classical.choice` and `Quot.sound`. No custom/native axiom or `sorry` was accepted. Seven binding tests and three mocked workflow tests independently passed. The separately inspected real integration report proves the incumbent and records Lean rejection of rotation 3→4, one extra mask bit and multiplier 4228→4224; those three real mutant runs were root's, not an additional independent rerun.

The theorem covers all 2^32 unsigned input words, including multiplication modulo 2^32. Four reconstructed words equal a separately expressed bit-placement specification. The 32 listed positions form a permutation; the finite multiply sublemma covers all 256 pairs of four-bit codes with kernel-checked `decide`. The correspondence between that specification, the position list and the pinned Python packing functions is a reviewed link, not a proved full tensor pack/decode theorem.

The review found three concrete source-binding defects, all repaired before this verdict. C++ backslash-newline splicing now precedes comment removal, including CRLF, so a continued comment cannot silently hide a real assignment from C++ while leaving it visible to the checker. Direct packing-map subscript writes/deletes and method calls are rejected. Macros overriding the modeled arithmetic identifiers are rejected. Focused mutations make these fixes falsifiable. Changed expression shapes, types, shifts, packing definitions and duplicate writes also fail closed. The candidate is AST-parsed, never imported.

Every verification checks proof-file and Lean/Lake executable hashes and builds in a fresh temporary directory. It does not reuse repository proof artifacts. Caller-selected Lean paths are removed. Generated candidate definitions contain the five extracted constants; saved JSON cannot bypass proving them again. The optional upload gate proves the frozen source, rechecks its digest, and records proof provenance before querying status. Failed proof prevents an official call; a later status failure preserves the accepted receipt. These are local/mocked tests, not an official submission.

The accepted scope retains explicit assumptions: ordinary unsigned32 and builtin funnel-shift behavior, distinct output registers, immutable packing maps, and a reviewed surrounding environment. Indirect aliases, reflection, arbitrary Python side effects, external macros/compiler flags and full C++ execution are outside certification. The local contract and the verified installed toolchain bundle remain trusted; hashing two executables is not hostile-filesystem attestation of every library. No claim covers floating-point interpretation, scales, MMA, dispatch, PTX/SASS, memory safety, asynchronous barriers, termination, full numerical correctness or performance. Unsupported new expression families require a newly reviewed translation and proof.
