# Fixed serving-finalizer GPU validation — 2026-11-04

This is component validation of frozen helper `91e6173baa984fb873994cc3cd2883da16e013091f10218262785e70e613ed98`, after official v22 passed its stock-Marlin component screen. It is not a new performance search, full Muse serving validation, or authorization to allocate. Root owns the runner, credit guard and one allocation. Author owns only the worker, this plan and a focused local contract test.

`tools/serving_finalizer_validation_worker.py` exports `build_payload(root,image)`, `validate_payload(payload)` and `run(payload)`. It uses only Python stdlib until invocation, then imports the installed Torch/Triton and the two supplied helper files directly. It never imports SGLang, model weights or evaluator internals. Payload file set is exactly `candidate.py`, `baseline.py`, `finalizer_validation.py`; hashes bind every file, including the frozen upstream helper `9b816e971817f96a22d2d09424dc8dfa6f6020e18de73fb895674c76494fe591`. Root stages/invokes this worker using the existing bounded Modal lifecycle. Output/checkpoints use `/tmp/okc-result.json`, capped at1MiB. One H200,600s outer timeout; worker stops beginning further tests after540s. An in-progress CUDA call/compile remains bounded by the outer worker/sandbox timeout, not a claimed Python interruption guarantee.

Numerical criteria are fixed before GPU execution. Compare new output to both unchanged original helper and an independent Torch FP32 expression oracle: shape/dtype match, then whole-output relative L2≤0.015 and worst-row relative L2≤0.075, with the official check's0.1×mean-row-norm floor and1e-12 absolute denominator floor. Diagnostic differences/norms accumulate inFP64 to prevent finite large values overflowingFP32 statistics; these are the same mathematical thresholds/floor, not a byte-identical evaluator implementation. Nonfinite metrics fail. These are the existing standalone MoE evaluator limits, not a full-serving output-agreement guarantee. Report actual whole/row/max-absolute errors; no rounding of results before comparison. For intentionally exceptional values, require identical NaN,+Inf,-Inf masks and use the same metric on finite positions; no NaN payload/bit-equivalence claim. Unchanged fallback outputs additionally require exact value equality with equal-NaN treatment. Original-vs-oracle disagreements are separately reported and fail even if candidate matches original. Stop on the first material failure; persist seed, case/mask pattern and mismatch metrics.

Fixed finite coverage is deliberately not a Cartesian product: allT1..31 at sharedH511/K3; selected H1/7/255/256/257/512/4096/16384 paired with K1/2/5/8/32; optional weight/apply-norm/weight-first/IDs combinations reuse H511/K3. Directed cases cover BF16/FP16/FP32/FP64 auxiliary dtypes, int32/int64 IDs, contiguous/noncontiguous x and auxiliary tensors, negative/zero/positive IDs, allremote/onelive/alternating masks, poisoned invalid x, cancellation, very small/large finite data and epsilon0/1e-8. Exceptional cases reuse H1/K1 and finiteH511/K3 signatures. T0 and unsupported T32/33, H16385, K33, FP32 x and broadcast norm weights exercise original branches. Large-path controls use finite data because the inherited large kernel skips invalid-route arithmetic, whereas the small eager original evaluates zero-slot arithmetic.

The actual90-case manifest is exported by `cases()` and hashed in the payload. It includes explicit no-norm positive/negative infinity outputs, NaN/infinite/negative epsilon, and1e-39 BF16 subnormal inputs in addition to1e-30 tiny values. Kernel-signature variants include H/K, allconstexprflags and every pointer dtype (x/scores/weight/IDs); the current conservative bound is62 small-kernel variants against a fixed80 cap. T/grid changes do not create new constexpr H/K variants. This is a safety cap, not an assertion about Triton's internal compiler cache. No additional shape/epsilon tuning is permitted after results. Six warmed profiler calls require actual CUDA events with positive duration: both newkernels atT31, the originalkernel atT32/33, and eager fallback atFP32/K33/H16385. Missing CUDA profiling evidence fails activation coverage; host tracing cannot substitute.

Concurrency/capture validation uses two warmed nondefault streams with explicit producer-stream dependencies, separate input objects, and multiple outstanding outputs retained until comparison. Two independent CUDA graphs are then captured on their own streams. Each replay copies fresh same-shape values into its own static inputs before replay, retains output copies for every iteration, and verifies both graphs against original/oracle outputs. The worker records distinct output and captured inverse-scratch allocation pointers without changing the helper: a temporary `torch.empty` observer delegates the allocation unchanged during the single-threaded capture calls, then is restored before replays. Captured outputs/graphs/static inputs remain alive through all checks. A later replay of graphB must not change graphA's held output. This tests concrete two-stream/two-graph independence, not every possible serving scheduler/rank interleaving.

No kernel timing or throughput decision is made.
