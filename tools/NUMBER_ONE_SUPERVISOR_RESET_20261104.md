The concrete missing axis is **eliminating the correction execution while retaining the cheap original decoder**, rather than moving the same FP32 corrections or changing geometry. Current SK2 stores768 bytes per512 BF16 weights, clamps an exponent offset into a matrix-wide eight-value window, then uses separate correction warps/planes to recover exceptions. The earlier dictionary proposal removed these warps but added dictionary lookup work (about15 versus12 source integer operations per decode8). The local consecutive-window alternative retains cheap decode but the saved histogram shows5.86–7.10% raw-unit fallback, not3–4%, causing8.33–9.99% extra requested bytes with even an ideal4-byte header.

Instead, retain the parent matrix-wide window and low/code payload. Append one32-bit descriptor per8×64 unit: no exception, one exception carrying its original16-bit BF16 bits and9-bit owner position, or a raw-sidecar index for two or more exceptions. The ordinary consumer runs unchanged `decode8`, then fixes the selected16-bit half of its register before MMA. Use statically unrolled eight-word selection; a dynamic addressable register array risks spills. Raw units read their original1024 bytes. Remove the correction warps/planes and their handback counts coherently. Preserve row/K geometry, all COMP0/router work, PDL and UV/BND output semantics. Header padding and exact ring-size changes must be calculated rather than assumed free.
