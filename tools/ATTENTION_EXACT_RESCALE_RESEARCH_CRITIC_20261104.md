The proposed conditional skips only those sixteen O products when all participating row scales are exactly one. Use the already computed alpha comparison, not a tolerance or a substitute maximum-change condition.

The preferred simple realization is the donor-style `if (alpha != 1.f)` around only the sixteen O multiplications. It introduces no collective or new participation requirement. Alpha is quad-shared; different row groups may diverge, and the compiler may predicate the multiplies. This leaves branch policy and emitted savings to compilation and measurement, without requiring a warp-vote design. The vote-based version below is only a conditional alternative, not the recommended starting point.

Per eligible tile and warp, the source can remove sixteen scalar multiply instructions if emitted separately (512 lane products). It also has sixteen QK and sixteen PV warp MMA calls, nine exponent evaluations per thread, reductions, loads and synchronization that remain. A compare and conditional execution are added even when skipping fails (and a vote only in the alternative collective version); these counts do not establish cycles or a critical path. One row changing scale can prevent an entire warp from skipping. No new shared/global traffic is needed. ## Correctness conditions before implementation

1. **Avoid a new collective, or prove participation if one is chosen.** The simple scalar conditional requires no vote. For the alternative vote version, `m_new` is guaranteed uniform only within a four-lane row group, while the enclosing `if (m_new != -INFINITY)` can differ across groups for exceptional inputs. A full-mask vote placed inside that branch without further proof is invalid. CUDA requires named non-exited lanes to execute the matching intrinsic with the same mask. An explicitly justified active-subgroup mask can conservatively skip within that subgroup, but `__activemask()` alone does not prove a full warp converged. Alternatively place a properly defined full-warp vote outside divergent control without changing arithmetic. Specify one realization and prove every participating lane and mask; do not assume exceptional rows impossible without the task contract. [CUDA warp intrinsics](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/cpp-language-extensions.html).
2. **Retain numerical scope honestly.** Ordinary IEEE FP32 multiplication by positive one preserves finite normal/subnormal values, signed zeros and infinities. A multiply may quiet or change a NaN payload; copying is not universal NaN-bit equivalence. If the compiled O multiplication flushes subnormals, skipping it can also differ. Current build uses `-O3` without `--use_fast_math` or `--ftz=true`; the explicit `ex2.approx.ftz.f32` does not make every other instruction FTZ. The PTX distinction is documented for [floating-point multiply](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html#floating-point-instructions-mul). Alpha NaN must fail the equality test and follow original multiplication. Preserve the original row-sum arithmetic even at alpha one.
3. **First and empty tiles remain correct.** On the first live finite tile, old maximum is minus infinity and alpha is zero, so execute the original rescale. All-invalid branches retain original behavior. `ONE` specialization already eliminates O rescaling and must remain unchanged. Mixed one/non-one scales, signed zero, finite subnormals, nonfinite values and partial participation are required directed checks; CPU semantics cannot prove GPU synchronization or lowering.

This differs from existing `OKC_LAZY1=1`: that path holds an older offset until a threshold, changing probability magnitude and FP16 rounding, and conditionally updates both L and O. The exact-one proposal preserves the current offset at every tile. Q8 already uses its distinct lazy machinery and is out of scope.

## Falsifiable decision

Before a test: exact source-only scope, proof that no new collective was introduced (or full participation proof if root instead selects a vote), directed numerical/control checks, and matching current public/private comparison contracts. No broad new test platform or separate profiling run is necessary just to authorize a reversible experiment.

Suggested fixed screen for root to accept or replace **before** testing: complete official 16 correctness tests and 12 benchmark/profile cases; affected normalized-latency GM at most `1/1.01` versus both parents, at least three of five affected cases faster versus both, no affected case over 1.02 latency, and unchanged-control latency GM within [0.98, 1.02]. This is a consistency screen, not statistical significance. Preserve observed selected dispatch. Whole-decoder integration requires its own measured result; no 1% whole-layer promise.

Kill the fixed attempt for invalid participation/numerical semantics, correctness/resource failure, or failure of the agreed performance screen. If compiled code leaves all sixteen multiplies on the supposedly skipped path or branch overhead dominates, close this mechanism rather than widening into lazy-offset, reschedule or mask/threshold sweeps. There is no evidence yet that this can close the leaderboard gap.
