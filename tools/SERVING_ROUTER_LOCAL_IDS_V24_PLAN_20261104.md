# V24: separate local IDs in the existing serving router

Fixed source base: SGLang `a55ab7d5ae1bba59ac351e55026fe7f7644ecc5f` (Apache-2.0). The isolated `serving/candidates/router_local_ids_v24/` contains only five exact stock files, their candidate copies, the retained license, reproducible builder, unified patch and SHA-256 manifest. The existing checkout's finalizer and alignment edits are excluded. No native kernel incumbent changes.

The stock NVFP4 Marlin, non-SP serving path requests packed routing output that Marlin ignores, then launches Torch indexing for `expert_map[topk_ids]`. V24 writes a separate int32 local-ID output in the already selected CUDA JIT router, from the winning **global** `out_id`, and lets Marlin consume it directly. The original IDs, FP32 scores, top-k selection, tie handling, normalization, PDL operations, GEMMs, alignment and finalizer stay unchanged. The current expert map is read from `self.experts._expert_map` every invocation, without caching it on the routing object.

The opt-in `forward_with_local_ids` returns `(scores, original_ids, packed_or_None, local_or_None)`. Existing calls and their two-/three-result return contracts retain their defaults. It calls the normal BaseFusedOp dispatcher, never forces JIT, and does not use `auto_selected_backend()` as activation evidence. Only actual `forward_jit` allocates/fills the fourth output and suppresses packed output. In-tree Triton/native/CPU fallbacks return the original packed triple plus `None`. The wrapper routes compile mode, unrecognized/OOT/custom dispatch, unsupported forced modes, existing local mapping, valid-token state, or SoL capture state through the old call with local=`None`. Marlin then performs its original mapping. These exclusions are eligibility constraints, not workload-shape tuning. Normal CUDA graph capture remains eligible: allocations are graph-pool outputs and the map's lifetime follows the existing stream/capture contract.

The low-level Python wrapper retains its three-result return and appends optional `marlin_expert_map`/`marlin_topk_ids` arguments. Both must be supplied together. CUDA validates shape/dtype/device/contiguity and storage-span disjointness of the new output versus all router buffers, and the new map versus writable outputs. It writes padded local slots directly as `-1`, without indexing a negative global ID; padded FP32 scores remain untouched just as in stock. Production opt-in excludes `num_valid_tokens` entirely because the old separate Torch indexing of `-1` can select the last map element; V24 does not silently change that old behavior. Existing `local_expert_mapping` still has its stock semantics on ordinary output IDs; the production opt-in requires it absent.

The model preserves global-ID consumers: activated-expert capture receives the original `topk_ids`, SP takes the old route and old global-ID contract, and DFlash's physical token order is unchanged. Local output crosses from the routing side stream to the main stream using the existing join and `record_stream(main_stream)` outside capture. The per-call map is recorded on the routing side stream outside capture. No persistent scratch or output reuse is introduced. Marlin receives explicit local IDs only when the router returns them; there is no ID-range heuristic and no consumption of an uninitialized buffer.

For T tokens and K routes, excluding common global-ID/score writes, stock requests packed-write + global-read + map-read + local-write = `16*T*K` logical bytes. V24 requests map-read + local-write = `8*T*K`, removes one packed BF16 conversion/store per slot and one indexing launch, and swaps one `4*T*K` packed allocation for the local output. Map loads can extend the router's critical path and alter register allocation. These are source-level work counts, not DRAM savings or predicted speed. V22's observed index row was only 0.5–3.2% of its full MoE component; native decoder97af/standalone247888 already combine routing/local mapping, so this is serving-only. No full-model gain is claimed.

Fixed pre-result component gate (root): bit-identical global IDs, FP32 scores and local IDs versus the actual stock JIT router followed by Torch mapping; actual JIT activation and one indexing launch removed; geometric-mean net router+map **latency ratio <=0.95** over T=8,16,32,128,256, and no production case latency ratio >1.02. No threshold retuning or rescue sweep. Side-stream, graph replay and map-replacement cases are correctness requirements, not extra performance samples. Generic valid-token low-level tests must distinguish the new explicit `-1` sentinel contract from old `map[-1]`; they do not qualify production opt-in.

CPU evidence is intentionally bounded: complete reversible patch/source binding; actual BaseFusedOp dispatch and candidate opt-in wrapper with stubbed backend numerics; actual low-level wrapper argument/tuple checks; native C++ execution of extracted new store/sentinel/alias logic; and model/Marlin call-chain source checks. It cannot prove CUDA compilation, register/resource effects, PDL behavior, stream/capture memory safety, or GPU score bits. The separate component harness must load the actual isolated original/candidate wrappers and owned headers, preserving dependency/build provenance and avoiding installed-source/op-registry mutation. One future reviewed GPU experiment is required; this plan authorizes no provider call or submission.
