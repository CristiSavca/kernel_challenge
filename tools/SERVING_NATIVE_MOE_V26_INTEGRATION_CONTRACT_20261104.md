## Highest-priority boundary: replace weights before Marlin repacking

`layers/quantization/muse_spark_nvfp4_moe.py:128–146` is the narrow hook. `_process_weights_for_marlin` aliases six serialized parameters to generic Marlin names, calls the parent's postload conversion, then deletes the serialized names. Consequently, attaching V26 after that call cannot simply obtain the original FP4/E4M3 arrays. Retaining both banks would defeat the memory objective.

The smallest adapter should attempt installation **before those aliases/repack**, only for this Muse SM90 BF16 Marlin configuration, H=I4096, K8, group16, contiguous <=32 local experts, no expert TP, and a compatible execution-lane contract. The actual model constructor rejects interleaved expert checkpoints (`models/muse_spark.py:1329`), so no new W13 reorder is needed for this supported model. Do not silently widen that assumption to other models.

Use `prepare_native` with the six raw tensors mapped as follows:

| V26 key | Existing serialized parameter |
| --- | --- |
| `w13`, `w2` | `gate_up_proj`, `down_proj` |
| `w13_sf`, `w2_sf` | `gate_up_proj_weight_scale`, `down_proj_weight_scale` |
| `w13_gs`, `w2_gs` | `gate_up_proj_weight_scale_2`, `down_proj_weight_scale_2` |

Pass `source_is_local=True`, `local_start=layer.local_expert_offset`, `local_count=layer.num_local_experts`, `globals_prepared=False`. The loader already slices expert stacks by EP rank (`models/muse_spark.py:1444–1463`); slicing these local tensors again by global offset is wrong. V26 itself preserves stock gate-column collapse and BF16 global-scale preparation. It qualifies all block scales before packing, including zero/subnormal LUT handling. Do not recover the up scale, fold norm factors into the bank, or apply preparation twice.

Installation needs a prepare/commit boundary: qualify and construct the complete bank, successfully initialize both CUDA specializations, then register the five bank tensors as layer-owned derived buffers and publish the native-path marker. Only then release the six original registered parameters/aliases. Do not also invoke stock Marlin preparation. If metadata/format qualification declines, leave the layer unchanged and use its ordinary stock preparation. Unexpected compile/OOM/runtime failures should remain explicit, not be swallowed into a partially initialized layer. Once raw weights are released, there is no runtime Marlin fallback for that layer.

Use registered ownership, not an untracked tensor dictionary alone. The normal loader's `stage_module_for_post_load` snapshots tensors until its context exits and handles registered replacements; newly created nonpersistent buffers remain on the processing device. Initial scope should exclude offload, hot-reload and module device migration until those lifecycles are implemented. No edit to the prohibited `model_loader/` directory is needed. Preserve input-scale parameters and unrelated module state unless their users are separately audited.

## Forward adapter: finalize each chunk before reusing scratch

The H200 `forward` selects `_forward_marlin` directly (`layers/muse_spark_fp4_moe.py:683–705`). That method applies the existing pre-expert norm, obtains route outputs, refreshes the effective post-norm cache if necessary, and calls the finalizer with its actual epsilon and norm form. Routing has already joined its side stream before this call (`models/muse_spark.py:833–904`); retain the global IDs, score bits, capturer and `record_stream` behavior.

A replacement only inside `_marlin_expert_outputs` would still need full `[T,8,4096]` route output, **1 GiB at T16384**. Instead, add a native branch in `_forward_marlin`: preserve pre-norm exactly once over the original input; refresh the real cached norm metadata; then execute chunks of <=384 through `expert_outputs`, immediately call the **original** finalizer, and write the combined BF16 chunk to the final result before reusing the workspace. For a whole call T>=32 with a short last chunk, preserve V26's masked padding to32 so it retains the original large-token finalizer branch. T0 remains an empty result. No expert, score or padding token may be discarded.

Do not call the official `prepare/kernel_fn` wrapper verbatim: its default rank0, `1+w` norm construction and fixed epsilon are benchmark adapters. Serving must pass `_post_expert_norm_weight`, `_post_expert_norm_eps` and `_post_expert_norm_weight_first` from the existing module. Keep its missing-norm error and fallback semantics. Initial installation can require a compatible existing cached norm path rather than approximate an unknown norm module.

Keep finalizer source `9b816e97…` from the pinned checkout. The working tree contains the separate V22 edit, which failed broader numerical coverage; do not bundle it or the alignment patch. Keep the unchanged outer `_reduce_and_unpool` all-reduce and projection (`models/muse_spark.py:751–779`). V26 returns this rank's BF16 contribution, not an already-reduced result. SP dispatch, expert TP and alternate backend paths are outside this adapter; their exclusion must be determined before releasing stock weights, not after entering a forward.

## Persistent and peak memory

One full bank is **905,969,664 B (864 MiB)** plus128 B of prepared globals and1024 B LUT for32 experts. This replaces the corresponding code/scale storage; it is not an extra retained copy. For N converted layers, bank storage is N×864MiB: 50.625GiB at60 or52.3125GiB at62. The actual checkpoint's sparse-layer count remains to be read from loaded metadata; source defaults are not that evidence.

During one layer's conversion the old and complete new banks coexist: **at least1.6875GiB for that layer**, plus repacking temporaries and the rest of the model. The2048-row slab bounds dimensions, but not to a few MiB: `_pack_codes_nat` materializes a64MiB int64 array plus other arrays. `stage_module_for_post_load` can retain old tensors until context exit. Measure actual allocated/reserved peaks after each converted layer; do not promise a tight peak from this source inventory. Convert and release layer by layer, never build all native banks beside all Marlin banks.

V26 Workspace is **129,005,088 B (123.028839MiB)**, including40MiB private partials, BF16 activation rings and24MiB route output. One workspace per62 layers would cost7.449GiB before extra graphs. Prefer one **target-model/device/execution-lane-owned** workspace shared across serial layers and shape buckets. Do not allocate it in each layer's weight preparation. At T16384, chunking uses43 core/finalizer iterations (43 core launches plus43 large-token finalizer launches) and a128MiB combined output, plus existing input/pre-norm storage and small score buffers. The six timed component cases stop at256 tokens. They do not establish prefill speed or compliance with the serving TTFT limit; this is a material unmeasured risk.

One bank is our memory design objective, **not a contest mandate**. If stock prefill proves materially better, alternatives include keeping stock for unconverted layers, or retaining both formats on selected layers with a measured memory/throughput tradeoff. A second full copy costs864MiB per selected layer, plus its own workspace; it is not categorically impossible, nor known to fit. Do not promise all-layer dual retention or silently introduce a shape fallback. Record actual loaded sparse-layer count, available capacity, KV/draft/graph reservations and peak memory before choosing that different design.

## Streams and CUDA graph ownership

The parent scheduler encloses its regular overlapped forward in `forward_stream_ctx` (`scheduler.py:4395`), and the router side stream is joined before experts. This supports serial sharing in that path, not a universal concurrency guarantee. Decode capture uses a separate capture stream; PDMUX has multiple stream groups, and TBO has separate overlap machinery (`decode_cuda_graph_runner.py:1099–1114,1199,1444`).

Allocate/zero the workspace and initialize extensions before capture. Keep it alive with the model/runner until every referencing graph is destroyed and work completes. Captures for different batch sizes may reference the same buffers only when replay is serialized through completion of finalization. Same-stream ordering naturally provides this; different replay streams require an explicit dependency or separate workspace. A Python lock does not order asynchronously executing GPUs. A key based only on current stream is also insufficient: capture and replay use different streams. Key by the runner's execution lane, model identity, device and geometry; use separate lanes for overlapping graphs/target-draft models. `get_resources().flashinfer_megamoe_workspaces` demonstrates lifecycle-owned sharing, but its geometry-only key is not automatically safe for this kernel.

Cooperative launch prevents the persistent grid's admission deadlock. It does not prevent two grids corrupting shared scratch. Leave the CUDA core unchanged, preserve source-owning tensors across asynchronous use, and do not rely on the allocator to rescue an unregistered workspace. Initial adapter should explicitly decline unsupported overlap/offload modes before weight replacement, while preserving stock behavior for them.
