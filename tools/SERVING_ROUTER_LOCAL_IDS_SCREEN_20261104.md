# Fixed V24 router component screen

This is one H200 component experiment, not a serving throughput or leaderboard claim. The source parent is SGLang `a55ab7d5ae1bba59ac351e55026fe7f7644ecc5f`. The actual original JIT wrapper/header and the author's isolated dual-ID wrapper/header are uploaded unchanged. The baseline computes packed IDs (unused by Marlin) and then `expert_map[global_ids]`; the candidate writes separate global and local IDs and requests no packed output.

The only harness adaptation removes the exact four-name JIT utility import from each private wrapper and supplies the verified real utilities plus a scoped loader adapter. That adapter accepts only the original router load signature, substitutes an absolute owned header path, and assigns a role/content-hash module name. Reverse adaptation must recover the complete original wrapper bytes. Installed files, loaded modules, custom-op registries and compiler flags are not patched. Before compilation the installed JIT Python utilities and recursively included SGLang headers must match the pinned tree. After compilation the worker retains generated source/build/shared-library/dependency-manifest hashes and verifies equal common dependency entries. This demonstrates component JIT selection, not the deployed model's backend selection; the author's independent CPU dispatcher tests cover fallback routing.

Correctness uses E256/K8 sigmoid/FP32, all eight contiguous expert maps, physical T0/1/3/8/16/31/32/128/256, and random, exact-tie, extreme-finite, forced-local, forced-remote and mixed routes:432 fixed cases. Every path, including timing, uses the pinned source configuration defaults multiplier0.17677669529663687, division epsilon1e-15 and route scale1.0; these are not claimed to be values inspected from downloaded model weights. Scores compare raw FP32 bytes; both ID outputs compare exactly. Inputs must remain unchanged and output storage must not alias inputs or other live outputs. The original packed output is checked against its own documented BF16 packing expression. The new fast path excludes valid-token mode. Eight separate low-level padding checks use initialized scores and compare active rows only: global and local padded IDs must be -1, while the old `map[-1]` behavior is explicitly not a sentinel oracle. Eight more calls omit both new optional arguments and compare the actual original mapped-ID/packed contract.

Two independent CUDA streams perform eight fresh-input calls with producer dependencies; two independent CUDA graphs replay eight times with fresh input/map copies. Distinct graphs own distinct inputs/outputs. After both streams finish, graph inputs must equal their copied fresh values and live graph outputs must equal their captured snapshots, so a later cross-stream overwrite is not hidden by an earlier clone. Concurrency is enqueued, not asserted to overlap without a timeline. Actual positive-duration CUDA profiler events at T16 and T256 must show one router on each side, exactly one indexing kernel removed, and no replacement copy/kernel.

Timing covers T8/16/32/128/256, rank0 mixed routes, identical changing inputs, warmed independent graphs and alternating AB/BA order. Each timed graph contains 64 actual complete chains; twelve paired rounds use CUDA events and report per-chain times and every pair. There is no artificial cache flush: this tiny routing stage is tested as a warmed serving component. Input copies and correctness checks occur outside timing. The fixed screen requires **geometric mean candidate/parent latency <=0.95, every timed production case <=1.02, exact outputs and the verified indexing-launch removal**. No policy sweep or retry follows a failed screen. Individual graph medians determine per-case ratios; paired ratios are also retained. This operational screen is not a significance estimate.

The sandbox hard cap is600 seconds and worker cooperative budget540 seconds; compilation is bounded by the sandbox, and the worker records a checkpoint before each JIT build. Payload and result are each bounded, the result limit is1MiB, and failures retain their stage/traceback. `screen_complete` means every fixed check and timing was collected; a separate recomputed boolean decides the performance gate. Missing or failed correctness/ownership/activation evidence is failed/incomplete, never a successful screen. No full model, weights, PDL change, shared persistent output, precision change or serving promotion is included.
