# Existing serving patch: bounded source audit

**Verdict: no source-domain blocker found in the two existing changes; serving correctness and performance remain unvalidated.** Keep this small patch as a reviewable starting point, not a proven serving entry. The SGLang checkout and patch were not modified.

Base: `a55ab7d5ae1bba59ac351e55026fe7f7644ecc5f`. The 1,549-byte `serving/patch.diff`, SHA `4a861b0a3299ee812da4ab16ead0fd841898261369bdae8f427943a795b212d2`, exactly matches the checkout diff and the patch introduced in root commit `ee009e1` on October 24. That commit's README calls it an unvalidated draft. Its intent matches contemporaneous standalone `local-routing-v1` source `835601de…`: reduce alignment overhead and tile padding while retaining stock Marlin math. Saved private check `1cc96c4a472b470a` passed five tests/six benchmarks at 1.05264×. That separate kernel also used a persistent workspace and fixed EP8 bank, so it neither isolates these two changes nor validates serving.

The patch changes only `_marlin_expert_outputs` in [muse_spark_fp4_moe.py](../serving/sglang/python/sglang/srt/layers/muse_spark_fp4_moe.py):

| Change | Source finding | Limit |
|---|---|---|
| Divide expected routes by global rather than local expert count when choosing M tile | In a replicated global batch with uniform routing, expected routes per local expert are `M*topk/global_experts`. EP8 therefore removes the old eightfold overestimate. Every actual route still receives a complete tile. | This is a performance heuristic, not a correctness repair. Concentrated local routing may favor larger tiles. EP1 is unchanged. No actual-route host synchronization is added. |
| Pass local expert count to alignment after mapping IDs | Constructor maps local contiguous expert range to `0..L-1` and all other global IDs to `-1`. The wrapper adds its own sentinel bucket: `L+1` histogram buckets and `L+2` prefix entries. Extra global buckets were empty. | Correct only for IDs already mapped to the local domain. Do not transplant the change before mapping or into an API that expects global IDs. GPU ordering/precision still need validation. |

For EP8, tiles are unchanged at M1/8/16, but M32 changes 16→8, M128 48→8, M256 64→16; by M16384 both choose 64. Smaller tiles can reduce padding but increase scheduling/reduction overhead. No speedup is inferred.

**Sentinel chain checked in actual pinned source.** The [wrapper](../serving/sglang/python/sglang/srt/layers/moe/moe_runner/triton_utils/moe_align_block_size.py) passes `num_experts+1`, default `ignore_invalid_expert=False`. The [AOT CUDA aligner](../serving/sglang/python/sglang/kernels/aot/csrc/moe/moe_align_kernel.cu) counts `id+1` and writes expert labels back as bucket minus one. Thus remote routes occupy bucket zero and retain label `-1`. The [Marlin kernel](../serving/sglang/python/sglang/kernels/jit/csrc/gemm/marlin_moe/marlin_template.h) excludes those blocks; the [finalizer](../serving/sglang/python/sglang/kernels/ops/muse_spark_v12/fused_post_expert_norm_weighted_sum_triton.py) reads contributions only for nonnegative slot IDs. This is a source-chain audit, not verification of the image's prebuilt alignment binary.

Reducing 257 buckets to 33 also changes the implementation selected: the wrapper's tiny Triton path requires more than 64 buckets; the AOT one-CTA path accepts at most 64 buckets and fewer than 1024 routes. Under EP8 this enables the latter for M<128. Therefore it is inaccurate to describe the patch as allocation-only. The new buffer bound is valid: for N routes in at most L+1 buckets, padded length is at most `N+(L+1)*(B-1)`, or `N*B` when N<L+1, rounded up for vector stores. Empty/global-only trailing buckets contribute zero.

**Supported assumptions and unchanged math.** Positive expert counts, valid global routing IDs and the constructor's local mapping are required. The existing Marlin path rejects expert tensor parallelism; this patch does not add support. Empty batches normally return earlier in the model. Default EP8, EP1 and other contiguous partitions retain the source-domain contract; arbitrary custom dispatch/maps, experimental LoRA alignment overrides and unrelated GPU backends are not newly certified. Both GEMMs, scale preparation, SwiGLU, pre/post norms, weighting and outer TP reduction are unchanged. Tile changes may alter floating-point reduction order. The comment should be understood as a uniform-routing estimate, not a guarantee for skewed routing.

**Bounded CPU evidence.** An inline run executed the exact old/new tile-loop AST for 147,456 M/partition cases, checked all 511 contiguous partitions of 256 global experts, and checked 2,520 independent padding histograms including all-remote/all-local/mixed cases, zero routes, boundary sizes and large prefill route counts. Missing-sentinel, unmapped-global-ID and missing-sentinel-capacity negative controls fail their required bounds. These checks cover domain/allocation reasoning only, not CUDA synchronization, numerical tolerance or throughput. Exact hashes and limits are in [the audit JSON](../experiments/iterations/20261104-existing-serving-patch-audit.json). Independent critic review agrees on the local-domain/padding argument. `git diff --check` passes.

**Minimal future MoE boundary, not an implementation plan.** A selected fast path would belong inside `_forward_marlin` after the existing pre-expert norm, returning the same local weighted `[M,H]` output. Keep `_reduce_and_unpool` and communication outside it. Prepare state in the quantization module's post-load hook, outside the forbidden model-loader directory, before Marlin destroys original layouts; preserve the stock path. An adapter is mandatory:

- Current `247888` preparation hardcodes local start 0/count 32 and H=I=4096; other ranks cannot call it unchanged. Serving must bind each rank's actual local range without moving or dropping routes.
- Stock accepts separate gate/up global scales, then collapses to the gate column for Marlin; its post-expert norm convention is part of that contract. Native code expects a shared global scale and raw norm parameter, forming `1+w` in FP32. Serving caches an effective norm weight and supports different norm forms/epsilon. These are distinct interfaces, not interchangeable buffers.
- Current MAIN `wgs_range` has no explicit global-zero-job guard and reads job metadata for `nj==0`. All-remote routes require a supported device path; a host input-value branch would not be a solution. Per-layer scratch, overlapping execution, capture and prefill fallback also remain unresolved.
- Current standalone preparation retains **6.75 GiB of packed weight payload per layer**:27 MiB per expert × 32 experts × four layouts × two states, excluding scratch, originals and temporary packing. The four layouts are separate natural, fat, unit and WGS tensors in each tiny/larger state. Copying this preparation across the model is infeasible. Any future selected component must retain only justified layouts and establish a whole-model memory budget.

The existing patch is small and maintainable enough for focused validation when serving checks open. A wholesale current-kernel port is not ready; the concrete boundary above explains the required work without creating a new candidate or promising a gain.
