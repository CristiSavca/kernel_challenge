# Routed expert weight traffic at low decode load

V93 already makes one logical pass through each selected expert's packed W13 and W2 matrices when a single request verifies eight nodes on the eligible Hopper path. A replacement one-row GEMV cannot remove a whole expert-weight read in this case. The argument holds for any routing distribution. Hardware latency, cache-line transactions and actual HBM reads on the serving path still require measurement. [V93 source](../candidates/v93_expert_argmax_dense_prefill/patch.diff) · [V89 kernel](../candidates/v89_paired_expert_dequant/README.md) · [Humming tile audit](../candidates/v74_humming_decode_two_ctas/README.md)

Each target row selects eight distinct experts out of 256. Eight rows can therefore visit a particular expert at most eight times. V89 W13 uses a warp MMA that handles up to eight routed rows with one load of each packed weight tile. It writes the rounded activation for W2 directly. The grouped Humming W2 consumes all of that expert's rows in a tile of at least eight rows. Empty experts contribute no weight tiles. V90's separate activated-down kernel starts above 256 global route slots. At four requests and verification width eight, V93 still uses V89 W13 and grouped Humming W2, but skewed groups can exceed eight rows. [V86 ownership and dispatch](../candidates/v86_skinny_expert_gate_up/README.md) · [V90 dispatch](../candidates/v90_activated_expert_down/README.md)

At hidden and intermediate widths 4,096, the two W13 matrices occupy 18 MiB per expert. W2 occupies another 9 MiB. Each matrix element costs half a byte of E2M1 and one sixteenth of a byte for its E4M3 group scale. The table models independent rows choosing uniformly distributed top-eight sets. For target row count `m`, an individual expert's count `X` is binomial with probability 1/32. The 32 local experts contribute `32 × P(X > 0)` distinct banks and `32 × E[ceil(X/8)]` eight-row weight passes. A larger grouped W2 tile can reduce the latter figure. Real requests can route differently.

There is one relevant cold-HBM observation from a separate H200 MoE component, with synthetic checkpoint values, one local expert partition and NCU cache flushing. At 32 target rows, its measured route counts touched 16 experts, each with at most eight rows. The kernel read 456,964,352 DRAM bytes for 452,984,832 unique expert-weight bytes, a ratio of 1.0088. At 256 rows, 26 selected experts occupied 27 work units and the ratio rose to 1.0456. Both samples used that component's own fused implementation. V93 serving hardware counters remain unavailable. ## Other ways to change the traffic

- **Losslessly compress the existing bank.** Hopper supports an opt-in CUDA allocation with transparent, data-dependent inline compression. Code nibbles account for eight ninths of the packed bank. Even removing every scale byte saves only 11.1% of the selected expert payload. The official standalone fixture generates uniformly random packed code bytes, and the model publisher restricts access to its checkpoint shards. On November 18 the anonymous official metadata endpoint identified revision `6b5fa7bb2d5bcf422a01852ae562a8f7f52b55c3` as manually gated. Official tensor-index and shard range requests returned HTTP 401. H200 counter measurements on authorized real weights are needed to justify changing SGLang's persistent weight allocator. [NVIDIA inline compression](https://docs.nvidia.com/cuda/hopper-tuning-guide/#inline-compression) · [Public weight fixture](../../muse_moe_w4a16/nvfp4.py) · [Publisher's model](https://huggingface.co/meta-models/Muse-Spark-Open-816B-A42B-NVFP4)
- **Balance the busiest rank.** Expert tensor-parallel sharding can distribute each bank over ranks while conserving aggregate bytes. In 8,192 independently drawn uniform route sets per geometry, eight verify rows touched on average 10.64 experts on the busiest rank versus 7.18 averaged across ranks. For 32 verify rows the figures were 24.20 and 20.42. The calculation uses Python’s random.Random(82313) and 8,192 trials for each of 1, 8 and 32 rows in that order. Each row samples eight IDs without replacement from range(256), and each rank owns 32 consecutive IDs. The ratios of 1.48 and 1.19 assume equal bandwidth and zero redistribution or synchronization cost. These concern only time to transfer the selected weights. The pinned Muse model accepts expert tensor parallelism for INT4 only. NVFP4 support needs checkpoint sharding and a global W2 partial reduction before post-expert normalization, plus compatibility with existing prefill. [Pinned Muse implementation](../sglang/python/sglang/srt/models/muse_spark.py) · [V74 EP8 tuning](../candidates/v74_humming_decode_two_ctas/README.md)

Each additional fourfold-score candidate should address a larger measured cost than reloading these low-load expert tiles. A standalone W2 rewrite has a testable case if serving traces show W2 kernel time substantially exceeds what its nine-MiB-per-expert volume explains.
