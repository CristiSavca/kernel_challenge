# V134 multi-turn prefix transfer review

**A native cache-policy experiment is available on the scored V64 patch.** Add only `--hicache-write-policy write_back` to V64’s four existing flags. The release’s write-through default starts a host backup on an eligible new leaf’s first insertion. Write-back delays the transfer until an eviction needs the device slots. A prefix that stays on the GPU can avoid its entire host backup in that interval. The precise tradeoff is whether background copies contend with prefill more than deferred evictions stall later turns. The public runs contain no measurement of that tradeoff. This review produced a local flag manifest and executable source checks. [V64 patch and proposed flag set](v134_hicache_control.json) · [Serving flags and constraints](../flags)

V64 attached a Rust unified radix tree with both full and SWA components. Each rank allocated 93.09 GB of full target host storage, 66.91 GB of SWA host storage and 58.18 GB for the draft. Its 3,419,325 full device slots and 854,831 SWA slots show that keeping many turns resident is possible. The published typical lengths would use 2,746,752 full slots across 32 simultaneous 13-turn conversations if they all followed those lengths. Branches, historical conversations, allocator pressure and variable requests change actual residency. All 21 archived receipts with measured rungs cut the server trace at first request and report a combined cache-hit metric. The 92% figure and TTFT percentiles cannot identify GPU-resident versus host-restored prefixes, transferred bytes, transfer duration or a per-request mean. [Official V64 result](abd217baf0ed49fd.json) · [Observed pool allocation](abd217baf0ed49fd.log) · [Archive scan](v134_hicache_control.json)

The host allocations give 4,096 bytes of full target KV, 11,776 bytes of SWA target KV and 2,560 bytes of draft KV per physical token slot per GPU. If 74,160 newly cached rows receive a full+draft backup, those two pools transfer 493,608,960 bytes per GPU. Each backed SWA row contributes another 11,776 bytes. A 2,048-row window adds 24,117,248 bytes. The native Rust cache walks unbacked *nodes* until it covers the window, so the number of backed rows depends on node boundaries. Byte counts here describe possible transfers, independent of accelerator timing. Eviction can move the same bytes later, and synchronous backup at eviction can delay admission. ## Source checks

- Device-resident prefix matches already return existing physical slots. The load-back entry point starts a transfer only on device eviction or host-only full/auxiliary hits. Eager hybrid attention constructs the SWA page table once and each ordinary layer reads it. V105 changes how attention *reads* the suffix to execute the model. Native host-tier transfer runs separately. [Resident and host-hit paths](https://github.com/sgl-project/sglang/blob/297e54fd105e974cdf401e5b4d20253a22c16f90/python/sglang/srt/mem_cache/unified_radix_cache.py#L3586-L3624) · [SWA page-table builder](https://github.com/sgl-project/sglang/blob/297e54fd105e974cdf401e5b4d20253a22c16f90/python/sglang/srt/layers/attention/flashattention_backend.py#L1279-L1301) · [V105](../candidates/v105_swa_suffix_prefill/README.md)
- The D2H engine already submits one all-layer backup call per participating pool. In the CPU fixture, restoring all three pools invoked 67 per-layer copies and 62 target readiness callbacks. This allows earlier target layers to consume restored KV while later layers transfer. An unconditional all-layer H2D barrier sacrifices that overlap. No archived receipt establishes a transfer stall to justify a replacement. [Native transfer engine](https://github.com/sgl-project/sglang/blob/297e54fd105e974cdf401e5b4d20253a22c16f90/python/sglang/srt/mem_cache/l2_transfer.py#L132-L184)
- The scheduler’s CPU all-reduce is real even when queues happen to be empty. It also checks rank agreement on write-back reclaim order. A local empty-queue fast return can leave a peer blocked when a rank’s backup allocation failed. The four-int64 reduction covers both acknowledgement queues and both signs of the digest in the ordinary no-storage case. [Acknowledgement consensus](https://github.com/sgl-project/sglang/blob/297e54fd105e974cdf401e5b4d20253a22c16f90/python/sglang/srt/mem_cache/unified_radix_cache.py#L3412-L3502)
- The scored launch uses native HiCache with 160 GB of target host capacity and persistent cache mode. The pinned public defaults are `write_through`, `page_first` and `kernel`. No declared V64 flag changes the write policy. The CPU checker exercises 96 trigger cases against the pinned Python implementation, cross-checks both Rust insert guards, runs all 16 combinations of native load-back predicates, and confirms that `write_back` survives persistent-cache validation and matches none of the 76 fixed-flag patterns. The native flag changes the backup policy of the existing KV cache. It introduces no token, response or extra request cache.
