# V106 paged SWA prefill

**Physical addresses.** The eager prefill backend translates full token slots to sliding-window cache slots, takes every P-th token and divides by P to form its physical page table. Graph replay reads the full token slots at those page starts, translates those slots and divides by P. Both therefore provide a physical page index for each logical page. For logical token t, V106 reads K or V at its own physical page stride times table[floor(t/P)], plus its token stride times t mod P. The first included token can start inside a page, and the last partial page may contain invalid or evicted neighbors. The kernel limits every source read to the selected sliding interval. Wide hybrid pools require the actual SWA metadata table. [Native backend](../../sglang/python/sglang/srt/layers/attention/flashattention_backend.py) · [Candidate delta](delta.diff)

**Independent tests.** The real eager and capture-time table builders agreed with independently generated allocations in 80 cases. The Python packer and production Triton body preserved 19,229,952 FP8 bytes and 77,312 output scalars of a local-attention reference over page sizes 1, 16, 128, 160, 256 and 320. Six batches used the submitted 160-token page geometry. The fixture exercised fragmented and repeated physical pages, 29 inside-page suffix starts, 34 partial last pages, differing page/slot strides between K and V, graph padding, and invalid prior-page references. Four incompatible head or overlapping storage strides selected fallback. All comparisons ran on CPU. [Fixture](independent_paged_oracle.py) · [Frozen results](independent_paged_oracle.json)

**What a matched check measures.** V100c and V106 use the same 160-token pages and 16,320-token prefill chunks. On Hopper, the pinned E4M3 head-dimension-64 full-attention kernel can use native paged tensor-memory loads when its 160-token key tile divides the page and there are enough queries. The 16 full target layers retain that path. Native paged FA3 excludes local attention from this load mode regardless of page size. On eligible sliding-window layers V106 gathers the visible suffix, then uses FA3's dense variable-length specialization, which supports tensor-memory loads. At TP8 each target rank has 16 query heads and two 64-wide KV heads. One complete long chunk can need the current 16,320 tokens plus 2,047 older ones, or 4.48 MiB of live FP8 K and V per sliding layer and request. At 46 sliding layers this adds about 413 MiB of source reads plus destination writes per rank and full chunk, before metadata and zero guards. Faster repeated FA3 tile loads must offset that traffic, the pack launches and workspace pressure. Measured V64 first-turn p90 TTFT was 50.06 s at 16 users and 110.00 s at 32. Those service times include queueing and all model stages. The direct V100c comparison would isolate the incremental effect of packing on 160-token pages.
