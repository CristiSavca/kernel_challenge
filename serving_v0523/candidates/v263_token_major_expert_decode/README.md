# V263 reads the original token matrix in small-batch W13

V263 eliminates the expanded BF16 input for the first routed-expert projection when all original tokens fit in an eight-row native Humming matrix tile. Each active expert projects the same contiguous token panel. At writeback its epilogue selects the source token for each routed row and applies the original expert scale, BF16 rounding, SiLU and output packing. Every routed expert, weight and original reduction dimension remains present. The native scheduler already issued one full eight-row WGMMA tile per job for these shapes. V263 changes which activations occupy those rows. [Full official patch](patch.diff) · [Changes from V261](delta.diff)

V77 and V261 both populated a separate routed-input arena. In V261, the real one-request DFlash shape uses eight tokens and 64 expert-route slots. With that shape V263 issues just the native metadata CTA. V261 also issued 64 per-route CTAs in the same launch. The H200 Marlin archive recorded ten local routes on one rank. Eliminating their BF16 input reads and writes removes 160 KiB of logical staging traffic per eligible sparse layer, or 9.69 MiB over 62 layers. W2 reuses the arena as output, so its allocation remains necessary. The 96-register direct projection additionally reads the sorted route key in its epilogue and completes all eight source rows' FP32 partials even if the expert has one route. The gain or loss depends on cache locality, block issue and phase overlap. [Shapes, archived measurements and formulas](work.json) · [V77](../v77_fused_expert_staging/README.md) · [V261](../v261_fused_decode_route_staging/README.md)

The direct descriptor covers the actual token matrix and starts each expert at token zero. Its owner writes all matching routes in their existing order, including repeated source tokens in one or more expert jobs. Larger inputs, other tile widths and non-power-of-two top-K retain their existing path. If the loaded weight binding changes or CUDA rejects the direct tensor map, the caller fills the ordinary expanded input before retrying. The dispatch depends only on tensor and kernel properties. In the inherited width-eight DFlash configuration it reaches one active request. At two or more requests the ordinary verifier exceeds the eight-token input bound. [Dispatch tests](dispatch.json)

Coverage includes duplicated and nonmonotonic source tokens, partial tiles, empty experts and multiple jobs for one expert. V263 has no physical H200 timing. V64's official four-load score remains 1.4119×. The 160 KiB saved on the recorded layout corresponds to 0.034 µs per layer at 4.8 TB/s. Using V64's 19.69 ms verification-period proxy at one user, a 5% improvement limited to these 62 layer calls would require about 15.1 µs per layer. Direct tile reuse is a low-load A/B candidate with no demonstrated end-to-end multiplier.
