# V173 stages sparse experts inside medium-density decode batches

V173 changes both expert projections during target verification. V168 uses one multirow kernel for the whole medium-density batch. V173 reads the existing device-side route count for each expert. An expert with one to eight live rows gets a Hopper producer warp that stages its packed NVFP4 weights, scales and BF16 inputs while eight consumer warps compute. An expert with more rows keeps V168’s 16-row gate/up and 32-row down-projection tiles, including its final partial tile. This preserves its reuse of each weight tile across rows. [Full submission](patch.diff) · [Three-file delta from V168](delta.diff)

The normal Humming route honors the existing preparation, device, weight-address and input-layout checks. A missing or stale tensor map takes the existing medium-density path. Both kernels consume the same ordered device-side list in each projection. The planner fills the unused positions of short lists with negative indices so a graph replay cannot read a previous batch’s slots. Each live expert runs its complete dot products, with the original BF16 scaling and activation boundaries. The route count stays on device. V173 uses exactly V168’s five flags and introduces no persistent GPU tensor. [Dispatch and flags](validation.json) · [Normal entry-point tests](dispatch.json)

## What can change on H200

For an eight-row verification of 16 requests, uniform distinct top-eight routing over 256 experts puts 95.35% of routes in experts with at most eight local rows. For 32 requests the model gives 45.52%. In a separate standalone H200 histogram with 256 input rows, only 59 of 354 local routes qualified. Those experts still accounted for 45.28% of nominal packed-weight reads. The scored serving trace omits expert histograms. V173 changes how the GPU loads and computes those rows while adding two kernel launches per eligible layer. Actual route skew, empty blocks, cache bandwidth and launch overhead determine the net effect. [Independent headroom analysis](independent_headroom.md)

NVCC 12.9 compiled the complete TVM-FFI entry points for SM90 and SM90a. The new sparse gate/up and down kernels compiled with 39 and 36 registers respectively, and the complementary multirow kernels with 121 and 118. All four compiled without register spills. The 17 pre-existing kernel bodies retained identical machine words on both targets. Numerical verification used CPU emulation. No V173 serving-throughput, TTFT, agreement or memory measurement is available. [Hopper compiler evidence](sm90.json) · [Independent numerical review](independent_review.md)
