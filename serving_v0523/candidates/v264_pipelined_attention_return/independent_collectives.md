# Native collective selection and stream ownership

The frozen V264 method probes the full contiguous partial arena and each of its two contiguous stripe views before launching a GEMM. Its startup vote checks a matching tensor-parallel rank order, a supported unquantized inference weight, and ordinary device memory. Runtime also checks that the exact enrolled quantization method is still installed and that the weight remains contiguous, frozen BF16 on the input device. [Source](delta.diff)

The CPU replay exercised the pinned SGLang group method resolver, custom all-reduce size predicate, sequence-parallel SUM selector, current-stream resolver and breakable-graph wait hook. It tested 8,192, 8,193 and 16,384 prompt rows with the native 8,192-channel output width. Across 24 accepted cases, the full and striped paths entered the same SGLang collective family. NVLS enabled selected all-reduce followed by the owner's token slice. NVLS disabled selected reduce-scatter. Size cuts between the stripe and full arena, the custom path on the full arena, and a stripe-only FlashInfer predicate caused 72 rejections before issuing any matmul or collective. The FlashInfer workspace predicate was modeled. [Executable check and conditions](independent_collectives.py) · [Results](independent_collectives.json)

The native reduce-scatter lowering on the complete 16,384-token chunk issued a count of 16,777,216 BF16 elements per receiving GPU. Each stripe issued 8,388,608. The two stripe calls resolved to the side stream and the originating compute stream respectively. The check exercised both enabled PyNCCL and the native process-group fallback with an ABI sink. Six failures injected during the first reduction or second projection joined the side stream before unwinding. Disjoint offsets in the 256 MiB partial arena were verified on PyTorch meta storage. CUDA graph memory residency and allocator high-water marks remain unmeasured. [Backend and lifetime receipt](independent_collectives.json)

Two different NCCL message sizes may choose different channel counts, trees and rank accumulation orders within the same SGLang family. An executable eight-rank operand example uses only BF16-exact values and ordinary FP32 accumulation to produce BF16 zero in one order and one in another. This is a sensitivity example. It identifies no actual disagreement in V264. Physical generated-token, memory and latency checks remain necessary. [Reproduction](independent_collectives.py)
