# V217 independent target-graph review

The shaped CPU fixture called the candidate and V215 through the existing MuseSparkTextForCausalLM, MuseSparkModel, MuseSpark1xModel and LogitsProcessor forward methods. It used the released five-tap structure, synthetic decoder layers, eight features per tap and a scalar replacement for the vocabulary head. At successive 16-, 8-, 16-, 1- and 3-row invocations, all 1,760 raw BF16 components and all output logits matched. Packed features retained the exact workspace object through the full logits processor. Each smaller invocation left its padded suffix intact. A quarter-output projection on that workspace matched the same channels of the native full FC. The logits processor also exercised its own pre-norm-output preference, which produced a different buffer and suppressed projection. [Fixture](independent_model_entry.py) · [Source digests and result](independent_model_entry.json)

The target and draft workers initialize before graph capture. The pinned scheduler captures target graphs first, after both workers have initialized. The DFLASH TP8 layout shares the target group, and sequence-parallel LayerNorm applies only to EXTEND. The actual Muse target builds its original five taps in a list and joins them through the logits processor. V217 writes these taps into the dedicated row-strided views in the target graph. The ordinary overlap scheduler executes the target forward, settlement and consumption of the draft features on its forward stream before issuing the next target forward. The early publication reports sequence lengths for scheduling. PDMux and two-batch overlap decline the shared workspace. [Candidate source delta](delta.diff)

The early prototype voted solely on module hooks and cached weight pointers. A reduced four-shard counterexample made rank one negate its raw features at the graph tail. The assembled first row became `[36, -100, 164, 228]`. The ordinary FC on rank one gave `[-36, -100, -164, -228]`. A rank-local capture shape change also produced three projected markers versus one raw marker. The revised candidate gates the epoch before capture and votes again on the exact output after each graph key has finished capture. The pinned FullCudaGraphBackend retains that object for replay. Participating ranks issue the same channel gather before any rank-local hook or changed-weight fallback. The separate 4/8-rank Gloo test covers asymmetric graph hooks, capture alias rejection, FC mutation/replacement, loader invalidation and native recovery. [Distributed replay](replay.py) · [Gloo result](replay.json)

The physical estimate at maximum batch is one 20 MiB raw workspace and an 80 MiB immutable local BF16 FC shard per rank. Official disk, tensor, distributed and IPC loaders invalidate the draft projection before modifying parameters, including failed updates. Direct writes through `.data` outside those loaders can evade PyTorch version counters. The tests used CPU tensors and Gloo.
