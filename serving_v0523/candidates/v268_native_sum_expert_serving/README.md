# V268 keeps the native attention-output reduction

V268 combines V248’s mixed scheduler and verification attention with half-prompt QKV projection, compact prompt expert routing, fused decode staging, token-major W13 for suitable small batches, and the fused terminal residual gate. Every rank executes the original full-width attention-output SUM. In the controlled Gloo test, the earlier split SUM reproduced 1,556 BF16 discrepancies. V268 matched the native result on all 6,291,456 owner values and all 5,234,176 QKV values across the same 48 calls. Forty midpoint tests found no argmax changes. These are CPU results. CUDA reduction and GEMM selection, generated-token agreement, latency, memory and throughput still need a judge run. ## What the candidate changes

- **Cold attention.** Each GPU receives its own half of a tensor-parallel prompt first. It projects that half while receiving the second half. Both GEMMs retain the full hidden dimension. Startup records the eligible quantization-method object. Each forward checks the method and its weight again. A separate full-width PyTorch comparison, including 16,384 rows by 8,192 hidden channels, matched all 41,319,936 BF16 values. The V260 traffic model puts ideal overlap at 2.78 seconds on a 304.43-second V41 run at 32 users, assuming 450 GB/s per direction and 989 dense BF16 TFLOP/s. Additional GEMM or communication overhead could erase the gain. [Full-width arithmetic](qkv_full_width.json) · [Communication model](../v260_pipelined_prompt_qkv/work.json)
- **Prompt experts.** At 16,384 tokens, 131,072 route slots span the eight expert-parallel ranks. V258 builds a stable compact plan for each owning rank. On average 16,384 slots are live per rank, reducing the explicit planning arrays by 1,439,612 bytes. V268 preserves expert IDs, stable ordering, weights and all routed matrix products. [Geometry and native dispatch](../v258_compact_prompt_route_plan/work.json)
- **Decode experts.** Eligible target verification at up to four concurrent requests uses one staging launch per MoE layer. If all original tokens fit the eight-row W13 matrix tile, the active experts project the original input and select the token row during writeback. In a one-request archive with ten local routes, this removes 160 KiB of logical input staging per rank per layer. The matched control used an older Marlin implementation. [Small-batch kernel design and cost](../v263_token_major_expert_decode/README.md) · [Staging geometry](../v261_fused_decode_route_staging/work.json)
- **Final residual.** The terminal decoder layer evaluates both FP32 products and their sum in one kernel. It preserves the stock FP32 rounding steps, BF16 subnormals and every attention and expert operation. At 2,048 owner rows and width 8,192 it removes 384 MiB of logical temporary traffic on that layer. [Gate and rounding validation](../v257_final_residual_gate/README.md)

## Validation and qualification

The integrated source matched V248 through 126 paired prompt rank cases on real TP2/4/8 CPU Gloo groups, totaling 4,747,168 BF16 values. The same expert objects then served 56 verification calls, including 14 failed direct projection launches followed by successful repacking. Changing the inputs and returning to prompt execution matched another 798,720 values. The fixture uses synthetic expert arithmetic and models CUDA peer memory. The independent grouped-decode fixture checked 320 rank-forwards and 20,234,240 staged or output words. The host-compiled CUDA writer and loader checked 27,694,080 output words and 16,380 tensor-copy coordinates.
