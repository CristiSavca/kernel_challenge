# V128 native draft embedding and replay feasibility

Keep the current V64 embedding for the private queue. At one user, packing the anchor and one copy of the mask reduces the embedding all-reduce tensor from 128 KiB to 32 KiB. Both paths still issue one collective and feed the full eight-row draft block to the five-layer backbone. Preserving arbitrary input-mutating hooks on individual ranks requires agreement before changing the collective shape. A TP8 scalar Gloo vote took a 349 µs median on the available local host. Against that observed cost, the single-user design breaks even on communication bytes only below 0.49 GB/s of effective logical ring throughput. H200 timing remains unmeasured. The native DFLASH worker resolves the target embedding, fills each block with the live mask token and overwrites the first position with that request's anchor. Its dense lookup executes **before** the draft model's captured forward. The worker reconstructs a replicated full embedding table only under attention data parallelism. The measured TP8 launch uses the ordinary vocabulary-sharded embedding path. Each packed lookup can use the current table and mask; no missing token or cross-request reuse is needed. The calculation uses eight BF16 features blocks of width 8,192 per request and two logical ring phases, each sending 7/8 of the tensor. Actual custom all-reduce algorithms can select multicast, and launch latency and HBM behavior enter the real break-even. [Pinned worker](../../sglang/python/sglang/srt/speculative/dflash_worker_v2.py) · [Vocabulary-sharded embedding](../../sglang/python/sglang/srt/layers/vocab_parallel_embedding.py)

Both feasibility paths passed 480 rank-scenarios over widths 4, 8 and 12, all four load points, rank-local input and output hooks, global hooks and changed mask-embedding weights. Each path compared 13,025,280 BF16 values by raw bits. The voted implementation packs the transport only if all ranks can do so. A second implementation lets clean ranks look up the compact IDs and expand their local contributions, while instrumented ranks execute the original lookup. All ranks then reduce the original dense shape. This preserves asymmetric hooks with zero extra votes, but saves no communication and adds local materialization on clean ranks. Each implementation uses a synthetic vocabulary and 256 hidden channels for correctness. The traffic table uses the real model width. The scored log also says the draft metadata glue graph was disabled for FA3. In the normal fixed-width, single-top-k verification path, FA3 already calls the fused page-table and prefix-metadata kernel once per forward. The five draft layers read its result. Enabling another CUDA graph around that operation would leave the five attention and dense MLP calls intact. A one-time capability vote at draft-graph capture also cannot seal hooks for the separate eager embedding call. V64 recorded 4.0 accepted tokens per pass and 203.2 median decode tokens per second for one user. Combining those aggregates gives an illustrative 19.69 ms verification period. Doubling current decode at that load requires saving roughly 9.84 ms per pass, and tripling it requires roughly 13.12 ms. These measurements contain no component-level timing that would support allocating a private check to one embedding lookup. The decision would change with an H200 trace showing a materially expensive embedding or with a future graph boundary that genuinely owns both the compact lookup and its instrumentation lifetime.
