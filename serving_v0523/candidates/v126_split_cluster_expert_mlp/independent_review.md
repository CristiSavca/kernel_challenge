# Independent V126 review

The frozen split CUDA header has SHA-256 `1eb83e89a851f2f09adb9e24612afe5fc255f6fddb0c224fa0fa1778697e32aa`. Every supported split covers all K contributions. The new reduction order **can change a BF16 projection result**, including with finite, exactly representable inputs. Physical H200 agreement and throughput remain unmeasured. **Routing and ownership.** Each eight-CTA cluster handles the same expert tile in all its CTAs. The Y work queue advances by the Y grid size and covers every tile even if the estimated number of live experts is too small. Every rank and split owns a disjoint set of gate/up output channels. Its warps handle interleaved K16 stripes, and the four output fragments are redistributed to one writer each after their FP32 sums. The down pass reads all eight ranks' activation bands and writes disjoint output channels in the current split plane. Every CTA sees the same row count, so the two cluster barriers uniformly order the activation writes, remote reads and scratch reuse. The finalizer reads those planes only through the staged live row map. An independent enumerator counted **1,916,928** activation or partial-output cells across 24 aligned geometries, with exactly one owner per cell and no missing down-projection K coordinate. [Ownership test](independent_order.py) · [Production route/consumer test](integrated.json)

**Dispatch and resources.** The 8-CTA, 256-thread geometry requires hidden width divisible by 512 and intermediate width divisible by `512 × splits`. The cluster capability and occupancy query run with the actual specialization and shared-memory requirement. The host filters full deterministic mode, nonmatching packed banks and unsupported device preparation. A failed optional module build leaves the existing expert path available. The Y-grid estimate affects wave count and utilization, with correctness maintained by the grid-stride loop. At width 4,096, P2 uses 32,768 static plus 4,224 dynamic shared bytes per CTA, P4 uses 32,768 plus 2,176. Both compile for SM90 and SM90a. P4 has 8 bytes each of reported spill stores and loads outside the two projection loops. The actual resident clusters and the effect of this scheduling on H200 still require measurement. [Compiler receipt](sm90.json) · [Dispatch tests](adapter.json)

**Accumulation order.** For a single output channel, set the contributions from K16 tiles at original K offsets 0, 16 and 64 to `+1, 2⁻²⁷, −1`. A serial FP32 round-to-nearest sum gives zero. Both P2 and P4 place the positive and negative unit terms in stripe zero and the small term in stripe one, giving `2⁻²⁷`. Both results are BF16-representable. A contiguous down split also has a converse example. Start the first split with `+1`, then start the second split with `−1, 2⁻²⁷`. The serial sum preserves the small value and the split sum gives zero. Each individual term needs one nonzero BF16 activation and an E2M1 coefficient of ±1 with unit scale. The example compares summation schedules in the stated FP32 model. The sparse parent dispatches Humming and its device instruction order has not been measured. [Executable examples](independent_order.py)

In 16,384 synthetic 4,096-element dot products using BF16 activations and exactly representable scaled E2M1 coefficients, one or two BF16 results per comparison changed with each split schedule. The worst observed absolute change was 0.00048828125. The fixture uses a common NumPy FP32 reduction within each 16-element tile and varies only the intertile order. These frequencies do not estimate target model agreement or emulate Hopper tensor-core accumulation. The finalizer's agreement test separately establishes the intended BF16 boundaries once its FP32 partials are given.
