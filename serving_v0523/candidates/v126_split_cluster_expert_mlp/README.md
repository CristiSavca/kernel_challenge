# V126 sparse split expert MLP

V126 gives several Hopper clusters independent work from the same routed expert. On the model's one-user verify shape it divides the intermediate channels into four disjoint groups. At four users it uses two. Each group reads its own gate, up and down weights once per eight-row tile. Under independent uniform top-eight routing this exposes roughly 230 live thread blocks at one user, up from 57 in a single-cluster-per-expert design. The eight-GPU serving reference is V68. H200 timing and end-to-end scores for V126 remain unmeasured. [Official patch](patch.diff) · [Launch flags and export](validation.json) · [Work model](work_model.json)

Each cluster has eight thread blocks. Within each block, two or four warps divide the W13 input reduction into FP32 stripes, then combine their results in shared memory before the original BF16 projection round, global scale, second BF16 round and SiLU. A cluster barrier makes its activation stripe available to the eight W2 output blocks. Each output block computes its share of the W2 intermediate channels and writes **FP32** partial outputs. A second cluster barrier protects peer reads at the tile boundary. The existing per-token finalizer adds all pieces in increasing channel-group order, rounds to BF16, applies the W2 global scale and rounds again before the original expert normalization and slot-weighted sum. Regrouping the FP32 additions changes some BF16 results. With legal BF16 inputs and packed ±1 weights, both split counts yield 2⁻²⁷ where a single ascending gate reduction yields zero. The independent audit also found one or two BF16 changes per projection and split count across 16,384 synthetic 4,096-channel dot products. Model-level agreement on H200 remains unmeasured. [Three-file delta](delta.diff) · [Integrated reference](integrated_routes.py) · [Reduction-order examples](independent_order.json)

The load-time check requires the original paired WGMMA bank layouts, group-of-16 scaling, compatible channel widths and positive device occupancy for each specialization. The low-load dispatch uses the token and top-k tensor shapes, model expert counts and SM count. When the expected work supplies two thread blocks per SM or mean routing density exceeds one slot per expert, it retains the inherited path. Otherwise it chooses among the device-supported split counts. The Y-grid reserves the expected number of live experts plus one standard deviation. A device-side grid-stride loop handles every additional or highly concentrated tile. V125's high-load path and V68's grouped fallback remain available under the four parent flags.
