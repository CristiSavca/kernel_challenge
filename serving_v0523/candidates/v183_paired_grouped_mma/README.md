# V183 pairs consecutive WGMMA slices in the prompt down projection

The frozen V181 parent sorts the local prompt routes into contiguous per-expert intervals. On Hopper, V183 gives the Humming down projection a second K16 slice to execute before its warpgroup waits. A 4,096-wide contraction has 64 K64 stages. Each warpgroup now executes **192 waits instead of 256** across the contraction. The expert weight bank, BF16 projection boundaries, FP32 dot-product order, per-expert RMS and top-eight return all follow the existing serving path. The adapter uses the published Humming native launch operator and falls back per tile configuration during preparation. [Production delta](delta.diff) · [Official export and flags](validation.json)

These are machine-instruction counts under NVCC 12.9.86 on SM90a. All three widths retained 32 HGMMA instructions, 168 registers per thread and zero hot-loop local-memory instructions. Each merged group leaves the first eight source registers and both FP32 accumulator bands untouched while decoding the second operand. Both matrices use the original shared stage. The group drains before the vendor's shared-stage release and at stage exit. Hopper specifies ordering across same-shape asynchronous instructions that share accumulators. The same experiment on the preceding fused gate/up projection counted 778–782 arithmetic instructions already scheduled while at least one matrix operation remained outstanding. Pairing raised this to 844–848, an increase of 66 sites per width. W2 exposed 228 additional sites in the same loop geometry. The frozen V183 source carries the V181 gate/up projection byte-for-byte. [Six matched kernel comparisons](sm90a.json)

**Performance remains unmeasured.** The closest archived physical H200 run used 16,384 tokens, 16,224 local routes and the same 4,096-by-4,096 experts. The complete stock Marlin call took 7.188 ms, while the dense BF16 reference covering both projections and their activation took 2.698 ms. There is no isolated Humming W2 timing. In a simple model with four equal K slices, operand preparation cost D and tensor execution cost M, one overlapping pair saves at most min(D,M) of 4(D+M). At D=M that would be 12.5% of the W2 stage, or about 4.2% of a prompt expert layer whose W2 costs one third. Both figures assume the other warpgroup does no comparable latency hiding. ## Correctness and reproduction

The production C++ method was run with a delayed-completion CPU model that retained source pointers until retirement. Across 297 cases, 45,936 FP32 outputs matched bitwise, with 365,376 source-register lifetime checks. The actual grouped host adapter passed 200 paired/ordinary/partial-eligibility prompts with 6,931,520 in-place BF16 output values. Its new W2 route dispatched 278 times and covered 2,453,898 local routes. Hardware tensor arithmetic and serving wall time remain unverified.
