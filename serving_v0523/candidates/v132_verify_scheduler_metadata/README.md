# V132 FA3 scheduler reuse across target verification layers

V132 shares the native FlashAttention 3 schedules for full and sliding-window layers within a single DFLASH verification on V120b. For a long fixed-width call on the registered model, the pinned FA3 implementation reduces 62 scheduler prepares to two and adds zero standalone semaphore resets. This predicts **60 fewer GPU kernel launches per target verification** at each of the four scored loads. Elapsed time, output agreement on H200, peak memory and challenge throughput still require physical measurement. [Full patch](patch.diff) · [Frozen export and flags](validation.json)

The official export SHA-256 is `45c62ddfc33bb0060b836a235367f6bbb6dba08fd4c98eddcaa6c880fcbbc4d0`. It adds the default-off switch `--speculative-dflash-share-verify-schedule` to V120b’s eleven launch flags. Its four-file delta scopes a fresh metadata dictionary around the registered Muse target model call, feeds FlashAttention the actual live KV lengths, cumulative query offsets, physical page-table capacity and attention window, and keys the mutable semaphore by backend, device and stream. The model restores its surrounding state on return or exception. Graph capture records the native prepare before its first consumer so the prepare executes again on replay. The optimization performs no input or output lookup. [Delta](delta.diff) · [Challenge rules](../../RULES.md)

V120b’s page size is 160. A 131,072-token configured upper bound occupies 820 table columns and yields a **131,200-token physical K capacity** in FA3. Full/SWA static split counts at batches 1, 4, 16 and 32 are 57/15, 15/14, 4/4 and 2/2. The gate uses hardware occupancy, actual page geometry and the native tile size. Short or saturated geometries retain the parent’s internal scheduler. The pinned C++ checker tested 211,680 geometries across four page sizes. Every one of the 56,238 qualified examples selected multiple splits and matched the native forward. [Executable pinned-source check](splits.py) · [Results and source hashes](splits.json)

Forty-eight paired executions of the production model and attention methods on CPU-backed tensors preserved the parent’s attention arguments. These include ordinary and separate SWA metadata, streaming contexts, changes to lengths, guard fallbacks and eight full 62-layer calls across pages one and 160. A recorded instruction sequence exercised length refresh across 56 modeled replays. The official patch applies and reverses on the pinned SGLang release, and the parent plus delta reconstructs it. ## Launch accounting

The SGLang pin is `297e54fd105e974cdf401e5b4d20253a22c16f90`. Its AOT CMake file pins sgl-attn at `f89bc2306632d1ec5f97b014dded4254f5b4a907`. Scored V64 uses native target FA3. Its normal non-SWA decode already precomputes a schedule at query width one. Its DFLASH target verification calls the paged FA3 wrapper through `forward_extend` at width eight, and supplies no shared scheduler metadata. In the varlen launch wrapper, each internal prepare both fills the per-request scheduling vectors and initializes the semaphore. ## Matching the live forward

- Supply the padded batch size, real query-stride geometry, layer-local query/KV head counts and head dimensions, QKV dtype, causal mode, exact full or sliding window, page size, split policy, softcap presence and SM margin. Use the actual per-geometry INT32 cache lengths and cumulative query offsets. On the paged path the native forward derives its K capacity from `page_table.shape[1] × page_size`. An eager host bound may differ from the captured table capacity. [Builder inputs](https://github.com/sgl-project/sgl-attn/blob/f89bc2306632d1ec5f97b014dded4254f5b4a907/hopper/flash_api.cpp#L513-L537) · [Forward's physical K capacity](https://github.com/sgl-project/sgl-attn/blob/f89bc2306632d1ec5f97b014dded4254f5b4a907/hopper/flash_api.cpp#L740-L770)
- Target verify has already written its new K/V rows. The Python wrapper may supply `cu_seqlens_k_new` despite an absent new K tensor. The native forward assigns that pointer only inside the K-append block. The standalone metadata builder takes the optional pointer literally. Give it `cu_seqlens_k_new=None` and `max_seqlen_k_new=0` here. Passing the populated cumulative lengths to the builder would count them again. [Standalone builder](https://github.com/sgl-project/sgl-attn/blob/f89bc2306632d1ec5f97b014dded4254f5b4a907/hopper/flash_api.cpp#L556-L567) · [Effective forward pointer](https://github.com/sgl-project/sgl-attn/blob/f89bc2306632d1ec5f97b014dded4254f5b4a907/hopper/flash_api.cpp#L928-L969) · [Length addition](https://github.com/sgl-project/sgl-attn/blob/f89bc2306632d1ec5f97b014dded4254f5b4a907/hopper/flash_prepare_scheduler.cu#L90-L113)
- Keep separate INT32 tensors per geometry. For ordinary long full and local attention, native metadata has respectively `4 × round_up(B,4) + 1` and `3 × round_up(B,4) + 1` elements. Full causal scheduling sorts batches, and local scheduling omits that vector. Equal static split counts at 16 and 32 users do not make these tensors interchangeable. At 32 requests the two allocations together are only 904 bytes per device. [Native metadata layout](https://github.com/sgl-project/sgl-attn/blob/f89bc2306632d1ec5f97b014dded4254f5b4a907/hopper/flash_api.cpp#L613-L650)
- Fresh device lengths and query offsets must reach the builder **every iteration**, including every CUDA graph replay. A captured prepare kernel before the first layer of each geometry can read the live buffers and write graph-stable outputs in stream order. A second viable construction stages each newly computed tensor into its own captured address and orders the copy before its first consumer. Two additional device copies reduce the nominal saving to 58 launches. Private metadata/semaphore storage is required for overlapping streams or graphs that can execute simultaneously. Preserve the ordinary paths for unsupported sharding, ragged or cascade attention, fused KV append and nonmatching geometry. [Pinned replay metadata setup](https://github.com/sgl-project/sglang/blob/297e54fd105e974cdf401e5b4d20253a22c16f90/python/sglang/srt/layers/attention/flashattention_backend.py#L3168-L3199) · [Live scheduler inputs](https://github.com/sgl-project/sgl-attn/blob/f89bc2306632d1ec5f97b014dded4254f5b4a907/hopper/flash_prepare_scheduler.cu#L73-L119)
