# The four K slices update each output in the original order

The selected M8 W13 and W2 images use the same native Humming launch symbols and BF16-input, FP32-accumulator PTX instruction as their V297 controls. Each stage issues eight matrix operations. Four K16 slices update each of two distinct four-register output fragments. All 32 static updates per image retain V297’s accumulator and slice order. The encoded input scales remain +1, each instruction consumes its previous destination, and block scales still pass through Humming’s original BF16 dequantization and scaling method. A full stage now uses one drain after eight issues, compared with two drains after four issues each. The PTX ISA specifies ordering for successive same-shape WGMMA accesses to the same accumulator. The wait establishes completion before the surrounding code reuses the inputs. [Bound public code and machine replay](independent_chain.py) · [Digests and per-stage register bases](independent_chain.json) · [NVIDIA warpgroup instruction ordering](https://docs.nvidia.com/cuda/parallel-thread-execution/#asynchronous-warpgroup-level-matrix-instructions-wgmma-fence)

W13 moves the next shared-to-register prefetch after the current stage release. At the last iteration its address is in the next stage modulo the stage count. The kernel has already waited on that stage at the penultimate iteration, whenever more work remains. W2 retains its previous prefetch placement. Both paths keep copied BF16 source words live through the full drain. Redirecting a same-shape instruction into the other accumulator, reversing one encoded multiplicand scale, or copying the wrong dequantized ping-pong buffer failed the independent checks. The scalar cancellation control also detects a reordering of the two middle updates. Hardware elapsed time and direct on-device numerical comparison remain unmeasured.
