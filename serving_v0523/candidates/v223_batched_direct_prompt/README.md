# V223 batched FP8 prompt attention

V223 extends V219’s single-request prompt optimization to long batches with multiple requests on Hopper. On each eligible full or sliding layer it builds one packed pair of FP8 tensors and calls native FA3 varlen on all requests. The physical cache writer consumes the same contiguous new K/V bytes as the packer. The packer reads old keys and values from the layer’s authoritative page table. It preserves fragmentation, shared prefixes, scales, query ordering, softcap, output placement and each request’s bottom-right causal window. [Delta from V219](delta.diff) · [Official export](patch.diff)

A full layer keeps all previous keys. A sliding layer keeps the smaller of each prior prefix and its left-window length. The 256 zero rows after every packed sequence isolate partially loaded tail tiles. Each live forward owns its lengths and offsets. Input data expires after the call. The sum of the guarded packed allocation and both contiguous FP8 input arrays must fit within 32 MiB. The normal source handles graph warmup, full capture, speculative mixed verification, unsupported pools and batches outside that bound. [Dispatch and FA3 review](independent_replay.md)

The archived V41 scheduler logged 55 long multi-request prefill calls across the four loads. All 55 fit the scratch bound for the sliding layers, including 15 at 16 users and 34 at 32 users. They account for 245,760 and 523,356 new rows at those two loads. Three of the 32-user calls exceed the full-layer limit from their recorded cache hits alone. These counts describe eligibility by batch shape and memory. [Archive replay](trace.json)

All 14 Hopper variants compiled with zero spills. The Triton interpreter matched 63,102,016 output bytes in 58 cases, including hostile indices outside the usable prefix, arbitrary FP8 bit patterns and unequal per-request windows. A separate CPU replay exercised 38 production forwards with the real Muse, Breakable attention callback, FA3 metadata builder and cache writers. It matched 81,512,960 physical cache bytes and 6,912 sampled float64 attention outputs against V219. Native GPU reduction order, generated tokens, peak memory, TTFT and serving speed still need H200 measurement.
