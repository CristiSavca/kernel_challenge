# V223 prompt attention replay

V223 selected the packed FA3 call in seven of 19 paired CPU cases. V219 used paged FA3 in all 19. All 38 forwards matched on 81,512,960 physical KV-cache bytes across both pools, including untouched slots. The independent float64 reference matched 6,912 sampled output scalars across first, middle and last queries in each participating request. The official full patch SHA-256 is `063fdbe4884732d44b6c92412334b15e53e00aaef8654f73faa901a3f40bdcca`. [Machine receipt](independent_replay.json) · [Frozen export](validation.json)

The harness reconstructs both versions from the published base and their full patches. It runs MuseSpark1xAttention’s ordinary forward, native reference Q/K normalization and sliding-layer RoPE, RadixAttention, the Breakable eager callback, AttentionBackend dispatch and FlashAttentionBackend.forward_extend. It executes the actual per-forward metadata builder on the live request table. KVLocPlan binds live and padded replay batches, and SWAKVPool translates independently shuffled full slots into sliding slots. The same production writers receive one write per layer in each version. The fixture marks CPU tensors as CUDA for dispatch, uses synthetic projections and models the native physical storage write. [Reproducer](independent_replay.py)

On ordinary EXTEND the target skips both fused cache-write paths. The normalized queries and keys and the projected values are BF16 at the eligibility test. The backend then converts queries to E4M3. The fixture compares both unit and distinct K/V descales, including the expanded batch-by-head views, canonical causal bounds, softmax scale, softcap, left window, num_splits and the graph-owned BF16 output. The translated SWA route crops a different halo per request. Poison values in reserved slot zero and padded model inputs never enter an accepted sequence. The CUDA graph runner supplies fresh plain FA3 metadata for its eager Breakable attention region. FULL and warming graph contexts take the original attention path. [Published head geometry](../../../muse_attention_decode/TASK.md) · [Production delta](delta.diff)

At the published per-rank shape of 16 query heads, two KV heads and 64 dimensions, a two-request example with 4,096 new rows and 122,368 retained prefix rows uses exactly 32 MiB for packed K/V, per-request guard rows and contiguous FP8 writer inputs. It selects dense full attention. One additional prefix row raises the charge by 256 bytes and selects the parent paged route on that layer. The corresponding sliding layer remains eligible under the 2,047-row halo. Additional declines cover 4,095 live tokens, full-graph metadata, active capture, warmup, mismatched live row count, mixed verify, inconsistent host lengths, absent eager request mirror, deterministic execution and a custom cache writer. [Per-case results](independent_replay.json)

The native FA3 interface reads a physical start offset from `cu_seqlens_k` and a separate live count from `seqused_k`. V223 allocates and zeroes 256 additional physical rows after every sequence. That exceeds the published Hopper FP8 head-dimension-64 K tile widths of 128 and 160. This protects masked tile tails when a neighboring sequence contains invalid values. Packing can shift the native tile boundaries and split selection. The numerical replay compares matching logical attention in float64. CUDA FA3 arithmetic, bitwise GPU output equality, latency, allocator behavior and score still require hardware measurement.
