# Native pre-expert RMSNorm on Hopper

The checked SGLang model constructs its pre-expert norm as `MuseSpark1xRMSNorm` with a weight and zero-centered gamma. After loading, the norm caches the effective gain in the model's parameter dtype. Its CUDA forward calls `F.rms_norm(x, (hidden_size,), effective_gain, eps).to(x.dtype)`. The Humming W4A16 expert path performs this call before expert staging. The routed replacement accepts aligned BF16 input and effective gain and checks the PyTorch revision during capture. The ordinary path stays available for other dtypes, revisions and shapes.

The pinned SGLang pyproject requires PyTorch 2.14.1. An archived diagnostic records 2.14.1+cu130. That diagnostic did not execute a GPU kernel and does not establish the judge's git SHA. The audited upstream release revision is 5c4886908584029761b579af026dcfb627c84070. Its matching-dtype CUDA path calls the fused operator. It makes the inputs contiguous, allocates BF16 output and FP32 row statistics and selects a four-wide kernel when input, gain and output are aligned to eight bytes, the width is divisible by four and no greater than 2^24. [Functional RMSNorm](https://github.com/pytorch/pytorch/blob/5c4886908584029761b579af026dcfb627c84070/torch/nn/functional.py#L2998-L3012) · [Operator selection](https://github.com/pytorch/pytorch/blob/5c4886908584029761b579af026dcfb627c84070/aten/src/ATen/native/layer_norm.cpp#L326-L368) · [CUDA dispatch](https://github.com/pytorch/pytorch/blob/5c4886908584029761b579af026dcfb627c84070/aten/src/ATen/native/cuda/layer_norm_kernel.cu#L1140-L1176)

For each row the native CTA has four warps. Each lane reads four consecutive BF16 values and advances by 512 channels. Its FP32 square accumulation contracts to one fused multiply-add per value. Warp reduction uses descending offsets 16, 8, 4, 2 and 1. The four warp sums combine as `(w0+w2)+(w1+w3)`. The kernel divides by width in FP32, adds epsilon and takes CUDA's reciprocal square root. The output first multiplies the input by the inverse RMS, then multiplies by gain in FP32 and rounds once to BF16. [Thread count](https://github.com/pytorch/pytorch/blob/5c4886908584029761b579af026dcfb627c84070/aten/src/ATen/native/cuda/thread_constants.h#L16-L26) · [Arithmetic and addressing](https://github.com/pytorch/pytorch/blob/5c4886908584029761b579af026dcfb627c84070/aten/src/ATen/native/cuda/layer_norm_kernel.cu#L140-L345) · [BF16 conversion](https://github.com/pytorch/pytorch/blob/5c4886908584029761b579af026dcfb627c84070/torch/headeronly/util/BFloat16.h#L123-L150)

The offline comparison compiled the candidate's registered TVM wrapper and the release's real vectorized kernel body, shuffle functions and BF16 class using NVCC 12.9.86 for sm_90a. The reference translation unit supplies the CUDA FP32 accumulator and warp width. Both images contain the dependent square FFMAs, all five shuffle/add stages, a refined FP32 division with corner-case handling, the subnormal scaling path around MUFU.RSQ and two independent FMUL instructions in the dependency chain of each of the four weighted BF16 outputs. The candidate uses 32 registers, 16 bytes of static shared memory and zero spill bytes. Changing dynamic rank division to a shift and a mask removes four reciprocal instructions from the image and reduces the static count of instructions with operands from 798 to 688. Both counts include untaken branches. These checks cover the source and local machine code. Exact device outputs, the installed judge binary, runtime speed, and peak GPU memory require GPU evidence.
