# V284 normalizes rank-major pooler output into expert staging

V284 builds on V283's sharded projections. Each rank computes its pooler output columns with the full 8,192-element BF16 input and participates in the original all-gather. The router selects the usual top eight experts, and Humming’s existing planner assigns each local route a destination. One CUDA block per token reads all 4,096 projected features from the gathered shards, applies the full pre-expert RMSNorm and writes the BF16 result to each live destination. The original W13 and W2 kernels consume that staging buffer. [Full patch](patch.diff) · [V283 delta](delta.diff)

On the two archived rank-local routing histograms, 39 local routes at 32 rows give 65.39 MiB and 354 at 256 rows give 543.47 MiB when extrapolated across 62 layers. The donor still performs two full input reads per token and adds route-map reads. Whether those accesses reach HBM, and whether eight token blocks provide enough parallelism at low concurrency, require hardware timing. V283 joins the pooler and router before its native RMSNorm, route plan and staging execute in sequence. V284 puts the existing route plan before the combined kernel. That ordering would sacrifice some normalization/planner overlap if combined with V272's separate stream schedule. The current export uses V283's ordering. ## Numerical and execution checks

- The selected CUDA path matches PyTorch's 2.14.1 CUDA BF16 vectorized RMSNorm for aligned, same-dtype effective gain. It preserves the four-value accumulation per lane, 128-thread reduction tree, FP32 reciprocal square root, gain multiplication order and single BF16 conversion. Both the pinned ATen source and the new registered TVM wrapper assembled for SM90a. The final donor uses 32 registers, a single barrier resource, 16 bytes of static shared memory and zero spills. Constant-time shard indexing removes four reciprocal instruction sites from the first donor. [Assembly and compiler provenance](independent_native.md) · [Upstream ATen source](https://github.com/pytorch/pytorch/blob/5c4886908584029761b579af026dcfb627c84070/aten/src/ATen/native/cuda/layer_norm_kernel.cu)
- A host coroutine executed the submitted CUDA body one thread at a time with synchronized shuffles and barriers. Across TP4/8, the 5,920,768 live BF16 output words and 24,160,256 untouched padding words matched the independent row-major reference. A second numerical implementation matched 884 reciprocal roots and 3,620,864 normalized BF16 words. Changing the inter-warp reduction tree changed two BF16 results. Introducing an earlier BF16 rounding changed 934,527. The two host comparisons use a common CPU reciprocal-square-root implementation. [CUDA-body replay](host.json) · [Reduction-order controls](independent_norm.json)
- The actual model pooler, public expert entry, grouped Humming dispatch and planner/gather call sites ran with emulated CPU math and routing kernels. Old and new paths matched 5,087,232 live staging words, 4,005,888 result words and 7,824 map words. Mixed, concentrated, repeated, all-local and all-remote routes were covered. Uncached, FP32 or unaligned gain, an overridden gain getter, unsuitable shard widths, noncontiguous IDs and specialized JIT failure used native handling. [Model and Humming replay](dispatch.json)
- The module is resolved before graph capture. Real four- and eight-rank Gloo trials exercised 204 rank conditions. A second bit shares the pre-existing Gloo MIN vote across ranks. A missing module, different PyTorch build, hook or unsupported model can therefore retain ordinary output columns on all ranks. On a later local shape rejection, the ordinary row order is restored from the completed all-gather, and the installed norm runs. No second collective is required.
