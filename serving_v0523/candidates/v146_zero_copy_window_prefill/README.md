# V146 zero-copy sliding-window prefill

V146 extends V143's full-attention optimization to eligible sliding-window prompt layers. It checks physical FP8 slots in the translated sliding-window cache once per forward. If the visible keys form a dense, uniformly strided batch, Hopper FA3 can use its tensor-memory accelerator to read K and V from their existing storage. The candidate retains V64's four flags and page-one allocation. The official export contains 61,251 bytes across 11 permitted Python files. [Patch, flags and validation](validation.json) · [Two-file V143 delta](delta.diff)

For a request with K live keys, Q new query rows and an inclusive left window L, the first visible key is max(0, K − Q − L). The kernel computes Q from the actual device query offsets. It checks every visible physical slot, bounds every read by that request's own length, and ignores expired slots. When all rows qualify, FA3 receives each original query, a view of its visible K/V suffix, the cropped device lengths and the original causal window, scales, output buffer and split policy. Shifting both ends of the bottom-right mask preserves the keys seen by each query. Fragmentation, an unfinished certificate, a different window or metadata object, graph padding, full capture, sinks, LSE requests and deterministic execution retain the ordinary path. The cropped length tensor records the consuming CUDA stream. [Independent runtime and FA3 review](independent_review.md)

For one 16,384-token chunk following a 65,536-token prefix, the 2,048-token window makes 18,431 keys visible across the chunk. The verifier examines 73,724 bytes of unique int32 slot IDs and returns 48 host bytes for all eligible layers. At two 64-wide FP8 KV heads, the earlier V105 packing approach would read and write about 414 MiB across 46 sliding-window layers per GPU. V64 already skips keys outside the window and reads directly from paged storage. The potential improvement over V64 therefore depends on the dense FA3 kernel, the cost of validating the IDs and how often physical spans qualify. The production proof ran in the Triton interpreter across 220 cases, including stale slots, malformed offsets, undersized capacities and nonuniform suffixes. Sixteen Hopper specializations compiled with zero spills. The independent wrapper ran 72 paired cases against V143 and checked 57,103,104 selected FP8 bytes. Another 460,800 comparisons reproduced the physical key ranges of the pinned native attention code. The inherited full-attention path passed its 243 interpreter cases. Output agreement, peak memory, first-token latency and serving throughput still need the H200 judge.
