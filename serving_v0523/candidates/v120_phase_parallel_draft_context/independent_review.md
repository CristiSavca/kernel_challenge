# Independent V120 review

The official DFlash2 model inherits the native `DFlashDraftModel.project_target_hidden` method. Its ordinary verify output supplies the same five target taps to every member of the draft tensor-parallel group. V120 binds that group inside `draft_tp_context` after checkpoint loading. Rank `r` owns output channels `[1024r, 1024(r+1))` at TP8. The narrow keeps all 40,960 input features. The device all-gather restores the channel axis in group-rank order, then the original `hidden_norm` sees the complete 8,192-wide result once. GEMM shape can affect BF16 rounding on H200. The existing target verifier and accepted-slot writes still execute their original work.

The worker's two production callers distinguish prompt and verify with their slot metadata. The verify call supplies `cache_loc_2d` and `commit_lens`. EXTEND supplies `extend_lens` alone. V108's completed SP projection marker takes precedence in both. V120 leaves the full replicated `nn.Linear` available to the SP prompt path. For a 16,384-token eligible prompt chunk, V108 still gathers 256 MiB of projected features per rank. Short or ineligible prompted inputs still use the original replicated projection and acquire no verify all-gather. [V108 prefill evidence](../v108_replicated_sp_draft_context/README.md)

The startup Gloo vote is unanimous. Every supported verify rank executes the same device collective using the original weight reference before dispatching a hook or an overridden local projection. Local hook and module replacement semantics therefore survive without a host collective on each decode. A two-process CPU/Gloo run executed the production helper and native projection body against real BF16 `nn.Linear`. It checked 52 rank-local results for exact agreement, hook counts and precisely one all-gather. Coverage includes either owner registering a mutating pre-hook, post-hook, global pre-hook or normalization hook, replacing the FC, replacing its Parameter, overriding the projector, or enabling deterministic mode or autocast. The autocast test also supplied FP32 input to a BF16 FC, exercising the temporary cast before native fallback. Production still assumes replicated tap values and current checkpoint weights across the draft group, as ordinary TP inference requires. [Independent test](independent_hooks.py) · [Machine-readable receipt](independent_hooks.json)

At TP8 the candidate retains the full 640 MiB weight on each device for prompt processing. A verify pass logically consumes an 80 MiB row slice per device and performs one eighth of the original FC multiply-adds. At one user and width eight the assembled buffer is 128 KiB, with 112 KiB of incoming peer data per rank. At 32 users it is 4 MiB. The pinned group implementation gathers rank-major into one buffer, then permutes and reshapes, which can materialize another. At the 256-row scored maximum, both buffers plus the local result amount to 8.5 MiB, or 4.5 MiB above one native full output. Allocator bins, communication workspaces, graph pools, and the achieved end-to-end peak require hardware measurements. The original V64 reported +1.9 GB per GPU under the +2 GB cap. Replacing a live model's FC Parameter can retain an old full-weight storage until the worker is reinitialized. The judged checkpoint is static. [V64 result](../../runs/abd217baf0ed49fd.json)

Even granting an eightfold projection speedup and zero communication cost, quadrupling a whole decode pass through this projection alone would require it to account for six sevenths of baseline pass time. Its measured share is unknown. A matched check can determine the contribution of the channel exchange, GEMM geometry and allocator behavior at the intended load. This review used no GPU allocation or challenge quota.
