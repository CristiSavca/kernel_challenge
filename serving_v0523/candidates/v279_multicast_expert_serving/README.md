# V279 shares prompt expert activations across GPU blocks

V279 integrates the gate/up and down projections on V248 with the compact prompt route planner and the fused decode route staging path. Both prompt projections now protect shared memory between consecutive jobs. V270 and V273 were withdrawn after the original two-block down projection was found to reuse a peer’s live output buffer. The two- and four-block down kernels in V279 have the fix. [Official patch](patch.diff) · [Independent ordering check](fence.json)

On rank 3 of the archived 16,384-token route fixture, gate/up needs 4,356 MiB of BF16 activation source boxes with ordinary blocks and 1,089 MiB with four-block multicast. The wide down projection needs 2,496 MiB with two blocks sharing a transfer and 1,248 MiB with four. All packed weights, per-group scales, output rows and K terms are retained. The down projection uses four blocks only when its occupancy matches the two-block case. Gate/up permits losing at most one four-block cluster, with a minimum of seven eighths of the ordinary grid. At 132 resident blocks all eight reconstructed ranks had identical critical issued-row counts for both gate/up variants. At 128 blocks the largest increase over ordinary dispatch was 4.6% for the 12K case and 4.2% for the 16K case. [Gate/up replay](../v277_multicast_prompt_gate_up/traffic.json) · [Down replay](../v274_four_block_prompt_multicast/schedule.json)

Six integrated CUDA sources were rendered by the pinned Humming generator. The exact two gate/up sources were recompiled for SM90a, including the real CUDA driver/TVM launch wrapper. The four down sources matched the compiled inputs from V274 byte for byte. Eleven synthetic host runs went through the model’s actual prompt entry, including the path from the fused gate/up activation to the four- or two-block down projection and independent projection fallbacks. The five component patches reconstruct the same tree in all 60 valid orders before the shared fence and tighter occupancy rule are applied. All eight inherited flags pass the live contract. V64 holds the official four-load score of 1.4119×. V279 has no H200 serving result. For scale, charging all of the avoided gate/up requests as HBM misses at 4.8 TB/s over the archived 32-user cold wave gives 6.63 seconds against 212.78 seconds elapsed. Actual DRAM traffic, overlap, issued work, synchronization, cache reuse and the runtime’s occupancy decision can move the result. This calculation cannot predict a four-load score. At 50 MiB of fully associative L2, all eight combinations of issue order and grid size model the same HBM read volume for ordinary and clustered kernels.
