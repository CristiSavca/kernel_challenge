# V149 overlaps prompt route planning with pooled input exchange

V149 starts from scored V64. At 8,192 or more native Muse prompt rows, the sequence-parallel Humming path gathers routing scores and IDs first. A shared model-owned Hopper stream maps global IDs onto local experts, performs V64’s stable sort, and builds the same expert offsets. Meanwhile the main stream gathers the pooled BF16 input, then rejoins the planner before the normal grouped expert call. All ranks issue their three collectives on the main stream in the same order, including ranks with hooks that require ordinary routing. Native W13 and W2, per-expert normalization, finalization, the full-size reduce-and-narrow, and unpool receive their usual inputs. The 48,957-byte official export uses V64’s four flags and has SHA-256 `3d95c2a024218660f942a0801e9e5e4778ef9d6fe694aac23fe89772e03718e5`. At 16,384 tokens, each rank receives 112 MiB of pooled inputs from its peers into a 128 MiB result. The new order can hide up to the shorter of the route-planning and gather times. At an illustrative 200 GB/s of effective per-rank gather bandwidth, the window is 0.587 ms per layer. Actual availability depends on graph replay, NVLink bandwidth and competition for GPU resources. The native host read of the route count still follows the join. Route IDs, sorted expert IDs, slot indices and offsets occupy about 2 MiB per rank before sort scratch. The shared stream allows successive layers to reuse those allocations. Scored V64 consumed 1.9 GB/GPU over stock against a 2 GB limit. Combined peak memory, TTFT, output agreement, exact lengths and throughput need H200 measurement. V149 has no private slot. The production forward and grouped adapter matched V64 over 336 TP2/4/8 rank cases using real Gloo exchanges and CPU stand-ins for Humming and the finalizer. Tests compared 1,353,600 BF16 output elements plus each grouped GEMM’s complete expert offset vector. The captured/eager path used the pinned break-wrapper, its nested argument handling and 96 changing-route replays with fixed tensor addresses, comparing another 1,122,560 BF16 elements. CUDA execution, overlap, the CUDA graph allocator and NCCL remain unmeasured. Splitting the *return* collective would change the 128 MiB native dispatch. Eight equal pieces fit the pinned custom communicator’s 16 MiB workspace; a reduced payload can select a different reduction backend or schedule. BF16 addition can give 0 or 1 when grouping 256, 1 and −256. The scored path has one reduction, followed by a rank-local unpool which needs those reduced channels. V149 retains that boundary. The draft alternative also has a concrete dependency: V64 already uses one projection for both sides of each dynamic convolution, and the next projection consumes the normalized result of attention. V123b and V114 cover rank-major output layout and repeated mask embeddings.
