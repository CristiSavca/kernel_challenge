# V85 streamed draft vocabulary projection

The DFLASH2 selector projects every draft hidden row against every original vocabulary row on its TP shard. V85 computes that dense BF16 projection in Hopper tensor-core tiles, rounds each completed FP32 dot product to BF16, and retains each tile’s highest-scoring candidates. A second reduction recovers the shard’s top K. One TP gather transports the FP32 score bits and global token IDs as pairs to the existing selector lattice. Uneven vocabulary shards may select dense or tiled local kernels independently and always participate in the same collective.

At K=16, each full 128-token tile emits 64 bytes of candidate keys per hidden row. The dense BF16 logits for that tile occupy 256 bytes. It still reads and multiplies every vocabulary weight. Vendor GEMM accumulation order and unspecified draft top-k ties can select a different proposal at a rounding or tie boundary. The complete target computation, greedy acceptance and sampled-proposal correction retain their existing logic. The switch applies to eager and graph DFLASH2 selector proposals. Full-partition requests retain their original path.

V85 adds `--flag speculative-dflash-fused-candidate-head` to V84’s launch flags. The frozen patch is a component for composition. Its V84 parent contains an attention compiler failure discovered during this iteration. V84a repairs that inherited issue. The V85a follow-up also reduces register pressure in the vocabulary tail.

CPU tests exercised 65,536 BF16 encodings, 48 full/partial tile projections with row strides and ties, and 60 PyTorch rank invocations including mixed local dense and fused paths. The [SM90 compiler receipt](sm90_aot.json) covers 16 compiled projection and merge specializations. No GPU timing or full-model output is available. At K=16 the 25,256-row vocabulary specialization spills 12 bytes to local memory and reloads 24 bytes per thread. For a CPU repeat, run `cpu_check.py PATH_TO_PATCHED_SGLANG --torch` with NumPy and PyTorch installed. [Validation receipt](validation.json), [official rules](https://openkernelchallenge.dev/rules).
