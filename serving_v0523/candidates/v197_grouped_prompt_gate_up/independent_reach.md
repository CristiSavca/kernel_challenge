# Grouped prompt path and the size of the opportunity

**V197 targets a reachable cold-prompt operation on V195.** With the Humming target backend and layernorm sequence parallelism enabled, ordinary EXTEND dispatch replicates the pooled expert inputs, routing scores and IDs across TP, then calls the normal expert module. V195 selects `_grouped_humming_and_combine → humming_grouped_expert_outputs` for BF16 inputs with post-expert norm weights and at least 256 routes per global expert. For top eight and 256 global experts the first eligible execution shape is 8,192 input rows, including padding visible to the model. Eager and Breakable graph replay can execute the grouped callable. Ordinary stream capture and Dynamo tracing fall back to the indexed path. A three-gather replay through four original methods confirmed all 192 threshold, dtype, post-norm and execution-mode combinations. [Executable check](independent_reach.py) · [Results](independent_reach.json) · [V195 source export](../v195_fused_expert_affine_verify/patch.diff)

The grouped callable sorts local route slots, removes the remote prefix, and gives each projection contiguous row offsets for its 32 local experts. Both prompt tunings come from the final Humming grouped bucket with Stream-K and TMA-C disabled. Published Humming 0.1.12 gives W13 a 176×256×64 CTA tile, four stages, 384 threads and 128,000 shared bytes. V191’s decode kernels use 8/16/24-row tiles with a 128-wide K stage and packed route keys. V169’s alternative 136/152-row prompt tiles belong to a separate branch. The stock grouped path applies the gate’s per-expert BF16 global scale to **both** W13 halves following the BF16 projection cast. It rounds that product to BF16 before FP32 SiLU times up and a final BF16 activation cast. W2 then separately casts its projection to BF16 and multiplies by its own global scale before postnorm and routing-weight combination. [Native Humming geometry](../v169_grouped_expert_tile_cohorts/generated.json) · [Narrow decode geometry](../v191_decode_gate_up_epilogue/config.json)

**A fused W13 epilogue removes four full intermediate accesses on V195.** The GEMM writes the unscaled gate/up, the in-place scale reads and rewrites both halves, and SiLU reads both again. At the archived 16,224 local routes and 4,096 intermediate channels this is 1,014 MiB per layer, plus the small scale-index buffer. V177 saved 507 MiB against its already-fused activation parent at this size. The corresponding V195 transfer time at the published 4.8 TB/s H200 peak is 0.222 ms per layer, conditional on every byte reaching HBM. Kernel launch overhead, L2 hits, actual bandwidth and the fused kernel’s efficiency change the realized saving. [V177 traffic scope and H200 archive](../v181_peer_inputs_paired_gate_up/physical_comparators.md)

**A 5% raw throughput gain needs substantially more than that transfer equivalent.** The archived eight-H200 client traces contain 75 eligible logical prompt calls at 16 users and 150 at 32. Spread across each call’s 62 layers, a 5% whole-trace improvement requires 1.688 ms and 1.559 ms net per layer respectively. Under uniform rank load, the eliminated intermediate’s peak-bandwidth transfer time represents 0.25–0.68% of elapsed time across the seven repetitions. These counts use logged logical rows. Graph bucket padding, rank skew and the execution of additional calls at a larger shape can change exposure. [Measured trace replay and per-load thresholds](independent_reach.json)

The closest 16,224-route single-H200 experiment measured **7.188–7.394 ms for the complete Marlin expert call**, containing both projections and their surrounding operations. The grouped dense BF16 reference, with already prepared inputs and weights, took 2.643–2.698 ms. Neither interval measures stock Humming W13, its activation or the savings of V197. As a scale comparison, achieving 2.833× raw end-to-end by accelerating only those logical grouped calls would require **22.94 ms per layer at 16 users**, or **21.18 ms at 32** on those traces. V177’s compiler evidence and V183’s W2 instruction scheduling cannot establish this saving. A matched H200 timing of the original and fused *complete grouped call* is the relevant next measurement. The initial V197 source also passed independent numerical review. The CPU oracle executed the production C++ prompt tensor-map builder and M176 shared-memory writer, checked 3,538,944 native packed addresses and 18,382,848 BF16 destinations, and verified 24,635,136 untouched guard words. Its inputs cover every BF16 bit pattern on each half. Prompt row metadata holds direct local expert IDs, so the tile’s first live row selects the correct scale without decoding a packed key. The fused branch allocates its compact W13 activation separately, then W2 reuses the staged input as its output only after W13 has finished on the same runtime stream. Empty ranks return before launch and W2 retains its original postscale. CPU expf and software BF16 round-to-nearest-even were used for this test. Hardware WGMMA, CUDA fast math and achieved latency still require physical measurement.
