# V197 · grouped prompt gate/up on V195

V197 writes the BF16 SwiGLU activation directly from the grouped W13 projection in ordinary long-prompt MoE. The actual Humming 0.1.12 tuner chose a 176×256×64 CTA on the scored 4096-channel expert. The same prepared W13 bank also serves the existing 8/16/24-row decode kernels. V197 inherits V195’s five launch flags. The official export is 187,772 bytes, SHA-256 `0974f9542bd481e7c15fbce9331cd041966ebf4e4813e7d1640defcc728b2f0e`. [Patch](patch.diff) · [Four-file delta](delta.diff) · [Frozen tree, flags and rules](validation.json)

For an EP rank with 16,384 live local routes and 4,096 intermediate channels, the original BF16 double-width projection occupies 256 MiB. Its four global-memory touches are the W13 store, both sides of the in-place global-scale multiply and the SiLU read. The fused path eliminates those four touches, the scale gather and three kernel launches. It saves 128 MiB of peak expert workspace for this shape. W13 and W2 still perform both full projections with all the original weights. At 4.8 TB/s, transferring 1 GiB would take 0.224 ms. Caching, occupancy, compiler differences and the actual route distribution affect realized time. [Native branch, actual archived shape counts and H200 timing limits](independent_reach.md)

The standard grouped callback for this model requires at least 8,192 logical prompt tokens under the inherited policy. Prompt route IDs already identify contiguous intervals for each local expert. The epilogue takes the scale from that expert’s interval, rounds projected gate and up separately to BF16, scales each with BF16 rounding, then applies SiLU and stores the BF16 product. W2 consumes compact activations, reuses W13 input storage only after W13, and applies its original BF16 global scale before per-route normalization. Missing device/compiler support, unsupported tuning or changed bank addresses select stock grouped execution. Deterministic mode retains stock execution.
