# V190 pairs the grouped target expert kernel with bounded draft metadata

V190 applies V188’s two-file draft metadata change to V189. A verification round first builds the current request’s draft page table from physical addresses in the shared pool. Five DFlash2 layers use those addresses to propose the next tokens. Target verification subsequently runs the V189 grouped W2 expert kernel where its original width and architecture gates permit. These operations run in different model passes. Their actual timing and effect on accepted throughput are unmeasured. [Combined patch](patch.diff) · [Changes against V189](delta.diff)

At 16 users, the archived V41 lengths give 17,237,738 full-prefix address entries versus 441,578 for the bounded representation at the first decode block. Both versions perform the same attention, preserving the five real receptive fields and their 128-key tile boundaries. At the same load, V68's earlier private check reached **17,512.9 tokens/s/GPU**. Gains from reducing metadata work depend on how much time that single kernel occupies in the end-to-end round. V189 also retains the paired prompt projection, direct prompt KV and target paged-attention work from V187. [Draft-window geometry](../v188_draft_window_metadata/independent_geometry.md) · [V68 physical control](../../runs/04b01f958aa5487c.json) · [V189](../v189_decode_grouped_mma/README.md)

V190 inherits V189’s five flags. The FA4 draft graph writes at most 2,182 page-one addresses per request in the ordinary fixed-width case. The registered DFlash2 startup configuration selected window-left 2,047. All 48 adverse configurations declined the optimization. The native target FA3 path, physical FP8 writes and W2 launch/setup code are preserved. The compiled SM90/SM90a receipts apply to byte-identical production kernel source. ## Verification on the integrated source

- The production draft graph metadata and FA4 wrapper ran for 200 calls over five-layer trajectories. All 84,800 compared BF16 components and 425,300 physical page IDs matched their ordinary CPU reference. [FA4 replay](replay.json) · [Fixture](../v188_draft_window_metadata/replay.py)
- The production grouped expert dispatch ran 144 end-to-end CPU cases over enabled, missing-middle-width and disabled modes. All 168,471 BF16 components matched. The C++ replay checked all four K-warp offsets at each of the three widths and 13,824 FP32 outputs. [Grouped dispatch](decode.json) · [C++ arithmetic](cpu.json)
- Seven integration suites covered Gloo transport, draft physical KV, Muse graph output retirement, fusion eligibility, FA3 fallback and paged FP8 attention. Every recorded behavioral result matched V189’s inherited reference. [Independent replay](independent_integration.json)
- The official exporter produced 158,066 bytes across 28 source paths. Both the original V188 delta and the V189-relative delta reconstructed the same tree, and all three patches reversed cleanly. The full export and five flags passed the published static limits. H200 performance, combined peak memory, first-token latency and all-load correctness remain unverified.
