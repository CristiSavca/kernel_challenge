# Target KV layout and copy coverage

Source checks used SGLang commit `297e54fd105e974cdf401e5b4d20253a22c16f90` with the frozen V99 patch. The new module SHA-256 is `752f519a11313d6409fc252961ae0ee95acea305cb60fcac80ff54f78d64e27a`.

The legacy hybrid builder instantiates `SWAKVPool` with ordinary MHA children for E4M3. It passes no quantization recipe. Each child selects `UnquantizedKVCacheMethod`, so its `is_quantized_kv_cache` property is false. The KVCache base stores E4M3 in uint8 tensors. In default NHD layout their shape is `[slots, heads, head_dim]`. The standard SWA allocator registers a contiguous int64 map with a trailing sentinel. Newly reserved full slots and their SWA peers are private to a live request. Slots with zero or negative physical IDs never write.

The pre-capture VMM owner creates ordinary contiguous tensors with the same shape and storage dtype in its arena. The pool assigns these tensors to K and V, then builds its existing uint64 base pointers and int64 row strides. Finalization backs the reserved virtual addresses and sets the serving capacity. The compactor obtains the current pool's arrays and map for each invocation. The setup vote also exercises a zero-length call, which never accesses the physical K/V bank. HND, page-major, unified and sidecar-quantized pools fail the static admission check.

Every program owns one request, one layer's K or V buffer, and 32 aligned 32-bit columns. A CTA loads each moved source for its column tile and reaches a block barrier before any store. Different requests own disjoint reservations, and different buffer/column blocks own disjoint words. An accepted source can alias another accepted destination. The copy uses the original bytes even in this case. Identity rows, slots beyond the accepted prefix, prior history, and other requests retain their bytes. The helper never writes the request table.

At TP8 with two local KV heads of 64 E4M3 elements over 62 layers, one slot holds 15,872 bytes of K and V per rank. For the width-eight topological tree, moving a row means at least one proposal was skipped. At most six positions move after the identity root. This bounds copy reads and writes at 186 KiB per active request, excluding metadata traffic. Parent-to-child edges in `_propose_tree` always point from an existing node to a later one. The kernel also passed synthetic cycles that exercise its stronger snapshot guarantee.

The exact production kernel ran in Triton 3.8's CPU interpreter with host-accessible raw pointers. Forty-eight combinations checked 7,286,016 bytes at page sizes 16 and 64, all widths 1–8, direct and both mapped pointer types, unequal row widths, inactive and identity rows, and bank/map replacement. Two additional zero-length startup checks used null bank addresses. This exercises copying and addressing.
