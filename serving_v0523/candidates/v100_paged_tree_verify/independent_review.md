# Paged DFLASH target and draft KV review

A page larger than one token makes the original request-table permutation invalid. Both paged attention and HiCache derive a slot from the page's first physical ID plus its offset. V100 keeps every physical page and offset in place. After the verifier accepts a tree path, it copies each accepted target node's K/V bytes into its corresponding sequential position in the reserved window. Tree acceptance includes the old anchor and ends with the verified bonus as its next input. The bonus's own K/V belongs to the next forward.

For one request, layer, key-or-value array and 128-byte column stripe, a single CTA gathers every source row before it writes any destination. This covers paths such as nodes 0, 2, 4 and 6 where an earlier source is itself a later destination. Distinct CTAs operate on disjoint column stripes, arrays or writable request windows. Shared prefix-cache pages precede those windows. The ordinary SWA allocator assigns both full and SWA locations for writable slots. The kernel reads the current full-to-SWA mapping independently for source and destination. Trailing rejected slots are still reserved and get overwritten when needed.

The capability check admits the plain token-major MHA pool or the conventional SWA wrapper around those pools. Per-token scale arrays, alternate memory layouts, pointer/stride mismatches and unsupported cache types select the incumbent path. The helper uses each pool's current pointer and stride arrays, including the separate widths of keys and values. The FP8 K/V data is copied as unsigned 32-bit words, preserving each stored bit.

The draft append receives the original physical destinations and the accepted node order. Its compact projection reads each original hidden row by that order, while its fallback explicitly gathers those rows. Both write sequential accepted positions. The worker records the shared cache-completion event following both the target copy and the draft writes before it publishes the new tree lengths. Page-aligned allocator accounting, page ownership, the full-to-SWA map, the request table and output token accounting keep their ordinary meanings. The option retains page-one behavior, and a failed paged capability or JIT probe votes to use linear verification across the TP group. [CPU worker integration](worker_check.json)

The independent fixture ran the submitted compactor, Python layout gates and dispatch on CPU-backed byte arrays, with random CTA issue order and explicit bounds checks. Across 96 configurations it checked 64,880,640 bytes against snapshots, including unequal key/value widths and adversarial source-destination cycles. A second sequence ran actual tree acceptance and compaction for 32 successive batches, covering all eight possible commit lengths, mixed active rows, reuse of a retracted physical tail, a shared radix prefix and page crossings. It compared 576 complete physical pages to the byte oracle through that sequence. These page-copy checks model HiCache's buffers; a live HiCache transfer still requires hardware. The actual packed attention kernels also ran against an expanded page-one slot reference on physical pages of 16, 128 and 160 tokens. All 552,960 output values matched in 36 cases with irregular prefixes, mixed requests, one or seven split lanes, multiple KV heads, full attention, and short and long sliding windows. This isolates page indexing and tree masks under identical simulated arithmetic. Native SM90 attention, graph capture and replay, GPU concurrency, operational prefix hits, peak memory, throughput and first-token latency require an official run.
