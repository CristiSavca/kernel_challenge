# V278 combines capture-time routing overlap and wider decode expert tiles

V278 is the decode-focused H200 check candidate based on measured V68. It combines V272’s independent routing and normalization streams with V275’s four-band W13 and W2 tiles at high load. The official patch is 81,106 bytes with SHA-256 `384c343938ed59d74937fa1402c86da6ff4f14373fd7403362f64f04b3622817`. Both integration orders reconstruct tree `cbe81725c7f03210676ed949f7b6e0d4ac94effa` from the published pin. The inherited launch flags pass the published contract. V278 has no H200 token agreement, latency or throughput result. [Official patch](patch.diff) · [Reconstruction and rules](validation.json)

Once capture warmup has resolved the built-in router, the main stream computes the pooler and native RMSNorm while the router stream computes top-eight routing and the grouped expert plan. The main stream waits before it gathers the projected inputs. Each expert projection then uses the ordinary Humming callback with the selected geometry. Width-eight W13/W2 retain V68’s original tile. At 16- and 24-row tiles the widened W13 and W2 share each input tile across twice the output channels. Compile rejection restores each native projection independently. Hooks, eager execution, a registered out-of-tree router, and other ineligible modes retain native stream order.
