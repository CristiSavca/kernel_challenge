# V90 fused activation and routed down projection

V90 replaces two high-occupancy expert launches per sparse layer with one. W13 writes the original BF16 gate/up output. Each W2 block applies the same expert scale and BF16 round to gate and up, calls the incumbent CUDA SiLU helper, rounds the product to BF16 and keeps a slab of those activated values in shared memory. Eight warps reuse that slab while producing 512 output columns. The second GEMM still traverses the complete K dimension with BF16 operands and FP32 accumulators. Its final BF16 values feed the parent’s scale, route-specific normalization and slot-ordered summation.

A warp-prefix scan maps a compact tile index to a real expert and up to 32 live rows using device-resident offsets. Empty experts produce no matrix operations. Within a tile W2 unpacks each 64×16 weight region once and uses the result for one, two or four eight-row MMA fragments. Skewed experts get several independent 32-row tiles. There is no host synchronization on routing data. The kernel checks the grouped layouts and uses the pre-existing packed weight bank. Input staging can hold the W2 output once W13 completes, so gate/up and W2 output reside in disjoint banks.

The path requires grouped Humming on Hopper, a compatible layout, K divisible by 128, N divisible by 512, and more route slots than global experts. This expresses an average greater than one routed token per expert across the batch. At verification width eight and top-eight routing over 256 experts, full batches with 16 and 32 concurrent users qualify. V89 retains its small-batch path. The switch `SGLANG_ENABLE_MUSE_SPARK_HUMMING_ACTIVATED_DOWN=0` restores separate activation and W2. A failed optional JIT build selects the parent’s implementation before graph capture.

## What changes at high load

For 128 and 256 target rows, uniform routing has 128 and 256 expected local routes per rank. The eliminated BF16 activation store alone is 1 and 2 MiB per layer at intermediate width 4096. W2 consumes those values directly. At output width 4096 eight independent output bands read gate/up and evaluate SiLU for each live route. This duplication and the cost of staging slabs can exceed the saved launch and avoided activation traffic. The parent’s vendor GEMM uses TMA and already processes most lightly occupied experts in one tile. Any reduction in packed W2 weight reads depends on the actual expert histogram and parent tile size.

Eight warps use a 128-element K slab with eight BF16 elements of row padding for shared-memory bank layout. Compiling the production kernel and TVM FFI wrapper with CUDA 12.9.86 for SM90 used 96 registers per thread, 8,704 bytes of static shared memory and no spill or stack space. The full-model throughput and agreement remain unmeasured. The latest released judge frontier at freeze was V64 at 1.4119×, with V68 and V87 still queued. [Compiler output](sm90_compile.log)

## Validation

The official [patch](patch.diff) is 197,451 bytes across 33 files. SHA-256 is `45fba4620ea380966400f7114df6070624839eff0407b2c375e92bad034f71a6`. Its [three-file delta](delta.diff) applies to frozen V89. The compiled W2 cubin hash is `a5ebff8d2fe0ad8cd826bdad1916307ba101e5f22008f96a6fb0d64568962368`. [Export receipt](validation.json)

The CPU harness ran the actual W2 tile C++ with software warp MMA and GPU arithmetic primitives. Real 32-thread prefix scans exercised both 32-expert groups. The checks covered 35 route plans, 143,360 live BF16 outputs and 20,992 poisoned inactive-prefix elements. Cases included tails up to 65 routes, no local routes, wider matrices, multiple K slabs and independent width-4096/K-4096 cases. A separate shape-only run through the actual grouped caller checked 96 path selections, disjoint input/output banks and producer-consumer aliases. Different hardware MMA accumulation order can affect agreement with the parent on real activations.
