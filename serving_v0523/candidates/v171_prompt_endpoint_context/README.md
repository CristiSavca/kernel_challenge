# V171 gathers only the prompt rows needed by the LM head

V171 builds on V168. On an eligible long prefill, each sequence-parallel rank runs the draft’s full-width BF16 context projection and its existing RMSNorm on its own token rows. It then gathers the normalized features for every prompt token. For ordinary next-token prediction, the target model passes one final hidden row per request to the existing Muse LM head. The decoder, expert choices, attention window, projection weights and verifier remain the same. [Submission patch](patch.diff) · [Delta from V168](delta.diff)

At 16,384 prompt tokens on eight GPUs, V168’s two gathers produce 1,536 MiB of logical output per rank. In V171 they produce 256.125 MiB for one sequence or 260 MiB for 32 sequences. Against the earlier V120b design, the new savings come from selecting the final rows before gathering them and moving RMSNorm to the token owner. The dense FC performs 11.00 trillion floating-point operations per rank on V168 and 1.37 trillion on V171. All K terms and all five draft taps take part. These figures describe one eligible forward. The public judge receipts identify client concurrency and aggregate timing, but omit the batch cardinalities during timed execution. [Audited geometry and trace coverage](traffic.md)

## Correctness and eligibility

The draft worker enables the feature for ordinary prefill when the target and draft tensor-parallel groups are compatible. Module type, dispatch, weight layout, device, capture mode and hooks take part in eligibility. Every rank votes before a collective changes width. Special scoring requests retain dense rows. Small prompts, unsupported normalizers, deterministic or instrumented execution and graph capture can fall back to the parent path. V171 adds one default-off flag to V168, `--speculative-dflash-sp-prefill-context`. The schema check preserved all 547 existing positional fields. [Flags and export validation](validation.json)

The distributed CPU test ran 324 complete prompt forwards across two, four and eight ranks. It invoked the pinned Muse forward, the native draft projection and RMSNorm, and the logits processor. It compared normalized features and logits and checked the exact collective shapes. It also compared raw BF16 endpoint bits for strided tensors, negative indices, duplicate selections, signed zero and NaN payloads. Special scoring cases used a CPU scoring observer to verify that every expected dense row reached the scoring interface. [Prompt test](check_prompt.py) · [Results](prompt.json)

A separate replay exercised the worker, graph-output trimming and draft KV handoff in 351 cases. It checked 3,340,224 normalized BF16 elements, including a fused writer failure followed by the sequential fallback. This replay simulates peer ranks and cache transport. [Worker replay](independent_worker.py) · [Results](independent_worker.json)

The official CLI exported 172,102 bytes against the published pin. Both the full patch and incremental patch applied and reversed under strict Git checks. Static checks covered source paths, line lengths, prohibited source words and 76 denied launch-flag patterns. H200 accumulation behavior for different GEMM row counts, collective overhead, peak memory, TTFT, output agreement, full output lengths and scored throughput require a judge run.
