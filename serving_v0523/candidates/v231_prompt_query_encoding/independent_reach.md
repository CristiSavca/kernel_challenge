# V231 query encoding across the prefill graph break

Sixteen CPU comparisons reconstructed V229 and frozen V231 (`3640f33545825885757f2b3f981acce1c01d29a93414fbd0e7dbdef9a1688b6a`). Each ran the Muse attention forward, registered the native RadixAttention callback with `eager_on_graph`, and called it again through `BreakableCUDAGraph.replay`. The callbacks consumed 4,099 real rows for one request or 4,110 for two requests. Capture included 13 poisoned padding rows. [Replay](independent_reach.py) · [Case results](independent_reach.json)

The child delivered FP8 Q and BF16 K/V to the callback in eligible cases. Full and sliding-window layers retained the single-request dense, batched varlen and paged fallback FA3 paths. A marked KV writer forced the paged path while keeping early query encoding active. A registered normalization hook and the full-prefill-graph mode flag both selected the parent BF16 producer. The two versions matched across 67,248,128 encoded FA3 query bytes and 153,815,856 bytes in all compared arrays, including physical KV slots and FA3 inputs. Sliding layers exercised K scale 0.75 and V scale 1.625. [Case results](independent_reach.json)

The output followed the BF16 value tensor in the native graph allocator. A BF16 sentinel of 1.0078125 survived both downstream model consumers at every live output element. E4M3 rounds that value to 1.0. The reduced replay supplied the Triton arithmetic and FA3 result at their hardware boundaries. It ran the production producer dispatch, Triton host wrapper, graph callback, cache writer and FA3 argument builder. CUDA stream capture, weak accelerator references, FA3 arithmetic and serving time require a GPU. [Kernel interpreter](interpreter.json) · [Hopper compiler](sm90.json)
