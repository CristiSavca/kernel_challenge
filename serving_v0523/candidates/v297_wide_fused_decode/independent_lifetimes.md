# W13 register and shared-memory lifetime

The two widened SM90a cubins contain 320 static HGMMA instructions across their full and residual-width code. Every group issues four bands of one K16 slice, then drains the group completely. Each source quartet was ready at the warpgroup fence. Between issue and drain, 1,194 ordinary instructions execute across the two images, including 1,091 writes to general-purpose registers. None reads or writes a live source word or accumulator. No branch enters or leaves an outstanding group. The M16 image covers row widths 8 and 16. The M24 image adds row width 24. The binary hashes match the archived machine receipts. [Source and machine check](independent_lifetimes.py) · [Results and rejected mutations](independent_lifetimes.json)

The generated code computes the BF16 weights and applies the block scale before each warpgroup fence and issue. The source keeps each of the four words per band live through the group's wait. Humming places the activation tile in shared memory and the dequantized weight in registers. Each emitted shared-stage release follows all four K16 slices, after the sixteenth HGMMA and its complete drain. The loop preloads from the next stage after the last slice returns, subject to its remaining-work guard. In the narrow control images, eight HGMMA instructions cover the same four slices. Their intermediate next-stage wait can branch out of line with work pending. The audit follows those polling paths until they rejoin the same live register set.
