# V114 schedules live expert work at low decode load

V114 changes how the V89 sparse gate/up CUDA kernel distributes its work. The original grid reserves one thread block for every combination of local expert and 64 output channels. A block assigned an empty expert reads its offsets and exits immediately. V114 uses warp ballots on the existing per-rank offset table to number the experts that actually received rows, then strides through those ordinals. Each eligible thread block calls the original projection on its assigned live expert. Every row and output channel keeps its full reduction, rounded operands, activation and output location.

On the native one-request, eight-token verifier, the caller supplies 64 route slots, 256 global experts, 32 local experts and 64 output bands. V89 launches 2,048 CTAs per rank and sparse layer. V114 launches 1,024, saving 63,488 CTA launches across 62 sparse layers per GPU and verification pass. These are thread blocks within the existing kernel launches. The occupied expert IDs are re-read on every device replay. The resource estimate controls the static grid size. A skewed request can assign several live experts sequentially to one CTA, including when every local expert receives tokens. At 16 target rows or more on this particular topology, the estimate selects V89’s original grid.

Under an illustrative uniform top-eight routing distribution, eight target rows visit 7.18 of the 32 local experts on average. Required weights, matrix work and output values are the same under either schedule. A smaller grid can improve block-issue costs, while the new ballots and possible extra iterations can reduce parallelism. The potential effect is limited to sparse W13 at low load. End-to-end throughput, GPU correctness and any contribution to the 4× challenge objective remain unmeasured. [Prior weight-traffic analysis](../../runs/low_load_expert_traffic_feasibility.md)
