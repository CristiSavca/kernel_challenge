# First-layer draft mask reuse

The first DFLASH block contains one anchor token and seven copies of the mask. The first normalization and dynamic filter can therefore share a result across mask positions. The trained two-tap convolution makes the first mask depend on the anchor. From position two onward, the mask also has a mask predecessor, giving identical inputs to QKV before RoPE. At one request, the filter GEMM could use two distinct rows and QKV could use three. Rotary position, attention over the request’s KV history and later sublayers still distinguish those positions. Across requests the same mask-only representative is applicable only when the embedding and associated transformations are also identical. [Pinned draft and score](../../runs/abd217baf0ed49fd.json) · [Published model configuration](https://huggingface.co/RadixArk/Muse-Spark-Open-DFlash2/blob/46c90f412549c472941a68382d91a99e5e6372a0/config.json)

At TP8 these two BF16 weight banks occupy 52 MiB on each GPU. Compacting the rows still requires every weight. It saves 306.2 million useful FLOPs per rank, 2.72% of the five draft layers’ linear work on the measured V64 stack, before accounting for the embedding, context projection, LM head, attention, target or communication. A single read of both banks takes 11.36 microseconds at the H200’s published 4.8 TB/s peak. This is a bandwidth scale, not a kernel timing. V64's one-user rung recorded four committed tokens per pass and 203.2 median decode tokens/s. Those aggregates do not expose draft phase latency. The stock Hopper GEMV backend admits one input row and would decline the eight-row block. [Bandwidth specification](https://www.nvidia.com/en-us/data-center/h200/) · [BF16 GEMV dispatch](../../sglang/python/sglang/kernels/ops/gemm/hopper_bf16_gemv.py)

The CPU test executed the pinned grouped convolution on 72 synthetic BF16 batches at widths 4, 8 and 12. All 264 requests reproduced the compact pre-RoPE projection and exhibited a counterexample to reusing the projected mask after RoPE or after attention. This example uses BF16 CPU linear algebra and a synthetic noncausal attention fixture. A CUDA GEMM's batch geometry can change its accumulation schedule. The evidence supports retaining the ordinary draft projection and spending the next experiment on target decode. [Executable test](check.py) · [Results and geometry](check.json)
