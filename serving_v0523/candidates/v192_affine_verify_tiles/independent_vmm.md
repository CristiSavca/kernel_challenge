# Physical KV backing and the captured Hopper tensor map

The scored V64 log reports a full target verify CUDA graph with eight tokens per request, captured for batch sizes 1 through 32, then 3,419,325 serving tokens in the full pool after KV sizing. The logged values establish capture reach and post-capture backing on H200. They predate V192. [Scored H200 run](../../runs/abd217baf0ed49fd.log)

Pinned `MHATokenToKVPool` constructs ordinary Torch tensors spanning its reserved virtual range. Its owner backs one padding page for capture, then maps a larger physical prefix in place and updates `pool.size`. For page-one legacy FP8, `get_paged_mha_kv_cache` reinterprets each native byte bank as E4M3 and returns `[reserved_slots, 1, local_heads, 64]`. Both bases and pitches therefore survive the backing change. V192's descriptor sees the reserved span. Physical read safety comes from the producer checking all 128 real allocated page IDs for one positive consecutive interval and completely excluding partial tiles. The direct branch loads exactly those same cells. This safety argument assumes the native allocator keeps all 128 IDs live for the forward, as required by ordinary indexed attention.
