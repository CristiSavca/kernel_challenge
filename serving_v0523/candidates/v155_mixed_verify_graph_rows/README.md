# V155 graph-backed target readout for mixed prompt and verification rows

V155 implements the target forward interface needed to put a real prompt and complete native DFLASH verification chains into one causal target pass. A caller supplies a resolved EXTEND batch with P prompt requests followed by T decoding requests of the checkpoint's width W. The target worker returns exactly P + T×W full-vocabulary logit rows, all real target hidden-state taps, and the native physical KV plan. The ordinary serving scheduler currently lacks the proposal, admission and settlement integration needed to use this interface. V155 has no measured H200 speed or score. [Official V147-based patch](patch.diff) · [Four-file delta](delta.diff) · [Frozen identity](validation.json)

The internal caller passes `mixed_verify_prompt_count=P`, `is_verify=True`, `capture_hidden_mode=CaptureHiddenMode.FULL`, and `return_kv_loc_plan=True` to `TpModelWorker.forward_batch_generation`. The target does no sampling or length publication. Before native position preparation, the worker checks the resolved prefix and input lengths, physical slot count, checkpoint width and CPU mirror. The caller owns the reservations, prior publish fence, correct device slot identities and actual proposals. The implementation supports text-only causal DFLASH in a single DP/PP/CP/DCP group, including tensor parallelism. The partial interface has no CLI flag.

Every input row takes the normal EXTEND body and the same prefill sequence-parallel path as ordinary prompts. After sequence-parallel gathering, the logits processor sends the last row of every prompt and every live verification position through the ordinary full vocabulary head, scaling and softcap path. FULL tap capture preserves all real positions. The selected rows follow the current forward batch through both breakable and full body replay. Graph output allocation uses the real head count, and oversized outputs use the native eager allocation fallback. Both graph trimmers return the required number of logit rows independently of token padding. A graph backend that also compiles the external LM-head tail falls back to eager execution.

The native CPU fixture ran 54 mixed forwards and 54 corresponding normal forwards across eager, full and breakable execution, checking every logit, all five synthetic target taps, positions and KV-plan identity. It exercised too-small and sufficiently large shared output buffers, repeated input sizes with different rows, 23 invalid entry configurations and four incomplete model outputs. The fixture runs the real worker, ForwardBatch construction, Muse model wrapper, logits processing, body-replay dispatch and output trim. It substitutes a deterministic CPU transformer-body stand-in, dense CPU vocabulary projection, device transport and graph buffer loading. The separate V152 reference checks real causal attention and accepted-chain math. H200 graph replay, checkpoint numerics, admission and throughput remain unmeasured.
