# V78 independent review

Reviewed SHA-256 `f042bb2d29454098bf8290bb0567949edb32303c59e05f4a8543142cfc5192d5`. The 145,959-byte patch modifies 28 permitted source files. Exactly three sections differ from V76. The longest added line is 106 bytes.

**Checkpoint and dispatch.** I read the 8,960-byte safetensors header at checkpoint revision `46c90f412549c472941a68382d91a99e5e6372a0`. It contains ten BF16 `layers.*.{attention_conv,mlp_conv}.kernel_projection.weight` matrices, each `[2048, 8192]`. Configuration specifies five layers, two convolution taps, group size 16 and block size eight. The stock name resolver handles all ten names and their `model.` aliases. The loader validates full checkpoint shape, then narrows the output axis at the rank captured during construction. The explicit opt-in is restricted to unquantized CUDA drafts with an active grouped convolution and a divisible output size on a multi-rank draft TP group. [Checkpoint](https://huggingface.co/RadixArk/Muse-Spark-Open-DFlash2/tree/46c90f412549c472941a68382d91a99e5e6372a0)

**Dataflow.** The draft declares `SINGLE_GROUP` and the DFLASH worker enters `draft_tp_context` for construction and forward. `DFlashDecoderLayer.forward` normalizes replicated rows before each active `prepare` call. Each rank retains full K and computes a contiguous slice of coefficient channels. Rank-ordered gathering precedes the original `[rows,2,taps,groups]` view. The pre/post convolutions, base kernel, normalization and residual operations retain their prior ordering. An empty layer returns before either filter projection. Different GPU GEMM shapes can change rounding.

**Independent checks.** The V78 source harness passed 8 factory gates, 144 projection cases, 726 checkpoint cases and 1,008 prepare/finish pairs. Its inherited context checks passed 120 gates, 336 projection cases and 924 checkpoint cases. A separate TP8 layout simulation checked 8,704,000 coefficient coordinates over the actual ten filter matrices at 1, 8, 32, 128 and 256 rows.

**Performance boundary.** Ten matrices shrink from 320 MiB of resident weights per GPU to 40 MiB at TP8. At 256 rows ten gathers receive 8.75 MiB per rank per draft forward and the generic gather can also copy data locally to restore channel order. Ten additional collectives make latency a primary risk, especially for small drafts. H200 graph replay, numerical acceptance, peak memory, TTFT and throughput require measurement.
