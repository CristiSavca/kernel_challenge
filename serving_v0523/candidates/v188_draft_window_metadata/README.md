# V188 bounds draft verification page-table work to the live attention window

V188 extends the metadata kernel that runs once before the five draft layers. Each request keeps the physical cache pages reachable by at least one of its eight queries, plus up to 127 earlier entries to preserve native attention tile boundaries. The original request map, allocated draft and target KV slots, RoPE positions, speculative width and target verification remain intact. The four launch flags match V68. [Changes against V68](delta.diff) · [Full export](patch.diff)

In archived V41 traffic at 16 users, the 208 first decode blocks had 17,237,738 live page IDs. Applying the bounded lookup to those same lengths would gather 441,578 IDs, a **97.44% reduction in logical address traffic**. The estimate counts only the metadata gather. The GPU already computes attention over its local window. V68's matched private check reached 17,512.9 tokens/s/GPU at 16 users. V188 has no physical H200 measurements. ## Page ownership and attention order

The released DFlash2 model has five bidirectional sliding layers with window width 2,048 and eight query tokens per request. Let P be the committed prefix length before the draft call. The earliest new query sees the inclusive interval starting at max(0,P−2,047). The program drops exactly 128 × floor(max(0,P−2,047)/128) leading table entries, so each retained table row holds at most 2,182 live addresses. It gathers each address from the current request's existing mapping at its original logical index. The physically stored K/V tensors and packed query buffer are the same objects used by the ordinary worker. [Released checkpoint configuration](https://huggingface.co/RadixArk/Muse-Spark-Open-DFlash2/blob/46c90f412549c472941a68382d91a99e5e6372a0/config.json) · [Production methods](delta.diff)

The 128-row origin matches the SM90 FA4 key tile for 128-wide Q/K/V heads. Translating both the local key index and the bottom-right query boundary by the same multiple preserves masks, per-split physical tiles and their order. The pinned wrapper takes its maximum sequence bound from the physical pool, so the native split count stays the same. Only the metadata launch contracts. Fully occupied 131,088-column request maps yield 513 address blocks per request at 256 columns per block. V188 issues nine. The original graph buffers retain their full backing and aliases, allowing native paths on the same backend. [CuTe geometry replay](independent_geometry.json)

The startup guard inspects the actual loaded draft model and its Radix layers, Hopper/FA4, BF16 cache, ordinary page-one pool and TP layout. The new path applies to fixed-width draft verification in the full CUDA graph. Ordinary eager execution, target attention, mixed or ragged rows, explicit compact draft pools, translated addresses, nonmatching attention geometry and deterministic execution retain the pinned behavior.
