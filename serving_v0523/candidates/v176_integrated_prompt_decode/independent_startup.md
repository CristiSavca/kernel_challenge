# Cold-start namespace and Humming API review

Pyflakes 3.4.0 found no new unbound names or locals across the 25 Python modules changed by the frozen V176 tree. All 58 distinct newly imported SGLang or Humming names resolved against the selected SGLang commit plus patch and the published Humming 0.1.12 wheel. The same checker detected the missing `is_cuda` binding that caused the V88 graph-capture crash. Three new diagnostic strings from Pyflakes belong to runtime CLI help metadata on the new options. All three option types and defaults resolved through the native msgspec constructors. [Source audit](independent_startup.json)

A fresh Python process imported the complete SGLang configuration, environment, runtime context, DFLASH projection, expert tile planner and Humming adapter modules. It bound 11 source call sites to eight actual Humming APIs. Five calls to the production Humming preparation function completed on small BF16/NVFP4-shaped host fixtures. They covered the base path, all eligible optional modules, failure to compile both narrower Humming widths, failure of the TMA module alone, and loss of all optional JIT modules. Schema construction, expert metadata, weight-scale permutation, selection of real H200 default tunings, replacement of checkpoint parameters and registration of prepared maps all executed. The eligible fixture requested widths 176, 136 and 152 for both banks. [Startup cases and defaults](independent_startup_runtime.json)

This test used CPU PyTorch 2.5.1, published Humming 0.1.12 and msgspec 0.22.0. Driver and compiler calls, device-memory repacking, the Triton decorator and SGLang package-level convenience imports used test substitutes. The CPU FP8 gather ran the actual permutation over byte views. The resulting evidence covers Python startup contracts and recoverable optional-module failure. The complete Linux server process, GPU capture and hardware startup time remain untested.

For reproduction, use Python 3.12 with CPU Torch, NumPy, Jinja2 and msgspec, and a checkout with the frozen tree object. Fetch and checksum the Pyflakes and Humming distributions named in the source receipt, placing them in a temporary directory as `pyflakes.whl` and `humming-kernels.whl`. Extract the vendor Python package into `packages/humming`. Run `independent_startup.py STAGE WHEEL_DIR` followed by `independent_startup_runtime.py STAGE WHEEL_DIR/packages`.
