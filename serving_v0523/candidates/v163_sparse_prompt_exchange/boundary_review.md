# V163 prompt expert capture and replay

The model can reach V163 on sequence-parallel target prompt extension. Muse enables replicated expert input for Humming, applies the existing pre-expert normalization, and calls the replicated-expert method only in its sequence-parallel branch. The positive path needs CUDA, multiple tensor-parallel ranks, the explicit flag, and enough routes for grouped Humming. The published top-k of eight and 256 experts put the threshold at **8,192 token rows**. The pinned `runs_sp` requires `ForwardMode.EXTEND`. Ordinary speculative verification follows the existing path. We exercised 288 combinations of backend, flag, GPU, TP, row threshold, compilation and capture mode through the model method. Four reached the new boundary, covering eager and breakable capture at 8,192 and 16,384 rows. [Fixture](boundary_check.py) · [Recorded run](boundary_check.json)

In breakable capture, the preceding segment gathers the fixed-shape score and ID buffers. V163’s outer eager boundary zeros its preallocated output during capture. Replay runs the native callback between two segments. It reads fresh routing tensors and the shape of the gathered ID tensor. The shape is the active graph bucket, which can exceed the scheduler’s raw token count. The native prefill runner pads its static inputs, replays the layer body, and trims physical outputs to logical rows. V163 processes the bucket just as the dense path does. The callback uses its captured ID shape for the dense fallback gather, so no captured Python replay-time token-count update is required. The existing `reduce_scatter_token_rows` consumes the fixed output after the eager boundary. [Capture and replay simulation](boundary_check.py) · [Pinned prefill runner](../../sglang/python/sglang/srt/model_executor/runner/prefill_cuda_graph_runner.py)

A hook installed after capture votes the transport back to the dense path. Capture finishes by resetting `_current_capture_var`, and `BreakableCUDAGraph.replay` sets only `_current_stream_var`. Consequently the nested native grouped expert’s eager wrapper executes immediately when `experts(...)` runs at replay. Native module pre-hooks and post-hooks can change IDs or outputs. All 96 such replays ran one registered graph break apiece and matched the expected modified output bitwise. [Pinned breakable graph implementation](../../sglang/python/sglang/srt/model_executor/runner_backend_utils/breakable_cuda_graph/breakable_cuda_graph.py) · [Replay receipt](boundary_check.json)

Across 288 changing-route replays and 110,736 bucket rows, the production grouped sort, per-expert scale calls, compact row map, segmented GEMM setup and finalizer launch arguments matched an independently computed per-original-slot BF16 reference. The test includes two remapped expert banks, duplicate routes, dropped routes, ragged tails, eight empty local banks and both normalization weight orders. It checked 48 sparse route counts and 280 nonempty slot maps. The small count used to replace the host read of `offsets[0]` includes duplicate local slots as required. The sparse input row map indexes compact received inputs only. The finalizer keeps original token/top-k positions for scores and output writes. [Exact source hashes and counts](boundary_check.json)

The fixture uses CPU Torch 2.5.1 and the production graph enter, exit, eager wrapper and replay methods. Humming matrix products, the final Triton device launch, physical CUDA graph segments and NCCL payload transport are represented by CPU operations. Hardware capture, H200 precision, memory peak and end-to-end throughput remain unmeasured. No change to serving code or official quota was made by this review.
