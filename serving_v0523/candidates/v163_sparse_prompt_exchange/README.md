# V163 sends prompt activations to the ranks that need them

V163 changes the communication step ahead of V64's grouped Humming prompt experts. Each rank advertises which live token rows its experts actually use. A source sends a normalized BF16 row once per requesting rank, even when several selected experts on that rank need it. Gate/up and down projections retain their original inputs, sorted route order, scales and output slots. The ordinary expert finalizer and token reduction produce the result. This is an opt-in change on measured V64 with its four flags plus `--muse-sparse-prompt-exchange`. [Official 53,638-byte patch](patch.diff) · [Flags, hashes and source checks](validation.json)

For an ordinary 16,384-row prompt chunk and 4,096 BF16 features, V64's dense gather sends 112 MiB of remote activation payload per rank. With eight distinct experts selected uniformly from 256, V163's expected payload is 74.1 MiB. At an assumed effective 300 GB/s for both transfers, the 37.9 MiB saving buys about 132 µs per eligible layer for the added packing, synchronization and collective launches. Actual routing and communication bandwidth during serving are unmeasured. In the older V41 hardware trace, 17 of 54 one-user prompt passes met V64's size threshold, covering 268,481 of 303,536 live prompt rows. At four, 16 and 32 users, 35, 75 and 150 passes met the threshold. V41 did not run this sequence-parallel exchange. [Trace and payload model](geometry.json) · [Reproduction](geometry.py)

The SGLang graph keeps a fixed output buffer and recomputes ownership on every eligible replay. Ranks gather small ownership masks and obtain the split counts and native grouped local-route count together. The transport splits destinations into groups so that the compact receive tensor and reusable activation send buffer together fit in the space of the original dense activation gather. The masks, indices, collective temporaries and graph allocator still contribute to peak device memory. Each rank enters the same variable-size exchanges in the same order. A rank with a hook or compiled expert override makes the entire group use the dense path. A uniformly broad fanout or a receive buffer too large for sparse staging also selects dense. At 16,384 rows, 64 synthetic uniform-route trials selected two exchange calls 36 times and four calls 28 times. Packing, the extra mask exchange and repeated calls can outweigh the payload reduction. The distributed CPU fixture passed 672 rank-cases on two, four and eight real Gloo processes, comparing 379,008 BF16 values. A separate replay exercised the native grouped host calls, original finalizer interface and both late dense and sparse branches. All 288 graph replays matched the expected BF16 output over 110,736 rows. The tests include duplicate assignments, dropped slots, remapped expert ownership, ragged padding, empty receives, a changing live route map and hooks installed after capture. Physical H200 payload, kernel and NCCL timing, CUDA graph execution, numerical agreement, TTFT and peak memory remain open.
