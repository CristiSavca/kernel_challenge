# V157 whole-cohort mixed target admission

V157 adds one explicit decision point on V147 for a worker that already holds the ordinary prompt, ordinary linear DFLASH target verify, and combined causal EXTEND inputs. The combined group contains all running requests under consideration. The four V147 serving flags and existing scheduling paths are preserved. A normal V147 launch does not call this helper. A scheduler that materializes the inputs, reaches the same decision point on all ranks, and settles accepted results is required before a timing comparison. [Patch manifest](validation.json) · [Single-file delta](delta.diff)

The worker calls `plan_mixed_dflash_target(model_runner, prompt, verify, mixed, tail_reqs)` on each tensor-parallel rank and then calls `agree_mixed_dflash_target(local_plan)` on **every** rank, including ranks that declined locally. A unanimous plan contains the padded row counts for the existing prompt, existing verification and proposed combined target. Any decline or disagreement retains the separated execution. The agreement uses six host integers and one Gloo all-reduce. Its per-opportunity latency needs hardware measurement.

The preflight asks the installed prefill and verification runners on all three prepared views and checks their actual captured backend keys. Prefill capture sizes are token rows. Uniform DFLASH verification capture sizes count requests, so the separate body cost is the rounded request count times the native width. Attention/LoRA graph variants and missing keys can change the verdict. Eager-only, ragged, incompatible topologies, tree masks, retired requests, reordered IDs, malformed extents, and inadequate native reservations decline. The preflight requires the CPU request-pool page indices to agree with the ordered cohort and takes no allocator action. The page-one double-width bound covers the allowed one-iteration host length lag. The native preparation still owns physical write-slot provenance, full and SWA translation, the stream ordering of prior publication, and eviction. The policy does not check device slot contents or create a new reservation. [CPU and distributed checks](cpu_result.json)

At 4, 16 and 32 users, the archived V41 eight-H200 admissions provided 112, 238 and 347 mixed opportunities. Replaying its actual prefill and verify grid keys admitted 66, 99 and 55 whole cohorts containing 164, 1,305 and 1,150 running requests. The resulting static target-body row count falls by 1,312, 7,120 and 7,072 across those historical schedules under the assumption that each separated cohort would otherwise run one native-width verify. A one-user mixed opportunity never occurred. Four useful tokens per paired tail would place 3.01%, 11.59% and 4.87% of the observed output at 4/16/32 users. Prompt SP was disabled in the archived V41 run and enabled for V147. Paying back target row count does not account for new attention, routing, logits, draft work, copies, synchronization, or the effect of changed admission order.
