# Request-local draft policy state

The choosing TP rank keeps one signed 32-bit score per live request. The DFLASH worker emits a fresh score vector after acceptance. A neutral score selects the original tree. No token IDs, prompt hashes or output history enter the relay.

In overlap mode, the scheduler stashes the score with the corresponding bonus token after the worker returns on the forward stream. The early sequence-length publication does not publish policy state. At the next forward, the scheduler gathers both by the filtered or merged request-pool indices. The stash copies the vector before captured or temporary storage can be reused. A fresh prefill, disaggregation admission or ineligible decode writes zero if the rank has ever initialized the buffer. The initial buffer is zero-filled. An idle dispatch writes no slots. Ranks that never emit a score allocate no policy buffer. In synchronous scheduling the DFLASH input carries the score directly, reindexes it under filtering, and fills missing rows with zeros on merge. No device-to-host synchronization or collective was added to these methods.

The verifier continues to broadcast one selected, full-width tree from its original authority. The adaptive kernels consume only the real batch prefix after the captured tree's `first_rows(bs)`. Its four dense planes are contiguous even when the captured graph pads the batch. Rejected and padded proposals contribute no policy state directly. The unchanged tree backend guard excludes PP and unsupported cache layouts. End-to-end overlap and graph replay still require CUDA execution. 

The [CPU fixture](lifecycle_cpu.py) executed the production filter, merge, create, publish, stash and gather methods using PyTorch 2.5.1 and a CPU stand-in for the event recorder. It compared 64 direct merges and 64 direct filters and ran 160 changing overlap batches with shuffled, reused slots. The fixture poisons the producer's source buffer after every stash; it checks both score and bonus ordering. It also checks idle input, rank-local allocation and a formerly occupied slot entering through disaggregation. [Receipt](lifecycle_cpu.json)
