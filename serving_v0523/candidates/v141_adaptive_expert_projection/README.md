# V141 adaptive expert projections for target verification

V141 changes the medium-density expert path that V139 still sends to indexed Humming. Its principal opportunity is the work spent on padded expert rows. At 256 verification rows, Humming's actual H200 tuning selects a 24-row tile. Under uniform distinct top-eight routing, the two V141 projections cover about 361 and 362 MMA row slots per rank, versus about 768 aligned vendor rows each. Packed-weight traffic is comparable under that distribution. The official 95,064-byte export is `dacec92848e669b47532fb53738c869f89efdfdf538a5a12415a20b98c3532a4`. Physical serving throughput, gate agreement, TTFT and memory await H200 measurement. [Manifest](validation.json) · [Official patch](patch.diff) · [V139 parent](../v139_integrated_experts_verify/README.md)

The route planner assigns one warp to each local expert. It compacts actual local route slots in original order and publishes their count. One projection CTA then owns an expert and 128 output channels. Each warp loads and decodes a resident packed NVFP4 fragment once and shares it across one, two or four eight-row tensor-core fragments. Each output uses a single ascending full-K reduction. W13 handles 8 or 16 rows at a time, applies the original BF16 rounding and scale, then runs SiLU. W2 handles 8, 16 or 32 rows and stores the scaled BF16 output at the original route slot. The parent finalizer then runs normally.

The dispatcher admits more route slots than global experts, up to the smaller of eight times the global expert count and 2048. The host applies V129's prepared-bank, architecture and input-layout guards. The original expert opt-out disables both native projections; the additional `SGLANG_ENABLE_MUSE_SPARK_MEDIUM_ROUTE_PAIR=0` affects only the medium-density implementation. Either JIT can fail independently. The four serving launch flags are inherited from V139 and scored V64. No host read of route data, additional collective or secondary weight bank is introduced. ## Indexed Humming comparison

The reference model executes Humming 0.1.12's actual SM90 indexed heuristic for W13 and W2. The 16- and 32-user geometries each use eight verification rows per request and eight routes per row. Random routing below means eight distinct experts selected uniformly from 256 per row. The last line uses the existing standalone H200 diagnostic's observed counts for one expert rank. These are work estimates. L2 caching, instruction issue, tensor-core efficiency and the distribution across the other seven ranks affect elapsed time. At 128 and 256 rows, the parent reserves 24 and 48 MiB for its activation and output arenas. V141 needs 16.125 and 32.250 MiB, including its preallocated per-expert slot table. Aggregate device memory also includes the serving runtime and graph pools. For the target H=I=4096 and 32 local experts, each projection launches 1,024 independent two-warp CTAs. A highly concentrated expert can occupy only its 32 channel bands at one time. The second weight sweep for a hot W13 expert can offset arithmetic savings.

## Checks

- The complete TVM FFI wrapper compiled for SM90 and SM90a with NVCC 12.9.86. W13 used 121 registers per thread and W2 used 118. Both have zero spill bytes and permit eight resident 64-thread CTAs per SM by register capacity. An initial 32-row W13 variant needed 204 registers and four CTAs. In W13's eight- and 16-row hot K loops, HMMA instructions rise from eight to 16 while packed BF16 multiplies stay at 64. W2's four, eight and 16 HMMA sites each require 32 packed multiplies. [Compiler receipt](sm90.json) · [Build recipe](compile_sm90.sh)
- The production projection bodies executed with a warp MMA emulator against an independent dense row-major oracle. All 64,384 BF16 activations and 77,056 BF16 outputs matched across six cases, including dimensions 4096×4096, tail rows, concentrated experts and negative IDs. The emulator preserved 64,384 inactive elements and all 25,088 input elements. Hardware rounding still needs comparison with the parent's WGMMA execution. The separate ownership test executed 850 planner fixtures, 765 stale-buffer replays and 73,754,240 individual output coordinates. Branches and shapes exercised the full release geometry. The official full export and three-file V139 delta reconstructed the same tree and reversed cleanly.
