# V184 re-verifying predictions from a rejected draft suffix

V68 committed **4.0 tokens per target pass** and delivered **17,512.9 tokens/s/GPU at 16 users**. Its target already calculates predictions for all eight input rows. V184 tested whether predictions beyond the first mismatch could replace another DFLASH forward. They can serve as guesses inside the current request's reserved block. Replacing the incorrect ancestor changes the causal inputs, so each retained guess still requires another target verification. Simulations matching V68’s acceptance put the throughput break-even well above what the existing measurement establishes. This is a feasibility result. [Official V68 result](../../runs/04b01f958aa5487c.json) · [Reproducible numerical results](check.json)

## What the second pass can certify

Let the first target pass read input tokens `x[0:8]` and produce greedy predictions `y[0:8]`. If the worker commits `c` tokens including its bonus, input rows `x[:c]` have valid target KV. The last emitted token, `y[c-1]`, has no KV yet. With `c < 8`, a second target pass can overwrite the existing physical suffix with proposed inputs `y[c-1:7]`. It uses exactly the preceding committed prefix and returns a fresh bonus at its own first mismatch. Across both passes the request can commit at most eight tokens. The last original prediction `y[7]` proposes a token at position eight; using it as a new target input requires a ninth writable row.

A simple counterexample explains why the remaining predictions cannot be committed directly. Take the same model output stream of all ones and a draft that turns to zeros after the first `c` input rows. A target that predicts one at every position repairs the whole remainder. A target that copies its last input agrees on the entire correct output stream, but its stale predictions are zeros. It repairs precisely one more token. Both behave this way for each possible initial mismatch depth. Mean acceptance gives no estimate of the probability that an off-path prediction survives correction. [Native DFLASH acceptance, commit and counterexamples](check.py)

The two-pass construction holds its intermediate guesses inside one model operation. It creates no lookup over request tokens and persists no rejected output. The pinned NGRAM worker maintains a reusable corpus of prompt and output tokens, which conflicts with the project instructions. V79 changes draft width beyond training and V118 already studies additional verified alternatives within the original seven learned prediction positions. V131 partitions one unchanged proposal and V166 chooses a single Bellman-optimal path under the current native draft probabilities. V184 explicitly examines a new, conditional target pass based on causal predictions from the first pass. ## Break-even at the measured loads

Let A be the average commitments in the original round, G the average additional commitments per request and P the probability of issuing a second batch pass. At the same starting anchors, if that pass takes fraction r of the original round time, the throughput ratio is `(1 + G/A) / (1 + P*r)`. Every retry adds at most seven tokens per request, so `G ≤ 7P`. The reservation also implies `G ≤ 8−A`. At A=4, even perfectly choosing which batches to repair permits at most 2× advancement with a free retry and 1.40× if each retry costs at least 75% of a native round. Those are favorable ceilings, conditional on the stated pass cost and unchanged original work.

For the following sensitivity, independent native draft matches reproduce the observed acceptance at each load. The extra guess has the indicated conditional probability of surviving a corrected ancestor, and each nonempty retry has a fixed cost. Native request-to-request dependence, actual retry cost, off-path agreement and scheduler TTFT effects are unknown.

In this model a retry costs 75% at 16 users and yields 0.904× throughput with 75% repaired-suffix agreement, or 1.027× with 90% agreement. V64’s four measured acceptance means give a geometric-mean advancement ceiling of 1.976× if all token reservoirs are filled for free. Multiplying that ratio by V64’s 1.4119 produces 2.79× in a fixed-time illustration. The official score includes fixed-interactivity interpolation, client TTFT and a possibly different sequence of starting anchors. ## Runtime evidence and decision

The CPU fixture executed the pinned native acceptance and commit functions on 65,536 causal cases and observed all 29 possible initial/combined length pairs. A second fixture ran a two-layer causal attention target with BF16-rounded intermediates, full-vocabulary greedy output and fragmented physical KV. For 256 requests, warm prefixes through 129 tokens and every mismatch depth, 1,411 committed rows and 67,728 committed KV scalar values matched independent serial decoding. The repair overwrote only its allocated suffix. Original off-path taps differed in 21,457 scalar positions across these trials. The synthetic fixtures establish the construction and indexing; they supply no evidence about actual Muse off-path agreement. [Attention replay](attention_check.py) · [Numerical results](attention.json)

V68’s native graph constructs its query boundaries and KV workspace using one fixed `draft_token_num`, and its normal worker publishes the committed lengths immediately before materializing draft KV. The auxiliary hidden buffer belongs to the graph and is overwritten by the next target forward. A deployed retry would need to preserve or immediately consume the first pass’s committed taps, mask and rewrite each corrected physical suffix, and publish once after both passes. A full-width replay at an advanced starting position would write past the current reservation. Per-request `c` also varies on device. At 16 users the modeled probability that at least one request needs another pass exceeds 99.99999999%. This makes an additional target weight traversal important even when each request has only a few unfinished rows. Sampling, grammars, token budgets, stop conditions and request cleanup still require their ordinary semantics.

There is no submission patch. The first physical comparison with stronger support is the V182 fused Q/K producer on V180’s H200-passing V68 lineage. It can remove up to 248 launches in the existing target pass without relying on off-path agreement. Its hardware timing remains open. To reconsider V184, the deciding measurements are paired extra commits and actual duration of a correctly sized second target verification, plus added peak memory on the same device. The built-in accepted-depth histogram can constrain how often a second pass is available; it cannot measure agreement after changing the ancestor.
