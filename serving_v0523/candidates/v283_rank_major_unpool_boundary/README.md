# V283 consumes the unpooler gather directly

V283 extends V229’s column-sharded decode projection. The NCCL all-gather already produces the unpooler result in rank order. The new FFN boundary reads each 16-byte BF16 vector from that layout, performs the original post-normalization, gated residual add and next-layer pre-normalization, and returns the normal row-major outputs. It introduces no new launch flag or collective. [Official-format patch](patch.diff) · [Four-file change from V229](delta.diff)

These counts assume the archived eight-position decode geometry, eligible Hopper JIT boundaries and the existing multicast path at eight rows. Only the first 61 of the model’s 62 sparse layers bind the next layer’s input norm. The real GroupCoordinator reshape on a host receive buffer confirmed that the original result allocates new storage and the new view aliases the receive buffer at all tested loads. The collective still transmits the same bytes on the same group. Cache residency, extra address arithmetic, capture-pool reuse and NCCL scheduling determine the device effect. [Shape and storage replay](work.json)

The accelerated path inherits V229’s group-wide capture admission, including the FP4 target model, Hopper, replicated inputs, single expert-TP rank, full CUDA graphs and lack of hooks. A subclass or instance override of the MoE transport helpers makes all ranks use the ordinary path. The replay also called both helpers using their original signatures. Code selects the shorter path only when a BF16 decoder can use the native JIT FFN boundary with a contiguous FP32 stream. The single-CTA kernel uses the original vector width, lane order, arithmetic and outputs. Terminal layers, native multicast and dense projections retain their existing entry points. A rank-major module build failure restores row order locally and reuses the ordinary JIT. The wrapper also preserves the native multi-CTA cluster selection when called directly. ## Verification

- The four- and eight-rank Gloo replay ran 23 scenarios per group and compared 119,832,576 BF16 words, including all 65,536 bit patterns. It exercised the actual decoder, unpooler, communicator layout and JIT selection with modeled GEMM and norm payloads. A missing decoder return initially caused double normalization. Both the failure reproduction and the final passing boundary controls used the real decoder method. [Distributed replay](independent_gloo.json)
- A second host test executed the actual C++ branch addressing on 103,612,416 lanes. Full-width CPU BF16 GEMMs matched 10,420,224 outputs. A host compilation of the old and new norm bodies matched 5,160,960 FP32/BF16 words in 72 cases, including scalar/channel gates and the launch change at 192 rows. Deliberately shifting shard ownership altered 97,803 words. The host models CUDA primitives and cannot establish H200 agreement. [Load and GEMM evidence](independent_layout.json) · [Normalization differential](independent_norm.json)
- CUDA 12.9 compiled the production TVM wrappers into eight SM90a translation units, totaling 128 kernel instances. All had zero stack and spill bytes. The 32 ordinary row-major device code bodies matched the parent byte for byte. The 64 TP4/8 code bodies matched the parent’s input-dependent floating-point and shuffle opcode counts. Ranked addressing adds 56–112 static instruction sites in a 256-thread variant and 16–32 in a 512-thread variant. A separate unsigned address form reduced sites for the former geometry and added sites for the latter. These counts do not predict kernel duration. [Machine comparison](sm90a.json) · [Address variant](address_trial.json)
- The 350,239-byte patch reconstructs on the public pin and reverses to its original tree. Its four-file delta also applies and reverses on V229. All six inherited flags passed all 720 argument orders, and the full patch passed the published source, size and flag restrictions.
