# V165 streamed low-density routed projections

V165 lets spare resident Hopper thread blocks work on separate routed experts. V164 sized the output grid using the expected local route count. In an expert-parallel run, a single rank with more local work than that estimate can take a second full projection sweep while peers wait. At startup V165 asks CUDA how many blocks of each compiled kernel can reside on the device. When the existing grid occupies less than that capacity, the new entry schedules additional independent expert tiles within the existing shape-safe route-plan bound. Both projections retain every live route and accumulate each output channel over the full input width in the original order. [Three-file change](delta.diff) · [Official export and five inherited flags](validation.json)

One producer warp issues tensor copies for the original bank and one contiguous 256-byte activation copy per live row per 128 input features. Eight consumer warps compute while the producer fills the next shared tile. Gate/up has two buffers and down has three. Each buffer has a completion barrier for its copies and a release barrier for the eight consumer warps. Only eight additional bytes of CPU metadata per sparse layer are needed for the resident capacities. Bank address changes, failed preparation, unsupported alignment and higher-density workloads retain their earlier handling. Medium verification and prefill are unchanged by this delta. NVCC 12.9.86 compiled both production TVM-FFI wrappers for SM90 and SM90a with zero spills. The new loop still waits on shared-memory barriers and has a separate producer instruction stream. The inherited tensor fallback has identical SM90a instructions and machine words. In the vector fallback the compiler reordered register zeroing and assigned different registers to an address calculation. All arithmetic instructions and their ordering were preserved. [Compiler receipt](sm90.json) · [Disassembly](sm90a.sass.gz)

In 32,768 seeded synthetic eight-row batches with uniform distinct top-8 routing across eight ranks, a four-block-per-SM occupancy assumption gives 8 → 16 route groups at 4,096 output channels. Any rank needed a grid-stride repeat in 98.03% → 0.0366% of batches. This doubles launched CTAs per rank from 256 to 512 with about 230 live jobs on average. Four blocks per SM and independent uniform routing are assumptions. The actual branch uses the queried occupancy, and at two resident blocks per SM on a 132-SM device it keeps the parent path. Both implementations still have roughly 193.8 MiB of cold packed bank traffic per rank per layer under this routing model. Physical route skew, empty-CTA issue, cache bandwidth and contention can change the outcome. V165 has no H200 timing or serving score. [Work model and results](work_model.json) · [Cold-read estimate](../v161_tma_expert_channels/README.md)

The production kernel loops ran under a CPU warp and async-copy interpreter on six geometries including 4,096 × 4,096. Three completion schedules produced the same 181,248 BF16 activation and 137,856 BF16 output values as the reference across the repeated cases, preserved 194,304 inactive cells, and exercised six accumulation-sensitive cancellation witnesses. The copy engine transferred 102,081,024 bytes and deliberately delayed 468,049 warps. A separate review tested 32,256 native launch geometries, 240 asynchronous schedules and all 512 projection/live-mask combinations. The official full patch and its smaller V164 delta reconstruct and reverse cleanly under strict whitespace checking.
