# V91 parallel target selection and one TP decision

V91 changes the greedy decision after the target model verifies the draft proposals. It keeps the complete target LM-head GEMM, its FP32 output and logit scale, and evaluates the original FP32 divide, `libdevice.tanh` and multiply for every valid vocabulary ID. The 202,048-token vocabulary gives 25,256 columns per TP8 shard. Where the old row kernel loops over seven 4,096-column tiles, V91 schedules those seven blocks concurrently. Each produces its highest score and earliest token using the original 4,096-wide, eight-warp reduction.

The new reduction packs the exact FP32 ordering bits and inverse vocabulary ID in one signed 64-bit integer. It canonicalizes signed zero for comparisons, preserves the row kernel's handling of NaN and negative-infinity tiles, and uses the smallest vocabulary ID when scores tie, including softcap saturation. Each rank sends one 64-bit local winner per target row to a single NCCL MAX all-reduce. Every participating rank receives the same ID. This replaces the local-winner all-gather, across-rank argmax and ID gather, plus the duplicate default decision broadcast. It applies to linear and tree acceptance under the same NCCL tensor-parallel group.

The switch defaults to off. The worker only selects it for a deferred FP32 target shard and an unadjusted greedy request that already qualifies for sharded decision-making. Sampling, grammar, logprobs, penalties and incompatible groups retain their existing paths. The Muse Spark logits processor uses FP32 target-head output, so the change can run on the official configuration. The draft head, target GEMM, attention, expert execution and acceptance logic match V89. [Independent source and compiler review](independent_review.md).

## Comparison

Use V89’s nine launch flags and add `--flag speculative-dflash-reduced-target-argmax`. The [validation receipt](validation.json) lists all ten. A matched four-user check would exercise low-row selection with additional GPU work available per row. Its benefit depends on the target-selection share of iteration time. Stock V64's 1.4119× is still the measured four-load result. V91 has no measured speedup.

CPU execution compared the candidate kernel bodies to the original across 432 rows. Tests include empty and partial rank tails, ties, signed zeros, infinities, saturation and NaNs. The host wrapper also ran across two real Gloo processes and matched the original all-gather decision on 64 rank-row cases. The compiler comparison matched the old and new reduction ordering under three pointer and width alignments and both scalar cap signatures. H200 NCCL, throughput, peak memory, output lengths, first/later-turn agreement and TTFT still require an official run.
