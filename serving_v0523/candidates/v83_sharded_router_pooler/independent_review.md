# V83 independent source and transport review

Final SHA-256 `bae9bc7a0a26ea3aadbbef8c80cd5049e8dd078673a3986d4407e110050a9dc4` passed exact V80/delta parity, Python compilation and reverse application. Three sections change from V80. The final export has 157,318 bytes and covers 29 permitted paths.

I identified a collective-order problem during review of the first version. Rank-local router hook state could have selected incompatible collectives on different GPUs. The final patch makes transport selection depend on the shared Hopper/Humming configuration and projection geometry. Every participating rank enters one ordinary rank-major gather. A rank requiring hook-aware or autocast router behavior can compute its own complete result on the side stream. It contributes unmodified FP32 shard words to the collective and uses its local override for routing. An independent exercise of 160 rank, shape, precision-branch and hook configurations reproduced local effects with hooks on zero, one, some or all ranks.

The incumbent constructor creates an FP32 router. On Hopper the small-M branch uses the full-K FP32 linear operation. The large-M branch uses the incumbent transposed high/low BF16 representations and adds their FP32 GEMM outputs in the established order. Column slicing retains every input feature. GEMM shape changes can alter floating-point summation behavior and expert ranking near ties.

The group coordinator concatenates dim-zero input tensors in group-rank order. The pooler multicast communicator uses the same process group's rank for its local weight slice. Both old and new pooler paths map each positive BF16 zero to signed negative zero. The new router side transports raw FP32 words. I independently exercised the production Triton unpack body on 120 layouts and 27,043,652 words across TP2/4/8, real payload widths, non-multiple tile tails, NaNs and both zero signs. All observed pooler and logit bits matched the reference rank concatenation. No random values or host request data are consulted by packing or sharding.

The side stream waits for the owner of the input and publishes its partial result through a main-stream wait before packing. Temporary router outputs needed on the main stream receive allocator stream records outside capture. Main-stream routing completes before local experts consume the gathered inputs. The new transport substitutes an ordinary gather, packing and unpacking for a specialized multicast gather. Low-M communication and the wait for both GEMMs can erase any reduction in replicated router computation. GPU replay, numerical agreement, peak memory and all-load throughput remain open.
