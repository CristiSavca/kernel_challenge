# Independent rank-major dispatch review

The registered DFlash2 checkpoint has five decoder layers. Each owns an attention and an MLP filter, each projecting the full 8,192-wide draft hidden state into 2,048 BF16 coefficients. The inference config has two taps, 512 groups, sixteen hidden channels per group and eight speculative input positions. `DFlash2DraftModel` inherits the native unquantized grouped convolution and single-group draft TP placement. V123's inherited filter option constructs the output-sharded `DFlashGatheredLinear` on CUDA. On TP8 each rank loads its own 256 complete rows of the checkpoint weight, derives the same input-token count as its peers, and calls one gather per filter. The registered loader and group are bound at construction. [Checkpoint header and constructor audit](../v78_dflash_sharded_conv_filters/independent_review.md)

For side `s`, tap `t` and coefficient group `g`, the global output channel is `(2*s+t)*512+g`. Its TP owner is `2*(2*s+t)+g//256` and offset within that owner is `g%256`. The candidate reads those entries from the physical device result `[8, rows, 256]`. Both `permute` and the precisely aligned channel slices are storage views. It keeps both original sublayer invocations and the two-tap accumulation. Captured padding still has the same block boundaries as the parent. The original group gathers rank-major before moving its rank axis next to the channel axis. That moved view requires a contiguous copy for `rows>1`; it can alias for a single row. The independent fixture executed the pinned GroupCoordinator under c10d, PyNCCL, symmetric-memory PyNCCL and PyMSCCL++ transport doubles, using real CPU tensors. Every comparison used the same send and receive shape and dtype; only the returned local layout changed. The CUDA custom-op dispatch keeps the same opaque group-name call. The graph-lifetime guarantee and timings of real H200 transports still require device validation. [Transport fixture](independent_transport.py) · [Transport results](independent_transport.json)

At eight drafted positions per request, the ten calls gather 0.3125, 1.25, 5 and 10 MiB per GPU for 1, 4, 16 and 32 requests. Omitting the local reorder saves one read and one write of each gathered result. Both physical network payload and gather count stay the same. A competing backend on NVIDIA receives the same destination shape `[8*rows,256]` and the same local `[rows,256]` before any dimension rearrangement. Rank-local forward hooks, overrides or grad mode may select different local representations without changing this wire contract. A custom hook that independently changes the input row count or skips the collective would violate the parent projection's TP contract as well. Empty decoder layers return before the filter. Gloo is used by the CPU harness and does not carry the scored CUDA coefficients. [Real two-, four- and eight-rank collective tests](gloo.json)

The ordinary scheduler suppresses gradients via `DynamicGradMode`, and graph initialization runs under `torch.no_grad`. The scored V64 server folded the draft selector into its CUDA graph, so the normal captured draft can choose rank-major at capture. The guard is evaluated at eager entry or while recording a graph, not as a host synchronization on each graph replay. At each eager draft call it reads Torch grad state, four hook maps and two module override fields for each active filter. The new inner convolution uses Inductor; its CPU code-generation receipt found one output allocation and no coefficient reorder. H200 code generation could have a different memory-access cost.

A separate whole-module Dynamo trace revealed a compatibility regression in this frozen export. `vars(projection)` fails fullgraph tracing on PyTorch 2.5.1. Replacing it with `projection.__dict__` traced but reused the clean branch after an instance override. The V123b correction preserves the parent channel-major path when an outer model is being compiled. [Fullgraph reproduction](independent_compile.json)
