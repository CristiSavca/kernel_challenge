# Independent review of V94

Reviewed the frozen export `242e038af77f04804623b4dc6fcbbed114a104dbc0554294c2750aed4ea558f2` and CUDA source `eb1dff23cec8afd1e3bc95388e01f464df53531042c47dea8bc551f37ee03c2f`. V94 shares a gate/up activation across the W2 output bands in one thread-block cluster. W2 arithmetic and output ownership carry over from V90. [V90 review](../v90_activated_expert_down/independent_review.md)

Cluster dimensions are (C,1,1) with C dividing the number of 512-column output bands. Every peer uses the same Y coordinate to resolve the same immutable expert tile. Peers therefore select the same row fragment count and enter the same barriers, including the empty tile branch. The first cluster synchronization makes all peer blocks available before their first mapped store. One barrier separates publication from local MMA reads and another separates the last reads from buffer reuse or block exit. The CUDA launch wrapper passes the cluster dimensions to the extended launch API on the existing TVM CUDA stream. CUDA 12.9 supports the cluster launch attribute on graph nodes. [Distributed shared memory](https://docs.nvidia.com/cuda/archive/12.9.1/cuda-c-programming-guide/index.html#distributed-shared-memory) [Cluster launch attribute](https://docs.nvidia.com/cuda/archive/12.9.1/cuda-runtime-api/group__CUDART__TYPES.html)

A separate exhaustive coordinate check swept C = 2, 4, 8 and every tile size from 1 to 32. It covered 96 geometries, 67,584 four-element vectors and 315,392 peer-vector copies, including padded rows. Every vector had exactly one producer and one copy on each peer, on an 8-byte-aligned destination. All live inputs stay within their row. There are 11 small-tile geometries where fewer than C blocks do useful activation arithmetic. All participating blocks still enter the same cluster barriers.

The production PTX SHA-256 was `8abba59229657f72a6e207c359a0fadf10c70b8463ffeb9061df1cb9620e4f7f` and SM90 cubin SHA-256 was `90f86f2e13e9687e560eab839100dd826996e869f08b0d387a21e1f82d69cf0f`. For cluster widths 2, 4, and 8, every one of 14, 28, and 72 statically emitted mapped-address registers feeds its associated vector store. All three specializations retain nine cluster arrive and nine wait sites across the three selectable fragment paths. The one-block specialization emits block barriers and no mapped-address operations. [Compiler receipt](sm90_compile.log)

The occupancy queries run during model preparation. A legal launch only establishes that the cluster can reside on that device. At width 4,096, the eight-block path computes each SiLU once across the eight output bands, with seven peer copies per published vector and two cluster barriers for every 128 K elements. At K = 4,096 there are 65 dynamic cluster synchronizations including the initial one. Register pressure, occupancy, padded rows and remote-store latency can outweigh the avoided activation work. H200 throughput, graph replay and model agreement remain unmeasured. [CUDA occupancy API](https://docs.nvidia.com/cuda/archive/12.9.1/cuda-runtime-api/group__CUDART__OCCUPANCY.html)
