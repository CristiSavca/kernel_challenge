# V136 fuses verification Q/K normalization, rotation, FP8 conversion and cache writes

V64 normalizes and optionally rotates the local target Q/K projection in BF16, converts Q/K/V to the configured FP8, then scatters K and V. On eligible FA3 target verification, V136 extends the existing normalization kernel to produce the FP8 query and write physical K/V directly. An eligible layer replaces five launches with one. Across 62 layers that removes up to 248 launches per verification pass, including 62 beyond V110’s downstream cast/scatter fusion. The patch keeps V64’s four serving flags. At 1,024 query and 128 key elements per token per rank, removing the intermediate BF16 Q/K write and read saves 4,608 logical bytes per row relative to V110. Across 62 layers this is 2.18 MiB at eight rows, 8.72 MiB at 32, or 69.75 MiB at 256. The fused kernel adds an FP8 conversion-table load for each element and reads the current pool limit. The combined warp layout also schedules raw V rows alongside normalization rows. CUDA graphs already amortize launch overhead. These counts do not predict a score or establish a 3× gain.

The producer preserves the existing FP32 RMS reduction, intermediate BF16 rounding, optional interleaved RoPE and final BF16 rounding. A 64 KiB table generated on the backend device with the installed torch conversion maps every BF16 bit pattern to FP8. V uses the original projection bits. Full attention and SWA use their own physical slots. The release kernel traps invalid slot indices and skips the reserved zero slot. At startup each eligible pool owns a stable eight-byte bound. A VMM pool starts at its physically backed padding page and publishes its final serving capacity into the same operand only after backing succeeds. Distinct full and SWA capacities match the measured post-capture configuration. [Scored V64 log](../../runs/abd217baf0ed49fd.log)

The Triton interpreter compared 2,402,816 bytes in 28 configurations plus three invalid indices and three replays with a changing capacity. The production guard selected 36 eligible cases and retained the native path in 558 fallback cases. A second reviewer invoked the actual RadixAttention and FA3 wrappers across all 62 layers. Twenty-four release SM90 specializations assembled with the bounds trap present. The target 64-wide heads used 28–48 registers and zero spill bytes. The deliberately wide 256-dimensional RoPE case with 32 simultaneous rows spilled 612 bytes each way. No physical H200 execution, peak memory or response agreement has been measured.
