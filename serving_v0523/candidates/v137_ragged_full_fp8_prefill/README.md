# V137 full-attention packing for unequal prefix lengths

V137 makes dense Hopper FA3 available to a class of page-one prefill batches that V95 sends to paged attention. V95 allocates equally wide K/V rows for every request. V137 packs every live key and value in request order, with a private 256-row zero guard after each request. The new path runs when the rectangular allocation exceeds 32 MiB and the guarded live allocation fits within 32 MiB. With two total KV lengths of 74,160 and 8,192, the allocations are **36.21 MiB** and **20.23 MiB** per eligible layer. This synthetic example establishes reachability. The official receipt ends at the first request and does not give the frequency of such batches. [Source delta](delta.diff) · [Measured V64 parent](../../runs/abd217baf0ed49fd.json)

**The default V64 target prefill graph is Breakable on CUDA.** Its attention boundary runs eagerly on each replay and trims query and KV inputs to real rows. Ordinary FA3 refreshes its metadata from the current batch. V137 uses the same CPU length mirror as that metadata builder to bound a temporary allocation and the device cumulative K offsets to place the data. It checks that the real query count equals the physical query row count. Padding, static Full graph state, missing mirrors and oversized batches keep V95’s existing routes. A single-request long prompt was already eligible in V95. The physical KV pool and page allocator keep their existing representation. Each full causal FA3 call receives the original queries, logical K lengths, cumulative query lengths, softmax scaling, softcap, per-request K/V descales and output buffer. Only K/V layout and physical K offsets change. The new `seqused_k` is the same tensor previously passed as `cache_seqlens`. It excludes each request’s guard from the effective key count, preserving bottom-right causal alignment. The packer copies all stored FP8 bytes, including fragmented and repeated physical slots, and zeroes each guard in its own allocation. - The production Triton CPU interpreter matched **67,233,920 destination bytes** over 57 cases, including empty sequences, uneven per-request lengths, distinct K/V/table pitches, repeated slots, unaligned tails, zero guards, outer canaries and a 74,160-row prefix. All 14 Hopper row-width and index-dtype specializations compiled. [Interpreter](interpreter.json) · [SM90 binaries and assembler statistics](sm90.json)
- The complete V95 and V137 attention methods ran against 21 CPU fixtures. Four ragged batches took the new route and 17 retained the parent’s route. An independent dense causal reference matched **3,840 output scalars**, with GQA and separate K/V scaling. Padded queries, over-budget total keys, capture, missing mirrors and unsupported topologies exercised fallback. Physical H200 FA3 execution, numerical agreement, allocator peak, TTFT and throughput remain unmeasured.
