# Mixed target projection and settlement

V202’s mixed call produces one ordinary causal EXTEND with each prompt followed by all eight speculative rows per running request. The eager head consumes the last row of each prompt and every candidate row. Its fixed index tensor is carried from the live batch through the static body replay. The full and breakable trimmers retain prompt endpoints plus verification rows for logits. They retain all true token rows for draft context. On long eligible batches the token owner runs the draft FC and RMSNorm once. When many candidate rows exceed the head's gather threshold, the head gathers the entire final state and uses those same explicit indices. Both sides use the native target vocabulary projection and softcap. [Numerical replay](independent_mixed.py)

The dedicated worker creates a nested context with the paired draft-KV helper cleared. The target model skips the paired-KV function altogether on a mixed batch, avoiding its CPU rank vote. Settlement checks the context representation before sampling or length publication. Normalized features go directly into both native draft writers. Raw features are projected on their original paths. Only the accepted tail prefix is visible to the prefix-valid cache writer. The V198 single-request direct FP8 prompt path requires batch size one, while the V194 mixed constructor requires at least one prompt and one running request. Its segmented target-verify attention also requires TARGET_VERIFY. The mixed target runs as EXTEND. The two optional attention optimizations remain available in their ordinary single-role phases. [V198 validation](../v198_segmented_verify_prompt_experts/validation.json) · [V194 admission review](../v194_mixed_decode_chunk_budget/independent_review.md)

Forty-five CPU executions sampled unequal prompt lengths and two to 144 running requests across emulated TP2/4/8 and eager, full-body and breakable-body modes. Eighteen used normalized context. Nine of those gathered the selected head rows and nine used the dense head. Twenty-seven exercised a disabled context, incompatible RMSNorm or short inputs. The oracle recomputed a nonidentity 40→8 BF16 FC/RMSNorm, compared 295,668 vocabulary values and checked 5,702,400 physical K/V words, including 2,985 discarded tail positions. The expected and actual acceptance lengths covered one through eight. Eighteen additional cases injected precomputed KV or malformed normalized width, retaining both the cache and the unpublished lengths. A preexisting context and unavailable paired helper tested nesting/restoration. PyTorch CPU executed the actual worker, target wrapper, logits processor, index construction, trimmer, sampler, accept and cache routing. CUDA capture, the transformer body, peer transport and storage kernels were emulated. Elapsed H200 performance is still unmeasured.
