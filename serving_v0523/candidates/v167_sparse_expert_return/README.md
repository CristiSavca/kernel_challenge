# V167 returns sparse prompt expert results to the token owner

V167 extends V163 on the scored V64 lineage. For a long sequence-parallel prompt, each expert rank already knows exactly which token rows it needs. It now runs the grouped Humming projection and stock per-expert finalizer on just those rows, returns each BF16 partial to the token’s owner, and sums the received partials there in FP32. The ordinary dense reduction handles broad routing, hooks and unsupported experts. The same opt-in flag, `--muse-sparse-prompt-exchange`, enables both directions. The five launch flags and 57,638-byte patch are frozen. [Patch](patch.diff) · [Changes from V163](delta.diff) · [Manifest](validation.json)

The transfer estimate assumes eight distinct, uniformly selected experts out of 256 on eight ranks. V64’s serving report does not identify NCCL’s physical all-reduce algorithm or achieved bandwidth. A switch-assisted all-reduce can cost less than the ring estimate. Each group of incoming expert ranks requires one return collective and one accumulation kernel. The static V163 route model predicted two or four groups on the 16,384-row uniform trials. These extra launches, route metadata and synchronization can outweigh the traffic saved. The compact input, local expert IDs and scores remain in original token order. Removing rows with zero local routes preserves the stable sort of live expert slots. The grouped expert input is staged into its native projection workspace before its finalizer reuses the receive buffer for the outgoing BF16 partial. The owner receives one group at a time into a bounded buffer. Between groups it keeps a 32 MiB FP32 accumulator at the stated geometry and writes BF16 only after the final source rank. The graph callback allocates a fixed owner-sized output and recomputes its peer lists on each replay. Numerical agreement with the judge's incumbent reduction order, CUDA graph behavior and allocator peak require a real serving check. The normal model entry and native breakable-graph callbacks passed 448 distributed CPU replays on two, four and eight real Gloo processes. Those included 48 multi-group cases and 136 dense fallbacks. The reference independently computed every rank’s BF16 normalized expert result before summing on the owner. An additional transport test passed 532 rank cases. Triton compiled 16 reducer variants for SM90 without spills. Its interpreter matched 737,352 FP32 values, 737,352 representable BF16 values and 6,336 allocation guard values. V167 has no H200 timing or judge job.
