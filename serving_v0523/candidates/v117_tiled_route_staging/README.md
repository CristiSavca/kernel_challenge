# V117 tiled route staging for high-load decode

At 256 verification rows and eight routes per row, V116b has 256 thread blocks each load and map the same 2,048 expert IDs, then compute two histograms. V117 maps the IDs once in 16 tiles. This reduces mapped-ID evaluations from 524,288 to 2,048 and histogram input entries from 1,048,576 to 2,048 per layer and expert rank. The new per-token staging kernel has 712 static Hopper instruction sites, down from 944. The tradeoff is one additional small planner launch per eligible expert layer. End-to-end H200 speed remains unmeasured. [Official patch](patch.diff) · [One-file delta](delta.diff) · [Disassembly and compiler counts](sm90.json)

Each tile sorts local bucket and original slot together. This gives every local route a stable ordinal within its own expert and tile, including duplicate expert IDs within a token. The planner also writes each tile's cumulative expert counts, with remote entries in bucket zero and tile padding subtracted. For a route to expert E in tile T, the normalization block adds its tile-local ordinal to one count from each tile. Tiles before T contribute entries up to **and including** E. The current and later tiles contribute entries before E. The resulting row therefore follows all real remote slots, all smaller local experts, and all earlier slots selecting E. The per-token block still computes one FP32 RMS normalization from the full input vector and scatters the result to every live route. Empty ranks and remote slots follow the parent behavior. [Kernel fixture](kernel_check.py) · [Interpreter receipt](interpreter.json)

The new path is selected only for normalized grouped decode when the original skinny W13 path is inactive and the route tensor contains at least eight 128-slot tiles. Its side buffer occupies `4 × tiles × (local_experts + 1)` bytes. A rank with 32 local experts needs 1,056 B at 128 verification rows and 2,112 B at 256. It reuses the existing row map to hold tile-local ranks until each owning token overwrites its own entries. The current stream orders the planner and normalizer, which run at static capture shapes. Projection weights, expert GEMMs, global scaling, expert RMS and the weighted final reduction retain the V116b implementation. The extra 128-slot planner uses 30 registers, 512 B of shared memory and 384 instruction sites for the target shape. At 256 rows, even all-local routing calls for at most 32,768 tile-prefix reads in the normalizer, plus one 528-entry reduction to generate expert offsets. The old 8 KiB ID tensor can fit in cache. The operation count therefore describes metadata processing and shared-memory contention, and does not give a DRAM or throughput speedup. The previous H200 hardware-counter experiment measured 75.06% sustained DRAM throughput at M256 on a different standalone fused expert kernel. This change retains all packed-weight reads, which can still dominate service time.
