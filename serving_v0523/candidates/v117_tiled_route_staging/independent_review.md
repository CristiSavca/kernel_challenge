# Stable tiled route order

The published count for each tile and cutoff expert excludes its padded lanes. A later consumer sums all smaller experts across all tiles and counts the current expert on earlier tiles only. Adding the slot's stable ordinal on its own tile gives its exact destination in the original global expert-major stable sort. This holds for a token straddling two tiles because the kernel uses the slot index in the tile comparison. Distinct token blocks only overwrite their own per-slot temporary ordinal, and the final key for each live slot has a unique destination. An independent CPU enumeration verified 900 layouts and 693,360 examined slots, including all-remote, all-one-expert, tile-sized expert runs, arbitrary invalid maps and duplicate experts. [Independent test](independent_order.py) · [Result](independent_order.json)

At 16 and 32 users the prospective 128- and 256-row verify grids add one launch and a 1,056- or 2,112-byte tile count buffer. The old implementation loaded one full ID vector per token then performed two histograms on that vector. The new one performs 8 or 16 tile-level histogram/sorts and uses the per-token tile summaries. Those operation counts distinguish the crossover from a timing result. The skinny W13 path and the four-user run stay on the existing schedule.
