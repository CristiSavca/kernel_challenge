# V147 target expert projections and prefill attention

V147 combines V144's target expert projections with V146's zero-copy prefill attention on the measured V64 configuration. Sparse verification uses the pipelined NVFP4 gate/up and down projections. Medium-density verification uses V141's adaptive expert row tiles. Eager FP8 prefill can pass contiguous full-attention cache spans or the contiguous visible sliding-window suffix directly to FA3. Each path keeps its own eligibility and fallback. The 113,650-byte official patch has SHA-256 `7a3d4dc6c0e526b60ca50bc975a6036da7796d8eb05f9e8afb70423164425437`. Combined H200 serving speed, gate agreement, peak memory and TTFT await measurement. [Official patch](patch.diff) · [Four inherited launch flags](validation.json)

The V144 and V146 changes each applied cleanly on top of the other parent's exact delta from V64. Both orders reconstructed tree `cd089ab0b54e9fa2ee4c1cfdcb3f354370748d85`, and applying either delta in reverse restored the other parent. Only `flashattention_backend.py` received changes from both parents. The expert and verify kernels are byte-identical to V144, and the full/window prefill module is byte-identical to V146. Their separate offline Hopper compiler receipts therefore describe the same device sources in V147. The combined host fixture alternated ordinary prefill and target verification through the production MuseSpark attention forward method and the merged FA3 backend. With both cache-layout certificates present, ordinary prefill selected the full or sliding-window dense view. Target verification used its original page table. Each of eight calls performed exactly one cache write through either the fused verification route or the ordinary backend writer. The test compared 538,624 newly written FP8 cache bytes and checked each query's FP8 encoding. It used host stand-ins for the GPU arithmetic. A separate 62-layer test passed inaccessible stale certificates on target verification.
