# V166 DFLASH linear proposal selection

V166 chooses a linear draft path that maximizes the expected number of committed tokens under the current draft selector’s own conditional probabilities. It uses the five-layer checkpoint’s native seven proposal positions and leaves all eight target verification rows in place. **Keep V166 as an offline experiment.** On 768 synthetic lattices, a target calibrated to the draft gave **1.011×** expected commits per pass. When a synthetic target was sharpened until native acceptance averaged four, V166 produced **3.818 versus 4.000**. The public serving receipt reports no calibration measurements that distinguish the regimes. [Synthetic results](quality.json) · [Measured V64 reference](../../runs/abd217baf0ed49fd.json)

## Proposal and rule boundary

The native DFLASH selector scores every transition between adjacent candidate positions. Its greedy walk chooses the locally highest score at every position. With a target distributed according to the draft probabilities, every matching token allows another commitment. Let `V[t,i]` be the expected remaining matches after predecessor `i` at position `t`. Then `V[t,i] = max_j p(j|i,t) × (1 + V[t+1,j])`, with zero value beyond the last position. The overall expected commit count is one plus the root value. For distinct token IDs at a position, the recurrence optimizes the complete linear path. This models the target’s unknown greedy decision using the draft distribution over its top K candidates. [Exhaustive short-path checks](quality_study.py) · [Native checkpoint](https://huggingface.co/RadixArk/Muse-Spark-Open-DFlash2/blob/46c90f412549c472941a68382d91a99e5e6372a0/config.json)

The optional `--speculative-dflash-prefix-value` switch adds a backward pass inside the existing selector-walk Triton launch for greedy rows with 2–8 proposal positions and K of 2, 4, 8 or 16. At native K16 and seven positions the path fits in a 32-bit register, and the returned one-hot proposal rows follow the new choices. Mixed-batch stochastic rows keep the native selected tokens, probabilities and uniform draws. Invalid conditional distributions restore the native greedy choice. The target worker, target forward, acceptance and KV writes are unchanged. The folded and eager workers both call this selector. V64’s official server log confirms the folded selector was active. [Production delta](delta.diff) · [Server log](../../runs/abd217baf0ed49fd.log) · [Export and option checks](validation.json)

The project explicitly prohibits input and output caching. The pinned NGRAM worker builds and queries a worker-owned corpus of prompt and generated tokens, including stored tails and prior-step updates. That implementation crosses this project constraint. V166 reads only the draft scores already computed for the current block. It builds no token-history lookup or cross-request state. ## What the experiment establishes

- The CPU study enumerated 12,928 short paths and matched the exact modeled optimum. It then used the native acceptance and commit functions on 12,288 independent anchor/prefix cases. On one constructed native-width lattice the new path raised model-expected commitments from 2.031 to 4.329. A deterministic target that always chose the original leading option committed eight with the native path and one with V166 on that same lattice. [Expected commitments and counterexamples](quality.json)
- The actual Triton 3.8 interpreter checked 360 request rows in mixed batches. All 180 stochastic rows were bitwise identical to the stock kernel for both token IDs and proposal probabilities. All 360 flag-off rows also matched. All 15 malformed greedy rows exercised stock fallback. [Interpreter receipt](interpreter.json)
- The exact kernels produced 14 offline SM90 cubins. At the native shape the enabled selector used 80 registers per thread and the native path used 24. Both compiled without spills. The existing single kernel launch reads more of the selector lattice. Device wall time, end-to-end serving precision and accelerator memory remain unmeasured. [Compiler receipt](sm90.json)
- The official export is 50,473 bytes and touches 13 paths including V64. Independent full and relative application and reversal reconstructed the published base and V64 source trees exactly. The new CLI flag defaults off. No official check was reserved or submitted. [Frozen patch](patch.diff) · [Verification receipt](validation.json)

The width-eight ceiling permits at most eight commits per pass, including the bonus. Even a perfect native-width proposal could at most double the one-user mean of roughly four if per-pass time stayed constant. The challenge’s four-load score also includes prompt processing and is not bounded by this single-phase calculation. [Prior native-width analysis](../v118_native_tree_budget/README.md)
