# V98 graph-captured grouped expert prefill

V98 replaces a CPU synchronization in every eligible large-prefill MoE layer. V64 and V93 sort the local routes, call `offsets[0].item()` to size two BF16 arrays, and run that expert stage as an eager break in the prefill CUDA graph. V98 puts the route plan, both grouped Humming GEMMs and the combination of their outputs in the captured graph. The production delta applies to V93 and uses the same launch flags. ## Keeping every route

For each token, the GPU counts the routes assigned to this expert rank. An inclusive scan minus that token’s count gives its number of preceding live routes. Dividing this prefix by the wave capacity assigns the whole token to one wave. A token with at most K routes can extend a wave by at most K−1 rows. The guard reserves those rows before it admits the shape. Tokens with zero local routes still receive their zero local contribution, and all-local skew uses further waves.

A stable sort groups slots first by wave and then by expert. The GPU constructs the token bounds and expert offsets from those bins. Each wave writes into the suffix of an arena. Humming takes the end of the last expert from the physical matrix shape. An empty wave therefore sets every expert offset equal to the row capacity, giving each expert zero matrix tiles. The host launch dimensions depend only on tensor shapes. Device lengths and routing data are read anew on each replay. [Independent route and vendor scheduler review](independent_review.md)

The first GEMM accumulates the complete K dimension in FP32 and writes BF16 gate/up results. It retains V93’s packed NVFP4 weights. The activation folds the original per-expert scale and BF16 boundary into the SiLU kernel. The second GEMM’s scale folds into the existing normalization and slot-ordered weighted sum. Every token is finalized once by its owning wave. The ordinary and wave finalizers share the original per-token arithmetic. All TP ranks vote during model setup on whether the required Hopper kernel is available. An asymmetrical compile failure selects the same fallback on the whole group and preserves graph-capture barrier ordering. [Dispatch and two-rank Gloo checks](entry_result.json)

## Measurement

The comparison is V98 versus V93 at 16 users. The scored V64 run measured first-turn p90 of 50.063 seconds there. The proposed gain comes from removing the per-layer graph breaks, host round trips and two standalone scale passes. Wave construction still requires a global sort. Empty waves launch scheduler kernels. A batch with substantial skew can perform several live passes. The patch limits its two BF16 matrix workspaces to 384 MiB combined. At 16,384 tokens, top-eight routing and width 4,096 there are nine possible waves and a separate 128 MiB output. The cap excludes metadata and CUDA graph allocator reservations. The judge must measure full-node peak memory, agreement, TTFT and throughput. [V64 judge result](../../runs/abd217baf0ed49fd.json) · [Workspace geometry](cpu_result.json)

The integrated adapter, gather and finalizer passed 50 CPU differential cases with exact BF16 output comparisons and 151 empty waves. An independent implementation checked 15,695 capacity cases. Independent testing of the actual PyTorch plan verified 1,168,433 live slot mappings. These checks cover duplicated and remote routes, a boundary-crossing token, nonuniform expert loads, all-local and all-remote ranks, unequal hidden/intermediate widths, two normalization orders, and stable token order. The inherited decode, target-selector and FP8 pack suites also passed. [Production plan checks](independent_production_result.json) · [Regression results](regression_results.json)

Thirteen Triton specializations compiled to Hopper machine code, including the ordinary finalizer, wave finalizer and masked-width packer. The scaled-SiLU CUDA wrapper also compiled with 32 registers and zero spills. The November 19 runner reserves one conditional 16-user slot for V98 against V93, with V95 as an independent fallback after a confirmed parent failure.
