# Independent review of V98 grouped prefill

V98 SHA-256 is `c1b8ffcd56c3fbb3c80ae008ab0f10bfe8f9d601ac6822f8d1a27d5c7aad2525`. Its rank-local route plan keeps every selected slot of a token in the same wave. If C is the nominal capacity and K is top-k, prefix positions that start in one C-wide interval can add at most K−1 rows at its end. C+K−1 physical rows therefore suffice for arbitrary skew. Source-token boundaries partition the full output, including zero-route tokens and a trailing empty interval. Within each wave stable sorting groups rows by expert and retains original slot order. The inverse map and common finalizer restore each token's original accumulation sequence.

The direct oracle tested 15,695 capacity cases and 582 numerical plans with 75,503 live slots. It also covered eight larger route layouts with up to 131,072 slots. Separate real CPU PyTorch execution of the exact production planner covered 60 plans, 1,168,433 live slots and the unique write of each of 296,334 tokens. Cases included invalid IDs, an empty rank, the last expert alone, repeated experts, trailing all-remote tokens, overflowing rank-local routes, and ranges cutting across a C boundary. [Independent route oracle](independent_wave_oracle.py), [production planner harness](independent_production_plan.py), [planner results](independent_production_result.json)

Humming 0.1.12 computes the last expert's count from the physical matrix shape and the preceding expert offset. V98 places all live input rows at the end of its arenas and shifts every expert offset by the same leading pad. All offsets equal the physical capacity for an empty wave. With Stream-K disabled, the scheduler computes zero work tiles and bypasses the first MMA. The submit-side launch reads tensor metadata and precomputed CPU config, encodes tensor maps and uses the current CUDA stream. It does not retrieve device route counts. Disabling TMA-C gives the vendor launcher a zero-length TensorMap buffer. [Pinned Humming release](https://pypi.org/project/humming-kernels/0.1.12/)

The V93 eager grouped path calls a host-synchronizing route count once per applicable sparse layer. Breakable graph capture also uses a TP barrier at every eager graph split. V98's final capability check performs a rank-wide MIN in the TP CPU group during model preparation, so all TP ranks select the same capture structure after an optional JIT failure. The production capability function returned the same decision on both processes in six actual Gloo tests including asymmetric JIT failure and disabled flags. The launch loop and tensor allocations during graph recording depend only on static shapes. Current device metadata controls all live work on replay.

At 16,384 tokens, H=I=4,096, K=8, the tested code chooses C=16,377, 16,384 physical rows and nine potential waves. The two BF16 arenas occupy 384 MiB per rank. The caller-visible output adds 128 MiB. Sorting, mapping, graph-pool high-water and graph executable memory are additional. V64's measured stock-relative peak was +1.9 GB, near the +2 GB rule. The dynamic launch savings are unmeasured. Empty waves still launch both vendor GEMMs and the guarded pack, activation and finalize grids. A useful private comparison is V98 against identical V93 at 16 users, with the same flags and model. It should measure first- and later-turn agreement, requested output lengths, peak, throughput and TTFT.
