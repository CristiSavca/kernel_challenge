# V256 uses sliding-window draft storage in the mixed serving path

V256 brings V255's five-layer private draft cache into V248's mixed prompt and decode pipeline. The private draft holds BF16 keys and values in the static target allocator's sliding-window slots. On the eligible FA4 path, both captured and eager forwards read the current request mapping only across the visible suffix, aligned to 128-key attention tiles. During host backup, consecutive destinations share one transfer per K or V plane. V248's target verification, prompt expert and context projection changes are included. The four-flag V255 export is the focused control for this eight-flag integration. ## How much changes

| Quantity | Result | Basis |
| --- | ---: | --- |
| Device KV payload reduction | 6.116 GiB/GPU | Five draft layers at V68's recorded full and sliding-window capacities |
| Host KV payload reduction | About 40.64 GiB/rank | Native host-sidecar row counts at the same control capacities |
| Draft page rows on 208 archived first decode blocks at 16 users | 17,237,738 → 441,578 per address table | Full-width versus bounded lookup on the same prefix lengths |
| D2H copy descriptors per 64 draft pages | 128 → 2 consecutive, 128 → 20 for ten runs, 128 → 128 fragmented | Production copy selectors under a queued CPU transfer fixture |

The payload estimate assumes fixed slot counts. Three additional full-sized static FA graph tables and the write vector require roughly 48 MiB at batch 32 and context 131,072 for one backend. Graph backing stays allocated for native fallbacks. Eager calls on the eligible path can allocate compact tables. V248 already bounds graph lookup on its full-address private pool. V256 preserves that behavior on the fallback pool and supports both address tables on the new SWA-backed pool. It also brings the bounded lookup to eligible eager calls. The archived prefix lengths establish possible lookup work. They do not give kernel durations or estimate the score. ## The integration fix

The mixed worker can receive already-projected K/V rows. When a fused writer fails after a partial write, the recovery path writes the layers again, including only accepted token positions for verified prefixes. That path formerly passed a translated physical slot to the outer cache object. The SWA wrapper expects both address types for an ordinary write and has no prefix-valid entry at that interface. V256 directs the fallback to the draft's actual physical subpool, matching the other three materialization paths. Each input slot is translated once. All prompt rows continue through the original context projection, including the rows needed after a split cached prefix.
