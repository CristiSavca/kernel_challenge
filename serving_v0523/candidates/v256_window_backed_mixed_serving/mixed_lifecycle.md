# Mixed scheduler and private draft lifecycle

Fifty-four runs of the frozen V256 tree passed. Each started with one or more prompts and two running chains, admitted the joined target, sampled the prompt, accepted the draft prefix, committed draft K/V to all five private layers and resolved the next scheduler tick. The comparison covered 216 prompt rows, 486 accepted verify rows and 378 rejected verify rows. It checked all 1,473,120 BF16 words across the ten physical K/V planes, including the sink and unused slots. Each of 27 runs was repeated with identical virtual IDs reassigned to different physical SWA slots. [Replay result](mixed_lifecycle.json)

The fixture executes the published scheduler selection and run methods, mixed target bridge, ordinary target worker, Muse wrapper, logits processor, acceptance, mixed settlement, plan translation and native CPU prefix-valid setter. It verifies all three combinations of target-output flags across eager, Full and Breakable execution. At the single-rank CPU boundary, the raw path uses the native projection decline. For the finalized-FC and preprojected-K/V paths, synthetic projection operators return tensors in the declared layouts. The actual model tail sets the two flags and the actual worker interprets them. The serving shape and five-layer numerical oracle are scaled. Draft proposals, transformer arithmetic, graph launches, device transfers and terminal CPU tensor stores are instrumented. The separate projected-store fixture covers partial writes. [Repeatable fixture](mixed_lifecycle.py) · [Projected-store recovery](paired_store.json)
