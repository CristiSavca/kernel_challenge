# Full-width SUM for attention output

Use the ordinary full-width attention output projection and its original single SUM when the numerical contract requires the parent's reduction. V267's first Gloo integration compared the same unreduced BF16 partials and found **1,556 differing owner words** after two stripe collectives. It also ran a fixed synthetic head and constructed a near-tie witness. Matching projection intermediates isolates this observation to the changed collective. Dropping just the ragged case or checking the outer dispatcher does not establish bit agreement on the physical node. [Integration receipt](../v267_pipelined_expert_serving/attention_pipeline.json)

An independent TP8 CPU Gloo test used the same exactly representable BF16 operand on each rank in the full and striped calls. At 16,384 × 8,192 it compared all 134,217,728 owner outputs for both SUM-and-slice and reduce-scatter against their two-stripe variants. The cancellation inputs matched on both collectives at this aligned shape, and at 256 output channels. PyTorch 2.5.1's pinned Gloo ring divides its input into per-rank chunks before segmenting transfers. The full and half tensors can preserve those chunk boundaries relative to token rows. The observed result is specific to those operands, layouts and transport. [Full-size Gloo results](reduction_order.json) · [Gloo source at PyTorch 2.5.1's submodule commit](https://github.com/facebookincubator/gloo/blob/5354032ea08eadd7fc4456477f7f7c6308818509/gloo/allreduce.cc#L145-L190)

NCCL 2.30.7's all-reduce ring selects the first sender for an element using its channel, flattened offset and chunk width. The same ring and protocol can therefore assign different rank orders to a full-width entry and the corresponding packed stripe entry. An executable example uses an eight-rank ring, an interior 65,536-element chunk, and row 16, column 0 of the 16,384 × 8,192 parent and 16,384 × 4,096 first stripe. These layouts place the entry in ring chunks two and one respectively. Holding all eight per-rank operands fixed gives **0 versus 1**, including with FP32 accumulation at every hop. This example demonstrates the missing guarantee. The actual H200 launch's ring, channel allocation, chunk size and algorithm selection are unknown. [Executable example](nccl_ring_order.py) · [Result](nccl_ring_order.json) · [NCCL 2.30.7 all-reduce](https://github.com/NVIDIA/nccl/blob/v2.30.7-1/src/device/all_reduce.h#L11-L57)

NCCL's reduce-scatter ring uses the receiving owner and the current channel's rank sequence. A fixed owner alone does not fix which channel or topology the tuner assigns at different message sizes. Both native group methods and exact alignment must be treated as provisional until the physical implementation's accumulation is pinned. A finite-operand sentinel or startup sample can detect a disagreement on that sample. Preserving the original tensor shape, column placement, dtype and full-width native collective removes the demonstrated order change without relying on probes. The two-stage QKV exchange only transmits BF16 input rows, so this particular reduction hazard is confined to the output endpoint.
