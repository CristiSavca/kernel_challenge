# V105 sliding-window prefill review

The pinned target uses 46 sliding-window layers and 16 full-attention layers. At TP8, each rank already processes a long prompt with 16 query heads and two 64-wide KV heads. The V105 change applies to long, page-one causal prefill on the sliding layers. The official V64 run used an FP8 target cache and reported first-turn p90 TTFTs of 50.06 s and 110.00 s at 16 and 32 users. Those timings cover the whole request queue and model. [Target geometry](../../../muse_attention_decode/TASK.md) · [Head width](../../../muse_attention_decode/reference.py) · [V64 measurements](../../runs/abd217baf0ed49fd.json)

For each request with Q new rows, K available keys and an inclusive left window L, the first query can read back to max(0, K − Q − L). The last query can read through K − 1. After relocating that entire interval, the lower-right causal alignment shifts every query and key index together. All 2,048 visible keys remain available on a Muse sliding layer, where L is 2,047. An empty request reserves storage and has zero used keys. The extra sequence accounts for the graph bucket's remaining query rows and owns one zero key/value. On the common 16,384-row chunk, the largest live suffix occupies 4.50 MiB across K and V on each rank. [Window semantics](https://github.com/sgl-project/sgl-attn/blob/f89bc2306632d1ec5f97b014dded4254f5b4a907/hopper/flash_attn_interface.py#L1012)

FA3's variable-length ABI uses cuK for the physical segment start and seqused_k for its logical length. Each real segment reserves its query length, L extra rows and 256 guard rows. Byte-exact packing plus zero guards protect the tile tail. The loader reads the layer's selected SWA page table after the normal KV write. The call retains per-request and per-head descales, layer scale, logit softcap, causal window, split count and output destination. Full-attention, prefill-aware SWA, special local metadata, context sharding, deterministic mode and requests for LSE retain their original paths. [FA3 segment offsets and lengths](https://github.com/sgl-project/sgl-attn/blob/f89bc2306632d1ec5f97b014dded4254f5b4a907/hopper/seqlen.h#L42) · [Frozen patch](patch.diff)

The pinned Hopper dispatch disables paged tensor-memory loads for local attention regardless of physical page size. The dense specialization enables those loads. Packing and launches must pay for themselves through subsequent query-block reuse. Different FA3 tile shapes or split heuristics can change FP32 accumulation order even though the valid FP8 inputs and logical attention math agree. Only an H200 serving comparison can establish the net effect or judge agreement. [Native dispatch](https://github.com/sgl-project/sgl-attn/blob/f89bc2306632d1ec5f97b014dded4254f5b4a907/hopper/flash_api.cpp#L402) · [Hopper mainloop](https://github.com/sgl-project/sgl-attn/blob/f89bc2306632d1ec5f97b014dded4254f5b4a907/hopper/mainloop_fwd_sm90_tma_gmma_ws.hpp#L61)

The final packer uses 32-bit loads and stores for aligned FP8 rows and byte loads and stores for other layouts. The native PyTorch wrapper selected word copies in six batches and byte copies in three. Both paths ran at the target dimensions of two 64-wide KV heads. Misaligned tests included K alone, V alone and both tensors, each with an odd row stride and byte-offset start.

The independent CPU oracle compared 86,450 causal windows, 5,236,608 FP8 bytes and 22,528 scalar attention outputs. Inputs included fragmented and repeated physical slots, poisoned evicted pages, unequal K/V storage strides, 74,160-token prefixes, empty requests, graph padding and differing per-request scales. It also exercised the actual backend call with and without descales and checked 15 backend fallback conditions. This receipt covers index, byte, mathematical and dispatch equivalence.
