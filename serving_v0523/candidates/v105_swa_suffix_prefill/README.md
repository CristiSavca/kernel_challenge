# V105 dense FP8 sliding-window prefill on V64

V105 keeps V64’s scored decoder and accelerates eligible long prompts in the target’s 46 sliding-window attention layers. Hopper’s pinned FA3 dispatch excludes local attention from its bulk tensor-memory load path when the KV cache is paged. V105 gathers the visible suffix from the existing page-one FP8 cache, then calls dense variable-length FA3 once with all the request boundaries, the original causal window, softcap and scales. The patch is 53,127 bytes across 11 allowed files. It uses V64’s four launch flags. [Patch](patch.diff) · [Two-file change from V64](delta.diff) · [Export and rule checks](validation.json)

For a request with K cached keys, Q new query rows and an inclusive left window L, the earliest visible key is at max(0, K − Q − L). Moving that key to offset zero shifts the query and key positions equally in FA3’s bottom-right causal mask. Each request keeps a separate dense segment. Device metadata supplies its actual used length. A final zero-valued key isolates CUDA graph query padding, and a 256-row zero guard protects the last key tile. The ordinary dispatch handles unsupported layouts or features. [Physical layout and FA3 call review](independent_review.md)

At the target’s two 64-wide FP8 KV heads per GPU, a long 16,384-token chunk needs at most 4.50 MiB of live K and V with the 2,048-token window. At a captured query capacity of 16,384 and 32 batch slots the two dense allocations occupy 22.05 MiB, including padding. Aligned rows use 32-bit copies and unaligned views use byte copies. The packer checks the allocation against a 48 MiB cap. Cold-prompt score-pair counts put these 46 layers at 13.5% of attention pairs in a 74,160-token prompt under equal head counts. End-to-end latency depends on achieved bandwidth, scheduling and time outside attention. [Allocation and work calculation](attention_work.json)

The production Triton interpreter matched 69,469,568 destination bytes across 88 cases. An independent CPU oracle matched 86,450 query windows, 5,236,608 FP8 bytes and 22,528 attention outputs. Tests included expired sliding-window slots, fragmented storage, per-request descales and padded graph inputs. All 28 SM90 specializations compiled without spills. At the target’s normal row size and int32 page table, the word-copy kernel uses 56 registers per thread. Hardware execution, GPU rounding, capture memory, latency and serving throughput still need a judge check.
