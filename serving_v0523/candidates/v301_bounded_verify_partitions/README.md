# Bounded key partitions for target verification

V301 sizes the split-KV verifier from the dimensions of the supplied page table and the maximum visible causal window. For a single request at the released target geometry, a 2,047-token sliding window and up to eight query positions can intersect at most 34 tiles of 64 keys. This cuts the partition grid from 132 to 68 thread blocks across the two KV heads. The two FP32 scratch tensors shrink by 1,064,960 bytes per eligible layer invocation. Across the target's 46 sliding layers, that is 2,944 fewer partition thread blocks per verification round. The kernel launch count stays the same. [Public wrapper replay](independent_runtime.md)

The wrapper takes the minimum of the native partition count and an upper bound computed from all requests. If the bound fits within the native count, both grids assign one tile per nonempty partition. Every key, partial slot and reduction order is preserved. The kernel skips the cross-request scan for one request. For full attention, the maximum partition width can also establish that one warp can check the entire tile range, eliminating a general long-run search. Sliding-window boundary tiles still use masked paged reads. This logic uses input dimensions and limits it can establish at dispatch. [Incremental source](delta.diff)

The compiler emitted 54 before/after Hopper images across nine shapes. The four-request full direct kernel went from 28 bytes of spill stores and 36 bytes of spill loads in the compiler report to zero. All 27 candidate images in this first matrix have zero spills. An experimental multi-tile sliding scan increased static code size by 48 and 88 instructions at four and sixteen requests. The final patch restores the prior sliding scan and matches the parent’s register, branch and instruction counts at four, sixteen and thirty-two requests. These are compile-time counts. [SM90 compile results](sm90.json)

At the 131,088-column captured page-table pitch, 48 additional before/after builds using the virtual K/V reservation recorded by V41 and V44 reproduced the one- and four-request branch reductions and the four-request spill removal. At sixteen requests the full direct kernel reported 32 spill-store bytes and 44 spill-load bytes in both versions. [Captured-pitch comparison](capture_sm90.json)

The capture allocates 16 extra positions for two in-flight blocks of eight, giving an origin-table stride of 1,025 full tiles or 34 sliding tiles. V41 and V44 reserved 5,005,915 full and 1,251,479 sliding descriptor rows including the sink slot. V68 logged its physically backed counts after graph capture. The V302 descriptor capacity on its eventual node remains unknown. Across all 48 images, switching to V68’s backed sizes as a sensitivity test gave identical register, spill, branch and instruction counts. The Triton host interpreter replayed both complete partition and merge kernels on 30 fixtures. The 2,263,040 FP32 partial and log-sum-exp words and 253,952 BF16 output words matched the parent bit for bit. Dense FP64 causal attention independently checked 184,320 live components with a maximum absolute error of 0.00885. Cases covered ragged and empty queries, zeroed expired cache entries, noncontiguous physical tiles, both descriptor and indexed reads, and page sizes one and sixteen. Both implementations issued the same 824 tensor-map reads in these fixtures. The host BF16 dot shim restores numerical multiply/accumulate semantics to the interpreter’s raw 16-bit representation. [Kernel replay](interpreter.json) · [Replay source](interpreter.py)

The 408,057-byte standalone patch extends V297 and changes one attention file relative to that candidate. The native launch flags, server configuration and expert projections in V297 carry over. There is one intentional dispatch difference for other configurations with a very small caller-supplied workspace budget. The smaller allocation can permit the existing paged path at a threshold that previously selected FA3. The released mixed budget exceeds both allocations throughout the public geometry. V301 has no eight-H200 serving measurement. Nine archived H200 standalone attention profiles at about 80K context put the entire stock attention operation at 1.61–1.64 ms across the model. The comparable historical one-user service interval is 15.84 ms per round. The two measurements come from different jobs. V301 touches only part of that attention time. The integrated V302 candidate also changes small expert projections.
