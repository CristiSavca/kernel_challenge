# V178b live prompt rows for dense FP8 attention

V178b changes how native target FA3 receives K/V for a single long prefill on V64. The current rows convert directly into the suffix of a temporary FP8 tensor. The regular writer consumes those same converted rows at the original physical slot IDs. A full layer gathers its entire previous prefix into the tensor. A sliding layer gathers up to its left-window length and adjusts the device cache length so bottom-right causal alignment retains the same positions. Each layer uses the existing query conversion, scaling, softcap, attention window and output path. The tensor expires with that call. [Source delta against V64](delta_from_v64.diff) · [Export validation](validation.json)

**Physical ownership.** Pinned SGLang `alloc_for_extend` passes its new allocation to `write_cache_indices` and returns that allocation as `out_cache_loc`. The CPU implementation and Triton `write_req_to_token_pool_triton` write the new suffix at the logical prefix offset in request row order. The page-one allocator reserves slot zero. Paired full/SWA allocations publish one mapping which the SWA writer and attention table both translate. Fragmented prior slots therefore affect the halo read only. Fifteen randomized allocations exercised 146,796 distinct positive slot observations for warm and fresh prompts. [Pinned paths and executable fixture](../v178_direct_fp8_prompt_kv/ownership.py) · [Source digests and results](../v178_direct_fp8_prompt_kv/ownership.json)

**Replay and capture.** The breakable graph's RadixAttention callback narrows Q/K/V and output to the live count. Only a matching raw token count from that replay scope permits direct conversion. Synthetic warmup has no live count and can have zero slots. Full capture and unsupported layouts follow the stock path. Ordinary eager EXTEND requires the host request-pool mirror populated during allocation. Both routes require a single request, at least 4,096 real query rows, an ordinary unsharded FP8 page-one NHD cache on Hopper and at most 32 MiB of temporary K/V. A paired 48-case callback suite verified 20,473,344 bytes, including live padded buckets and warmup. Independent tests checked another 11,593,728 K/V bytes, 3,072 numerical outputs and all BF16 encodings across four FP8 conversion cases. [Replay fixture](check_replay.py) · [Replay results](replay.json) · [Independent review](independent_review.md)

One-user traces recorded three cold prompts and 36 later turns. The shape threshold covers 17 of 18 modeled cold chunks, totaling 268,481 rows, and none of those later turns. The V41 server trace recorded 60 eligible single-request calls out of 75 long prefill calls at 16 users, covering 983,040 rows. These are shape opportunities. H200 timing, FA3 reduction-order effects and peak-memory allowance remain unmeasured for this patch. V180 adds this prompt change to the H200-passing V68 verifier, providing a matched 16-user reference.
