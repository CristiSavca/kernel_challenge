# Fused prompt route packing on V219

V221 packs sorted local routes into the input for Humming W13 and writes the inverse map used after W2 in a single Triton launch. It replaces five GPU operations in each eligible prompt MoE layer. The ordinary V219 host path has already selected grouped Humming, stripped remote expert IDs and obtained the number of live rows before the pack runs. Empty ranks and the memory-based indexed fallback exit before any new launch. The ordinary grouped threshold is 8,192 prompt rows for eight routes per token and 256 global experts. [Production delta](delta.diff) · [Grouped entry and measured prompt exposure](../v197_grouped_prompt_gate_up/independent_reach.md)

The first group of thread blocks gathers one complete activation row per live route directly from its original token. The remaining blocks invert the stable argsort permutation in chunks of 256 slots, storing −1 for remote routes and the exact compact row index for every local route. These blocks write disjoint arrays. W13 and the finalizer consume the completed arrays on the same stream. Existing V197 gate/up fusion, V207 scale finalization and V208 residual tile kernels retain their own rounding and routing contracts. [V219 export](../v219_verify_graph_sliding_tiles/validation.json) · [V221 export and rules verification](validation.json)

**Four fewer launches per eligible sparse layer translate to 248 across a 62-layer prompt call.** At 16,224 local routes and 4,096 BF16 channels, one read and one write of each routed input row still move 253.5 MiB. At 16,384 tokens and 32-bit map entries, reading the entire permutation for inversion actually adds 0.443 MiB of logical index traffic. The map is allocated earlier and can overlap the expert projections by another 0.5 MiB. The archived 16- and 32-user traces would need roughly 422 and 390 μs saved per eliminated launch for this change alone to improve whole-trace throughput by 5%. Those numbers are crossover requirements. Neither the physical launch time nor the achieved bandwidth of this new gather has been measured. [Reproducible work model](work.py) · [Shape and trace results](work.json)

**Verification.** The production grouped caller and finalizer matched V219 on 25,170,432 BF16 output words and 1,573,152 map entries in 20 paired CPU runs, covering both W13/W2 adapter modes, expert normalization orders, mixed and skewed routing, empty local ranks and the indexed fallback. Accelerator math in this test uses host implementations. The production Triton pack ran separately in the Triton 3.8 CPU interpreter over 36 fixtures and matched 4,549,210 BF16 words and 791,364 slot mappings, including every BF16 bit pattern, two map dtypes and non-unit, transposed and broadcast column strides. Twelve SM90 compilations used 20–42 registers with zero spills. The contiguous 4,096-column BF16 / int32 case used 26 registers, 2,048 shared bytes and vectorized global loads.
