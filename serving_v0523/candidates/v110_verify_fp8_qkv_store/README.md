# V110 fused FP8 verification query and cache writes

V110 uses one Hopper kernel to convert the target query to FP8 and write the new keys and values into their physical FP8 slots. On V64, FlashAttention 3 target verification issues three BF16-to-FP8 casts and one cache scatter. At 62 eligible layers V110 can remove 186 launches per target verification. The 16,384-token prefill, draft model, target verifier and FA3 attention operator use their original paths. The candidate uses V64's four flags. [Official export](patch.diff) · [Two-file change from V64](delta.diff) · [Patch checks](validation.json)

At 32 requests and width eight, each target step handles 256 rows. With two 64-wide KV heads, removing the temporary FP8 K and V writes and their subsequent reads saves 128 KiB of logical traffic per eligible layer, or 7.75 MiB over 62 layers per GPU. The replacement reads a conversion table for each BF16 element. The impact depends on launch overhead, cache hits for those lookups and FA3's share of the step. Hardware latency and the serving score remain unmeasured.

Torch fills the 64 KiB conversion table from all 65,536 BF16 bit patterns on the backend's device before capture. This preserves the installed CUDA build's FP8 rounding, overflow, signed zero and NaN encodings. The input indices are numerical bit patterns. No request data enters the table. The kernel writes Q even for padding rows, checks the physical slot against the selected pool's logical capacity, skips reserved slot zero and uses separate K and V pitches. The existing pool accessor retains its layer-transfer wait. Context-parallel, scaled, alternate-layout, multimodal cross-attention and other ineligible paths use the native writer. [Backend dispatch](dispatch_check.py) · [Torch CUDA conversion implementation](https://github.com/pytorch/pytorch/blob/v2.14.1/aten/src/ATen/native/cuda/Copy.cu#L65-L110)

The Triton CPU interpreter checked 4,323,144 bytes across 32 configurations and two invalid-slot cases using Torch's CPU-generated table. It exercised all BF16 encodings in each of Q, K and V with int32 and int64 slots, partial tiles, poisoned padding and independent pitches. The interpreter left both invalid destinations untouched. Its CPU assertion hook did not raise. Every offline SM90 binary retained the device assertion. All ten specializations compiled without spills. The target 1,024-channel Q and 128-channel KV variant uses 24 registers. [Interpreter](interpreter.json) · [SM90 compiler](sm90.json)

An independent comparison executed the original and changed target model's attention entry through the paged FA3 dispatch and ordinary FULL/SWA pool methods. All 96 paired calls agreed on every captured FA3 argument and byte, including all 12 fused cases. The CPU fixture records FA3 calls and models the device scatter. Physical H200 execution, numerical agreement on the official requests, peak memory and speed still require a judge run.
