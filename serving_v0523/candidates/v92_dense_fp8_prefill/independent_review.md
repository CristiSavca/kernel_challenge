# Independent FA3 interface and routing review

I traced the pinned FA3 wrapper and C++ dispatch at sgl-attn commit `f89bc2306632d1ec5f97b014dded4254f5b4a907`. The wrapper passes no cumulative K sequence array, supplies `cache_seqlens` as the per-request used K lengths and forwards the original cumulative Q lengths and descales. Without a page table, the C++ operator accepts contiguous K and V of shape `[batch, capacity, KV heads, head dim]` and reads their physical batch strides. The FP8 entry requires E4M3 input, which the raw-byte pack preserves. [Pinned wrapper](https://github.com/sgl-project/sgl-attn/blob/f89bc2306632d1ec5f97b014dded4254f5b4a907/hopper/flash_attn_interface.py#L1122-L1158), [dense shape checks](https://github.com/sgl-project/sgl-attn/blob/f89bc2306632d1ec5f97b014dded4254f5b4a907/hopper/flash_api.cpp#L747-L843).

Varlen kernel dispatch remains active when query offsets or used K lengths are present. The device sequence-length helper uses the live per-request length for the attention span. The target has already written the new K/V into its cache, so the dense call supplies no new K/V append. The unused cumulative *new* K lengths do not extend the attended span. The original causal mask, physical tensor head ordering and per-request/head descales reach the same API. The wrapper receives no scheduler metadata prepared for a different KV layout on this extend path. [Pinned sequence helpers](https://github.com/sgl-project/sgl-attn/blob/f89bc2306632d1ec5f97b014dded4254f5b4a907/hopper/seqlen.h#L70-L89), [FP8 parameter initialization](https://github.com/sgl-project/sgl-attn/blob/f89bc2306632d1ec5f97b014dded4254f5b4a907/hopper/flash_api.cpp#L52-L86).

The integration targets the ordinary full causal target EXTEND path once the GPU, page shape, query length and FP8 guards pass. SWA, local attention, KV translation and DFLASH verify retain their own paths. Device lengths govern the copy, including graph replay. Zeroing through 256 trailing entries covers the partial 160-column key tile of the Hopper FP8 head-dimension-64 large-query specialization. The logical capacity can exceed an individual request length. At one row and capacity 74,160, two heads of dimension 64 consume about 18.1 MiB for both packed tensors. Larger padded batches can exceed the 32 MiB guard. [Pinned tile dispatch](https://github.com/sgl-project/sgl-attn/blob/f89bc2306632d1ec5f97b014dded4254f5b4a907/hopper/tile_size.h#L46-L55).

Dense and page-one cache layouts can select different legal FA3 tile or split configurations. The fixed precision, token coverage and parameter passing do not establish bitwise attention equality. GPU runtime must check full-model output agreement, peak graph-pool memory and time to first token.
