# V92 dense FP8 prefill attention

V64's first-turn p90 was 50.06 seconds at 16 users and 110 seconds at 32 users. Those times include scheduling and the entire prefill, so they do not measure the attention kernel itself. V92 changes how full-attention layers read the KV cache during long prompt chunks. Page-one KV works well for prefix reuse, but the pinned Hopper FA3 implementation uses a separate load path for small pages. Packing cached rows in logical order gives FA3 a dense K/V tensor and access to its bulk tensor-memory load path. The extra gather must pay for itself as successive query blocks reuse the same K/V. [Official V64 result](../../runs/abd217baf0ed49fd.json) · [Pinned FA3 dispatch](https://github.com/sgl-project/sgl-attn/blob/f89bc2306632d1ec5f97b014dded4254f5b4a907/hopper/flash_api.cpp#L379-L401)

A Triton kernel copies both FP8 byte streams in one launch after the ordinary KV write. It follows the current batch's real page table and device lengths and allocates at most 32 MiB per eligible call. The batch can have prefixes, fragmented physical slots, different lengths and repeated physical pages. The backend passes the original query, lengths, scales, softcap, mask and output buffer to the existing FA3 interface. It selects packing on SM90 for ordinary full causal FP8 prefill with a maximum query length of at least 512 and compatible page-one storage. Unsupported layouts and oversized batches use the existing paged call. The packed tensors are temporary and contain live input data from the current invocation only. The test executed the submitted pack kernel and wrapper across 98 gather layouts and 12 fallback cases. Every one of 28,382,976 live source bytes matched. All seven supported power-of-two row widths compiled to SM90 code. The host tests verify the layout conversion. FA3 can choose a different legal tile or split, and the official H200 judge must evaluate end-to-end agreement, peak memory and latency.
