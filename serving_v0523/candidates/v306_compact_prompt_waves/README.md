# V306 removes the host route-count read from fused prompt experts

V197 reads one GPU counter back to the host in each eligible prompt expert layer before allocating the exact number of rows. V306 keeps that decision on the GPU. The fused gate/up projection writes a BF16 activation for each local route, then the down projection reuses the input buffer. The first wave executes in the parent graph. A device-controlled loop handles any remaining tokens, including trailing tokens with no local experts. Older runtimes can run the static sequence and a declined tensor map uses the unfused layout. Decode retains the V197 dispatch. [Patch](patch.diff) · [Changes from V197](delta.diff) · [Launch flags](flags.json)

At 16,384 prompt tokens the two BF16 buffers occupy 384 MiB per rank, the same arena budget as V115. V306 fits 24,576 physical rows versus 16,384, and the maximum number of waves falls from nine to six. In 512 synthetic rank draws at each of 8,192 and 16,384 tokens, V306 took one wave every time. V115 averaged 1.52. The original 16K H200 control happened to have 16,224 local routes and also fits in a single V115 wave. Actual expert skew and time exposed at the host synchronization determine the serving gain. The larger row-key array costs 32 KiB at 16K. Graph executables, sort temporaries, peak GPU memory and per-load time to first token still require hardware measurement. [Geometry and archive](work.json)

The whole-path CPU replay checked 134,784 BF16 output words across 720 cases. The Triton interpreter verified 21,739,116 packed words with guard regions, in 336 waves including 164 empty ones. All 18 Hopper packer and metadata specializations compiled without register spills. The public SGLang wrapper generator compiled and exported all seven native entry points. Public dispatch, two-rank readiness, eager fallback and the native C++ epilogue also passed their respective CPU tests. The compiler checks do not measure eight-H200 latency or generated-token agreement.
