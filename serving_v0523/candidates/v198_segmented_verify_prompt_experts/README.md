# V198 combines segmented verification attention and fused prompt experts

V198 targets two parts of the serving turn that the client experiences separately. During the initial prompt, one grouped expert kernel computes the gate projection, up projection, expert scaling and SiLU product. During generation, full-attention verification can keep using Hopper’s Tensor Memory Accelerator (TMA) on either side of a fragmented cache tile. The earlier fused expert decode path is included. V64’s 1.4119× is still the team’s best official four-load score. V198 has local execution and compilation results. Its eight-H200 speed, correctness, memory peak and time to first token remain unmeasured. [Frozen patch](patch.diff) · [Official V64 score](../../runs/abd217baf0ed49fd.json)

**Cold prompts.** On the ordinary Humming path, V197 writes the BF16 activation directly from the two rounded projection fragments. At 16,384 local routes and 4,096 intermediate channels this removes 1 GiB of logical intermediate reads and writes per eligible layer and rank, plus the scale gather, separate scaling and SiLU launches. The two temporary expert buffers at this shape shrink by 128 MiB combined. The native large-prompt shape uses a 176-row tile, and the three smaller decode tile images match V191 byte for byte. A vendor or shape mismatch uses the ordinary grouped path. In an archived trace, the eliminated prompt bytes would take 0.25–0.68% of total wall time at peak HBM bandwidth. Launch overhead, cache residency and real achieved bandwidth still need measurement. [Compiled Hopper kernels](../v197_grouped_prompt_gate_up/sm90a.json) · [Shape and timing evidence](../v197_grouped_prompt_gate_up/independent_reach.md)

**Verification.** V196 scans the actual cache addresses on the GPU. Every 128-row tile sent to TMA must already have a certificate that all of its addresses are contiguous and in bounds. A long partition can alternate direct reads and ordinary indexed reads while keeping the original FP32 softmax state and tile order. In the 32-user allocator replay, the share of history tiles eligible for direct reads went from 3.81% to 96.69% in first verify batches, and from about 9.0% to 96.42% later. With a free list composed of shuffled 32-row runs the share was zero. An address scan and extra loop transitions also cost time. The replay uses measured request lengths with hypothetical allocations and acceptance, so it cannot establish a throughput ratio. [Allocator replay](../v196_segmented_verify_tma/independent_serving_allocator.md) · [Instruction and spill counts](../v196_segmented_verify_tma/sm90.json)

**Combined checks.** Both donor orders produce the same 31-file tree, and the full and relative exports reverse cleanly. Four expert-source files match V197 exactly and the attention file matches V196. SGLang’s CLI parsed every ordering of all five flags. The export is 189,964 bytes and passed the public source restrictions and 76 denied flag patterns. The dispatch predicates use hardware capability, actual token geometry and physical cache addresses. The CPU fixtures ran the normal long-prompt grouped callback, switched between prompt and three decode kernels on the same weight bank, and exercised missing or moved bindings. They compared 5,772,800 BF16 prompt output components across six geometries and 288 joined decode forwards. A separate C++ epilogue replay checked 18,382,848 BF16 results. The integrated Triton interpreter matched V195 on 40,960 FP32 partials, 640 log-sum-exp values and 24,576 BF16 outputs. A concrete 256-word output from an attention intersection that alternated indexed, direct, indexed and direct reads then passed through the native decoder-layer fixture. Its ordinary and fused expert outputs matched, including a second run using an independent CPU contraction and explicit finite-value checks. The fixtures emulate matrix operations and CUDA scheduling on the host.
