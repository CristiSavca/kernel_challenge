# Independent V133 draft KV review

The frozen patch SHA-256 is `1b240b9e89e7f9c4ac5bf307cb57a03f14d0e20c1c017bca1cca173be62edd2c`. Both tested source files match the official reconstructed tree. On a plain BF16 NHD MHA pool the native full writer checks the physical KV destination against the current `size + page_size` and reserves slot zero. V133 performs an unsigned 64-bit comparison and a GPU trap for invalid slots, and discards zero writes. Legacy prefix-valid writes keep their own behavior and launch without that new bounds argument. [Frozen manifest](validation.json) · [CPU receipt](prompt_check.json)

A Torch evaluator ran the two production Triton bodies. The reference used the pinned worker's materialization kernel and the pinned MHA pool's ordinary writer through its NHD dispatch. The test compiled the native CUDA writer body with a CPU byte-copy primitive and simulated launch coordinates, retaining its index assertion, stride arithmetic and reserved-slot branch. All 2,709,504 cache and guard bytes matched across 40 cases with independent layer buffers, partial rotary dimensions, varying lengths, padded source strides, offset views, scrambled physical holes, slot zero and repeated writes across replays. Both writers rejected each of 60 invalid-slot cases, including negative indices and indices outside 32-bit range. [Reproducible fixture](prompt_check.py)

The actual DFlash worker and materializer executed 67 CPU host-dispatch cases with real BF16 matrix multiplication. Eligible prompts dispatched directly 17 times without allocating or growing helper workspaces. Each of 49 fallback cases dispatched the normal callback and one empty prompt performed no work. The cases covered native-store availability, overridden write methods, active capture, debug assertions, pool/table replacement, BF16 versus quantized storage, noncontiguous metadata, an updated live pool limit and trailing target padding. The historical V104 cases also passed, including 40 setup checks, 22 worker/projection cases and 1,483,968 additional bytes for BF16 and FP8 prefix writes. [Test results](prompt_check.json)

The prompt caller receives translated physical slots from the target prefill plan and trims target padding before passing those real rows to projection. During CUDA graph capture the prompt path defers to the original materializer, preserving its stable workspaces. During ordinary execution the projection and scatter use the same current stream and the helper reads the current physical capacity. Both pointer-table identities must still match the configured pool. A VMM capacity change with stable virtual addresses is compatible with this use, and replacement tables select the callback. Real CUDA stream execution, graph replay, checkpoint output agreement and speed remain unmeasured by this CPU fixture.
