# V135 compact scaled prefill

V135 ports the per-expert output scaling used in V66 to V64's large, compact grouped path. V64 scored 1.4119 over four loads on 8×H200. This candidate uses V64's exact four launch flags. The official patch SHA-256 is `5754c6ea8fe15f6d647682f5cda48db12254999f8f5eb79dd30f094458f8d375`. Physical V135 throughput, accuracy and peak memory remain unmeasured. See the [V64 scored receipt](../../runs/abd217baf0ed49fd.json) and [export manifest](validation.json).

## Production path

V64 selects large grouped Humming when there are at least 256 input routes per global expert. The model prepares the same BF16 activation / NVFP4 weight bank. V135 precompiles one scaled SiLU kernel during load on an eligible Hopper rank with hidden width no larger than expert intermediate width. Each rank can independently use stock grouped Humming on a JIT failure. Deterministic modes, the environment opt-out, other architectures and ineligible shapes inherit the parent. The graph gate and fixed output returned through the parent's eager callback are unchanged. Indexed verify and decode inherit V64.

For each large prefill, the callback collects the number of live local routes in 128-token tiles with a single synchronous host transfer. The parent already synchronized for the first local offset. The new transfer has 128 int32 counts (512 bytes) at 16,384 tokens. Greedy token-boundary windows stop before exceeding the expected local route count plus the larger of one tile or one-eighth of that count. Every window contains whole tokens. The stable expert sort, gather, complete-K W13/W2 vendor contractions and original slot order remain intact. Tail ranks may run different numbers of grouped GEMMs. The enclosing layer continues to issue its usual collective exactly once per rank.

The compact CUDA activation loads each expert's BF16 W13 global scale directly from its sorted int32 ID. It rounds the gate and up products individually to BF16 before the standard FP32 SiLU and multiply, then stores BF16 once. W2 produces raw compact BF16 rows. The exact V66 finalizer uses the original slot's local expert ID to apply that expert's W2 scale and recreate the original BF16 product before per-expert RMS, top-k weighting and accumulation. Both scales and both projections are applied to every selected route. Router scores, precision, attention and model weights are unchanged by the five-file delta.

## Work and memory

At 16,384 local rows and H=I=4096, fusing the two BF16 scale passes removes 512 MiB of W13 logical read/write traffic and 256 MiB of W2 read/write traffic per routed layer. Across 62 layers that is 46.5 GiB. The estimate excludes the extra local route count, the fused scale lookups, cache hits and physical DRAM efficiency. At 4.8 TB/s the nominal equivalent is about 0.168 ms per layer. The packed expert weights and dominant GEMM work still participate. Public scored H200 traces give overall per-load points and TTFT, with no per-expert histogram or complete post-warmup per-kernel timings to turn this estimate into an observed serving speedup.

With a uniform expected 16,384 local rows, either version uses a 384 MiB equivalent activation/arena pair. For a single rank receiving all 131,072 routes, V64's two BF16 arenas can reach 3 GiB. The new 18,432-route window caps the corresponding live arena pair at 432 MiB. This is a source-level bound for those two buffers. Vendor and allocator reservations and the final output are additional. More windows repeat GEMM setup, may reload weights and reduce M tile utilization. V102 and V115 already address prefill via graph-managed waves. V135 keeps V64's eager callback, with one grouped projection pair when the measured counts fit one window.

## Validation

- V135 and V64 produced bit-identical BF16 results in 64 CPU adapter comparisons with 2,932,608 output elements. The tests use production entry points, a dense CPU Humming surrogate and the actual compact CUDA device body compiled with a host vector/thread shim. Cases include both RMS orders, empty and remote experts, duplicate routes, shape tails and concentrated loads. A 16K mixed fixture ran one pair of GEMMs for 16,386 live rows. Full skew ran eight pairs covering every route. Widths up to 8192 exercised the vector loop. [Fixture](cpu_check.py) · [Results](cpu.json)
- The full TVM FFI host/device wrapper compiled with NVCC 12.9.86 for SM90 and SM90a. Both kernels used 32 registers, zero spill bytes and zero barriers. SM90 PTX preserved all 16 scalar round-to-nearest FP32 multiplies and 24 BF16 rounding sites in the eight-element vector. [Build](compile_sm90.sh) · [Compiler evidence](sm90.json)
- The official 54,008-byte export reconstructs the same tree from the pinned base as applying the delta to the scored V64. Both reverse cleanly. All four flags passed the local 76 fixed-pattern checks. [Full patch](patch.diff) · [Parent delta](delta.diff)

An independent run of the actual V64 and V135 Triton finalizer bodies compared 1,874,600 BF16 outputs across 200 cases, including 731,934 live values changed by the BF16 global-scale rounding boundary. All comparisons passed. [Independent review](independent_review.md) · [Results](independent_finalizer.json)
