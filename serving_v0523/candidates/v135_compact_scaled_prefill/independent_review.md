# Independent review of the expert-output scaling path

The test reconstructs V64 and V135 from their official full patches, extracts each production Triton finalizer and runs its arithmetic on CPU PyTorch tensors. V64 scales each compact expert output in BF16 before finalization. V135 uses the original slot’s expert ID to select the scale, casts the product back to BF16, and then runs normalization and the weighted sum in the same slot order. A separate compact-row index locates the actual data. On the normal adapter, a window containing no rank-local routes zeros only that window. The preparation guard restricts the compact implementation to hidden width no greater than intermediate width, which makes V64’s workspace-size fallback unreachable for an admitted window because live routes cannot exceed total slots.

All 1,874,600 compared BF16 results matched bitwise in 200 cases. The tests visited 15,424 live routes and 13,416 remote slots and preserved all 600 poison/guard rows. The inputs produced 731,934 products whose BF16 rounding changed their FP32 value. Coverage includes permuted compact rows, all-remote rows, repeated assignments, both normalization orders and non-power-of-two tails. The kernels used the source hashes recorded in the result and the official V135 patch starting 5754c6. [Executable](independent_finalizer.py) · [Receipt](independent_finalizer.json)
