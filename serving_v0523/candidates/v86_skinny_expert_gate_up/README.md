# V86 fused sparse gate and up projection

V86 replaces the first grouped expert GEMM and its subsequent scaled SiLU kernel with a single CUDA kernel for sparsely occupied Humming W4A16 experts. The kernel takes the original expert offsets, reads each packed gate/up tile directly from the resident Humming checkpoint bank and writes the BF16 activation into the down projection's input. Both projections still compute every selected local expert. The existing grouped down projection and slot-ordered post-expert normalizer consume the result.

The fast path admits decode and target verification when the number of route slots is at most the total number of experts. This expresses an average of at most one routed token per expert. The actual device offsets control the work for every expert, including duplicates, empty experts and experts with more than eight rows. At 256 experts with top-eight routing, target batches with up to 32 rows qualify. Four concurrent requests at the native eight-node verification width can exercise the path. Larger batches use the parent grouped kernels. The new cached JIT falls back to that path on supported compilation or module-loading failures, before graph capture. The environment setting `SGLANG_ENABLE_MUSE_SPARK_HUMMING_SKINNY_GATE_UP=0` disables the optimization.

## Arithmetic and traffic

Each 128-thread block owns 64 output channels for one expert. Its four warps partition the full input dimension into 16-element groups. Each warp reads coalesced 128-word FP4 tiles for gate and up, reads the original E4M3 group scales, and constructs BF16 operands for eight-row warp MMA operations. The kernel sums its four partial results in FP32. It rounds each projection to BF16, multiplies by the existing expert scale and rounds to BF16 again. The last step uses the parent's fast-math CUDA SiLU helper and rounds its product with up to BF16. The cross-warp addition order can change the final rounding on real activations.

The removed BF16 gate/up write and read amount to 32 KiB per local route at intermediate width 4096. For uniform top-eight routing over eight expert-parallel ranks, that is 256 KiB per rank per layer at eight target rows and 1 MiB at 32. Across 62 sparse layers the corresponding figures are 15.5 MiB and 62 MiB. The graph workspace reserves one fewer BF16 intermediate-width slab per possible route, saving 0.5 MiB at eight rows and 2 MiB at 32. Both banks remain disjoint during W13 and W2, and there is one fewer kernel launch per eligible layer.

This kernel still reads the dominant packed expert weights. It trades the parent's TMA pipeline for coalesced warp loads, in-register unpacking and a fused epilogue. Each CTA scheduled for an empty expert exits immediately. Low arithmetic intensity, short expert groups and per-warp unpacking make the throughput outcome hardware dependent. The offline compiler allocated 86 registers per thread and emitted no spill loads or stores. There is no measured H200 speedup for V86.

## Verification and experiment

The full [patch](patch.diff) is 179,260 bytes across 31 permitted sources. Its SHA-256 is `139ce6796500f569511d7c1c0750ef14e8c2a492f855f9b910d9806e297e26e7`. Its [three-file change against V84](delta.diff) is the part to integrate. This archived standalone patch inherits V84's tree-attention compile failure. Use the repaired integrated candidate for official testing. Keep the V84 launch flags and record real committed throughput, agreement, requested lengths, TTFT and peak per-GPU memory. Whole-model correctness and speed require an H200 run. [Export validation](validation.json)

- The actual CUDA header and generated TVM wrapper compiled to an object for SM90 with NVCC 12.9.86, TVM FFI 0.1.11 and the pinned SGLang headers. A second compilation to PTX followed by standalone assembly produced a Hopper cubin with eight static BF16 MMA instructions in the loop, one barrier resource, 16 KiB static shared memory and zero stack or spills. [Compiler commands](compile_sm90.sh) and [compiler output](sm90_compile.log)
- A CPU coroutine simulator executed the CUDA control flow and packed-address arithmetic with software warp MMA and CUDA synchronization primitives. Sixteen cases checked 38,912 live BF16 values and 30,080 poisoned inactive-prefix values against independently packed inputs and a separate numerical reference. These checks include exact hidden width 4096 and intermediate width 4096, separate cases with multi-tile expert runs, empty and imbalanced ranks, signed activations and nonunit globals. [Reproducible harness](cpu_check.py) and [results](cpu_result.json)
- The pinned Humming layer configuration, fake-tensor repack shape and candidate's actual eligibility expression passed for the target geometry. The prepared weights are 32 × 256 × 16,384 INT32 and the scales are 32 × 256 × 8,192 E4M3. Compiled JIT unavailability, invalid packed geometry and disabled grouped decode select the incumbent. [Metadata check](metadata_check.py), [result](metadata.json), and [Humming 0.1.12 release](https://pypi.org/project/humming-kernels/0.1.12/)
- Independent verification compiled the vendor packer, checked 217,088 code positions, evaluated 13,568 scale positions with the vendor transform and checked 2,032 dequantized FP4/scale pairs including signed zero. [Independent review](independent_review.md)
