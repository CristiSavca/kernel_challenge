# V87 fused draft head and sparse expert decode

**November 18 H200 outcome.** The four-user check crashed after startup and a successful health request, before any measured rung. The judge reports `TypeError` without a server traceback or failing operator. V88 isolates the new draft head on V64. V125 independently isolates the new clustered expert computation on V68. [Official V87 result](../../runs/00c134c978104d65.json)

V87 targets two costs paid during a verification pass. The [draft head](../v85a_bounded_vocabulary_tiles/README.md) scores the entire BF16 vocabulary, reduces each tile to its best candidates, and gathers scores and token IDs together across ranks. This avoids writing a dense logits tensor and reading it again for local selection. For K=16 the tile writes 64 bytes of candidate data per draft row, versus 256 bytes for 128 BF16 logits. The target continues to verify the proposals.

The [sparse expert projection](../v86_skinny_expert_gate_up/README.md) reads Humming’s packed W4A16 weights, evaluates both gate and up projections, applies their existing BF16 rounding and scale boundaries, and writes SiLU×up into the down projection’s input. This removes an activation kernel launch and the intermediate gate/up tensor from each eligible layer. Higher occupancy uses the existing grouped implementation. The FP32 partial sums combine in a different order. End-to-end token agreement needs the judge.

At four full requests, eight verification nodes and eight routes per node give 256 route slots, exactly the sparse kernel’s admission limit on this model. A full 16-user batch has 1,024 slots. The four-user private check therefore exercises both optimizations if the guarded paths activate at runtime. The scored V64 result at this load was 1.316× stock. V87 and V64 include several other differences. A single-load check measures their total effect at that load. [V64 score](../../runs/abd217baf0ed49fd.json)

## Reproducibility

Apply the [frozen patch](patch.diff) to SGLang `297e54fd105e974cdf401e5b4d20253a22c16f90`. SHA-256 is `c04ffda8c63ad2ac672b41f74bd7ba11f3e171abd501410a1bcc58ac24142684`. The [validation receipt](validation.json) lists the nine flag overrides and all parent hashes. Official export, forward and reverse application, the source path restrictions and the launch-flag exclusions were checked. The patch is 186,779 bytes across 32 permitted files. The longest added line is 118 bytes.

The [compiler suite](../../runs/compile_decode_sm90.py) compiled 46 Triton specializations into Hopper cubins from this combined checkout. On Linux with Triton 3.8.0, use `python compile_decode_sm90.py /path/to/sglang --only-extra --extra sm90_triton.json` to replay the exact configurations. The four-user draft projection produced zero register spills for the aligned and unaligned pointer configurations tested. Legacy grouped staging had spills in three fixtures. NVIDIA NVCC 12.9 also compiled the pinned TVM-FFI wrappers for the sparse expert kernel, BF16 all-reduce and two BF16 multicast-gather widths. [Triton compiler receipt](sm90_triton.json), [expert compiler log](../v86_skinny_expert_gate_up/sm90_compile.log)

Combined-source CPU tests covered vocabulary tiling and cross-rank candidates, packed expert dataflow, target-tree acceptance and slot reuse, normalization, compact context and router gathering. These tests use simulated kernel operations or CPU tensors. The judge determines target agreement, output length, peak memory, TTFT and throughput on the eight-GPU serving system. [CPU results](cpu_results.txt), [independent review](independent_review.md)

Triton's CPU interpreter also passed 120 tree-acceptance layouts and 27 candidate-head layouts with exactly representable integer inputs. Its BF16 dot primitive failed a standalone control, so the head replay used FP16 operands and the production BF16 score packing. The BF16 CUDA specialization compiled separately. [Interpreter fixture](../../runs/interpret_decode_kernels.py)
