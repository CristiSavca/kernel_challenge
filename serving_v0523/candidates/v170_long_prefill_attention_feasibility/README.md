# V170 long-prompt attention feasibility

Scored V64’s single-user cold prompt already selects one FA3 split for all five modeled chunks. The 74,160-token case has four 16,384-query chunks and one 8,624-query chunk. All use packed grouped-query attention and 192×160 tiles. Moving from physical page one to a certified dense view enables TMA reads for both full and sliding-window layers. V143 and V146 already implement those respective changes on the page-one allocator. V170 produced a reproducible dispatch and work comparison. It has no serving patch or hardware timing. The host fixture compiles the pinned FA3 split, TMA and GQA selectors and the actual block-range implementation. It covers 312 variable-length geometries at batch sizes 1, 4, 16 and 32 within V64's 16,384-query budget, plus ten fixed-shape dense calls. It includes live extents, long prefixes and the model's 131,072-token context. The split selector returns two or three only for single-user query widths 512, 753 or 1,024 in this grid. Those are possible later-turn cases. The receipt's one-user later-turn TTFT p90 was 175 ms versus 5.419 s for first-turn TTFT p90. Neither statistic isolates attention time. **Fully static dense attention.** An exact additional specialization could reshape the model’s flat packed queries to rank four for a uniformly-sized batch and drop both dynamic length arguments after proving each dense KV view has precisely the live extent. Native fixed-length dispatch replaces the variable-length scheduler prepare launch with a semaphore zero for single-split causal or local attention. The fixed default disables packed GQA in all ten cases. Over the five chunks, full layers visit 1,449,952 Q/K tile pairs per rank versus 1,436,918 packed. Sliding-window layers visit 86,016 versus 79,360. That adds 0.91% and 8.39%, respectively, or 1.93% weighted by layer count. Different CUDA scheduling and GQA addressing could still change elapsed time. There is no reduction in required attention or number of these setup operations to justify freezing another candidate ahead of a matched V146 measurement. **Existing packing covers fragmented page-one caches.** V95 copies full FP8 KV into a rectangular scratch area. V137 adds guarded live-length packing for imbalanced batches where the rectangle exceeds 32 MiB. V105 limits a sliding pack to visible keys, while V146 can use an affine view of precisely that suffix. Each rank has two KV heads of dimension 64. If every cold chunk packs its full history, the 16 full layers copy 974,848,000 payload bytes per rank across the turn. The 46 sliding layers copy 969,730,048 payload bytes if each packs only its visible suffix. Reading and writing scratch incurs twice those quantities in traffic before attention reads its input. V64 reads the paged cache directly. The benchmark does not give per-layer time or the percentage of span certificates that pass. The official one-user 92% cache-hit rate measures prefix reuse, which is a different property. **Context-parallel prefill.** The exact V64 Hopper/Humming resolver accepted its scored topology and rejected all 15 tested combinations that enabled CP, DCP or prefill CP. The Muse attention layers size their QKV and output shards from the attention TP group. Its model body lacks the explicit CP hidden/position split and final hidden/tap gathers present in the pinned CP-aware Qwen model. With eight fixed ranks, reallocating a factor of C from attention TP to context parallelism puts C times as many Q heads on a rank for about 1/C as many queries. Ideal balancing retains the same 208.44 trillion useful FP8 QK/AV operations per rank across this first turn, 86.46% in full-attention layers. It can change communication and utilization. Replicating KV for C=2 at the same capacity would add 22.42 GiB per rank just for target KV at 3,419,325 full and 854,831 sliding rows. V64 already reported 1.9 GB over stock against a 2 GB allowance. A viable design needs a real CP-aware model boundary and distributed page ownership, including speculative decoding's taps, physical slots and return to decode TP. A launcher flag cannot establish those invariants. [Executed resolver cases and math](check.json) · [V64 startup](../../runs/abd217baf0ed49fd.log)

The existing V146 versus V64 comparison is the direct test for the dense-span path. A separate later-turn microbenchmark could compare building reusable scheduler metadata for repeated single-user, multi-split geometries around 753 queries, preserving each layer’s actual full or sliding lengths.
