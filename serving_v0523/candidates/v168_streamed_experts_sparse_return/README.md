# V168 streamed decode experts and sparse prompt return

V168 combines V165’s low-load Hopper expert projections and V167’s two-way sparse prompt exchange on V164. It uses the same five flags as V164. Its official patch SHA-256 is `95816b34347ec23816b3def52e99265449ce0c8df523e0a36f587603ae57b574`. The scored ancestor V64 achieved 1.4119× overall. V168 has no H200 timing, scored result or measured peak memory. [Export manifest](validation.json) · [Full patch](patch.diff) · [Change from V164](delta.diff)

During eligible decode, a producer warp stages the prepared expert weights, scales and live BF16 inputs for the compute warps. V165’s residency test retains its previous kernel when the output groups already occupy the device. All decode CUDA headers, prepared-map setup and dispatch bodies match V165. A replay of 54 setup and 72 dispatch cases exercised TMA, vector, indexed, medium and empty branches. The native device-loop simulation covered 18 shape/schedule combinations and six accumulation-order probes across 102,081,024 staged bytes. V165’s separately archived Hopper cubins apply to the identical source. [Dispatch](decode_dispatch.json) · [Device-loop simulation](decode_warp.json) · [Hopper assembly](../v165_streamed_expert_stages/sm90.json)

During eligible long prompts each token owner sends its BF16 inputs to the ranks that own its selected experts. Each rank normalizes and combines its local expert outputs, then returns one BF16 partial per owned token. The token owner adds these partials in source-rank order in FP32 and rounds once to BF16. V164’s scaled grouped implementation can consume and overwrite a compact receive tensor because it stages a whole window’s inputs before writing that same window's result. A hook or an unfavorable transfer layout keeps the existing dense gather and reduction. The native return kernel is byte-identical to V167. [V167 kernel and transport checks](../v167_sparse_expert_return/independent_review.md)

V168 carries the original global token count into the V135 window-size calculation. Transport can drop a token from a given rank if none of its routes use that rank. Using the shortened row count to size the grouped arena can make otherwise unnecessary extra W13 and W2 calls. At 16,384 original tokens, eight routes per token and 32 of 256 local experts, the established cap is 18,432 routes. A test with 10,844 owned tokens and 16,384 local routes ran one grouped projection pair. Direct composition would have used two. The tests also exercised one below, at and one above the cap. The last case used two complete-token windows. The integer is available from an existing tensor shape without a host synchronization or extra token storage.
