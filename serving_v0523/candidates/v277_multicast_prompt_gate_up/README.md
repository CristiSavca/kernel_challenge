# V277 shares prompt gate/up activations across four output tiles

For a long grouped prompt, four neighboring Hopper thread blocks compute different gate/up channels for the same 176 expert rows. V277 uses one tensor-memory transfer to send the BF16 input tile to all four blocks. Each block still reads its own packed NVFP4 weights and FP8 scales and writes its original 128-channel SwiGLU band. The launcher queries resident clusters for the actual kernel function and stream-launched configuration. Short inputs, older hardware, insufficient occupancy and unsupported layouts retain the previous path. V277 is based on V248. [Official patch](patch.diff) · [Published-rule checks](validation.json)

On the reconstructed rank-3 routing of the archived 16,384-token H200 prompt, the 99 row tiles generate 3,168 output jobs. The source activation boxes shrink from 4,356 to 1,089 MiB per layer on that rank. Packed weights and group scales remain 1,782 MiB. These are requested payloads including tile padding. The GPU can satisfy repeated requests through L2, and cluster placement and synchronization can add time. At 128 resident blocks the longest sequence of issued tensor rows grows 4.2% on this rank. The SM90a compiler emitted seven activation multicast sites, fourteen 4D weight and scale load sites, and the same 96 BF16 matrix instruction sites as the parent. Both images use 168 registers and 128,000 bytes of dynamic shared memory. The seven actual TVM-FFI entry points compiled with CUDA 12.9. A compiled host replay of the epilogue checked 18,382,848 output values. The allocation and startup fixtures exercise the normal and declined calls.
