# Independent review of V138

The scored V64 configuration enables layernorm sequence parallelism and selects Humming. The registered Muse conditional-generation model constructs the Muse text model and its bias-free, unquantized QKV projections. The model runner initializes distributed groups before model construction. The loader constructs the model under its target device and dtype contexts. Its later weight load populates the real parameter used by every projection. The startup probe exchanges a single scratch BF16 value and never reads provisional weights. The transfer stream is associated with the model’s tensor-parallel group.

All participants in the official TP8 group have the same layer shapes and padded local token count. The startup Gloo MIN admits the path only when all ranks have an available PyNCCL communicator, matching attention-group rank order, Hopper and compatible local BF16 parameters. Neighbors are communicator-local ranks. A live layer uses only the shared, padded input row count, output width and TP size for its size threshold. With 2,304 output channels and TP8, the first eligible local shard has 576 rows. The final narrow uses the real row count after every rank finishes all eight projections. A separate ownership check covered 320 rank and tail combinations across TP4/8 and local shard sizes 1, 512, 2,048 and 2,049. Each output row had exactly the original source owner and local offset.

The registered custom op supplies a fake output shape to the Breakable graph tracer. Native PyNCCL send/recv resolves the current stream at each call. The pinned stream helper caches the device index and queries that device’s current stream. Each exchange waits on the compute stream before reusing its destination. The current projection and send can read the same source concurrently. Before the following projection the compute stream waits for that receive, including the final transfer. The two scratch buffers are allocated on the compute stream and their outstanding reads and writes are joined before returning. This relies on ordinary ordered model execution and a single issuing device per rank. The scored runner provides that execution model.

The startup test covers the configured precision and module method. An application that mutates its precision settings or replaces the quantization method later would require revalidation. The published CPU fixture provides rank and tail ordering coverage. Physical H200 graph capture and replay with grouped PyNCCL P2P, BF16 output agreement, and the elapsed-time tradeoff of eight smaller GEMMs still require measurement.
