# V257 · Fuse the final residual gate

V257 builds on V256 and combines the two FP32 products, the BF16-to-FP32 conversion and the addition in Muse Spark’s final residual gate into one Triton launch. It evaluates every row, attended key, routed expert and normalization. Precomputed channel gates on contiguous inference tensors can use the new kernel. The native expression handles other layouts and dtypes, training, tracing modes and unsupported devices. The cumulative patch is 405,125 bytes across 62 paths. Its SHA-256 is `d79351da3fc899b1d4c63dd9aff8c618fc73cfd4152be0f7295d56a0bef3bdf4`. ## Why the last decoder layer still runs

The pinned DFLASH2 checkpoint consumes post-residual outputs from target layers 1, 16, 30, 44 and 59. Layer 60 supplies the input for every key and value projected in layer 61. Those entries can be read during prompt continuation, prefix reuse and decoding. Layer 61 is outside the draft taps, but stock SGLang evaluates its attention and FFN rows before output selection. Input scoring can request interior rows. Restricting its FFN to one endpoint in a 16,384-token prompt would omit 131,064 routed expert evaluations. The serving rules require preserving stock computation. Even the hypothetical single-endpoint change that retains only final-layer K/V for the other rows removes about 1.57% of modeled 62-layer linear work. Removing only the final FFN would save about 1.10%. Both estimates exclude attention-score products, softmax, activations and elementwise operations. ## Local verification

The kernel widens BF16 by preserving its bits and executes two rounded FP32 products followed by one addition. All six SM90 compilations had separate FMUL and FADD instructions and zero FFMA. The Triton interpreter matched all 530,937 FP32 words across five shape tests. An exhaustive BF16 sweep matched all 65,282 non-NaN outputs bitwise and the NaN masks for the other 254 encodings. The CPU model-entry fixture compared V256 and V257 through the production terminal-layer and output-normalization code for ordinary prompt, mixed DFLASH, verification and ragged prompt batches. It included the true 2,048 × 8,192 rank-local shape of a 16K eight-way prompt. It used synthetic preceding layers, experts and sequence-parallel ownership, with Torch standing in for the launched kernel. [SM90 assembly](sm90.json) · [Interpreter results](interpreter.json) · [Model entry](model_entry.json) · [Lexical validation](global_names.json)

The fusion eliminates three temporary tensors and three launches per eligible call. Counting stream and branch inputs, outputs and intermediate traffic gives 34 bytes per element before fusion and 10 after. That is 384 MiB per rank at the 16K prompt shape, equivalent to about 0.084 ms at 4.8 TB/s. The comparison excludes channel factors and cache effects. Applying the same calculation to historical eligible grouped rows gives 6.29 ms and 12.57 ms per archived repetition at 16 and 32 users. These are traffic estimates. Physical H200 correctness, end-to-end throughput, peak memory and time to first token remain unmeasured for V257. [Traffic model](work.json)

Run `kernel.py SOURCE interpret` with NumPy, `TRITON_INTERPRET=1` and the campaign’s `serving_v0523/runs` on `PYTHONPATH`. Here `SOURCE` is the patched `python/sglang/kernels/ops/layernorm/muse_spark_norm_residual.py`.
