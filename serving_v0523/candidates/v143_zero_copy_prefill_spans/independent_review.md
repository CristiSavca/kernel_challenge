# V143 native attention and metadata lifetime

The frozen V64-based patch can reach FA3's Hopper tensor-memory accelerator path on long, causal, full-attention FP8 prefill. I compiled the pinned native tile and paged-dispatch selectors into a host executable. All 960 geometry cases passed. At head dimension 64 the long-query FP8 kernel chooses a 192×160 tile. Its selector accepts physical pages of 160 and rejects pages of one at the measured geometry. Across 1,392 native shape cases, including physical pools of 3.45 million slots, FA3 computes total K as request count times the dense length or times 160. Its tensor-map page count is a separate dimension. The certificate limits dense B×L to 262,144 and bounds exposed coarse pages by the largest certified live ID. Only complete live 160-token groups can use the coarse view. Native strides address the same FP8 rows as the original page-one table. Kernel selection can change floating-point accumulation and requires hardware correctness measurement. The pinned breakable prefill runner rebuilds ordinary FA3 metadata from the current live batch before replay. Its replay loop invokes the Python attention break between segments. Executing the runner's refresh method with alternating requests and repeated buckets yielded 72 fresh calls. The plan requires the exact table and length objects and matching query-row count, and checks version counters where available. Under inference mode the fresh advanced-indexed physical table and normal batch ownership supply isolation. The actual frozen view recorded each of 24 simulated CUDA consumers on its corresponding stream, after the producing event was ready. This protects the new compact page table from early allocator reuse across streams. Those tests also verified physical address order when separate sequences shared pages, and validated trimmed backing extents at four distinct starting residues. Native CUDA event and allocator behavior still need a device check.
