# Independent clustered expert MLP review

For each live expert, the warp scan assigns sequential non-overlapping slices of at most 16 staged route rows. All eight CTAs of a cluster share the same job ordinal, route offsets and row-count branch. Every CTA finishes reading the original BF16 input and publishing its own activation band before the first cluster barrier releases any W2 writer. W2 visits the eight activation bands in ascending K order and each CTA overwrites only its own output-feature stripe. The second cluster barrier prevents a fast CTA from reusing or retiring its shared memory while a peer still reads it. Other clusters own disjoint rows. The absence of a live tile is uniform across a cluster. [Frozen two-file integration and CUDA implementation](delta.diff)

The independent CPU simulator executed production `locate`, `load_rows`, `contract`, `gate_rows`, `down_rows` and both barriers. It substitutes the warp MMA instruction, packed BF16 multiply, cluster-address lookup and device synchronization with CPU equivalents. It schedules each warp independently through the next barrier, rotates warp order, reuses dirty shared banks across jobs, and checks for premature writes to the aliased input and for writes into shared row padding or guard regions. Its independent dense reference starts from unpacked FP4 codes and E4M3 scales, rounds the W13 projection to BF16, applies and rounds the expert global scale, rounds the scaled SiLU product, accumulates W2 in FP32 and rounds the returned expert row to BF16. [Simulator](independent_cpu.py)

Five geometries matched in all 69,632 live BF16 outputs and preserved 31,744 inactive global-buffer values. Tests covered empty experts, 1/7/8/9/16/17/35 routed rows, unequal hidden and intermediate sizes, and the 4,096 × 4,096 checkpoint dimensions. The full-width fixture uses finite sparse FP4 values to bound reference runtime. The simulator checked 11 live tiles and 37,632 software remote-address lookups. The production header digest matches the exported patch. CPU MMA uses a serial FP32 reference accumulation within each 16-wide instruction, and CPU exponential approximations are platform-specific. H200 instruction rounding, latency and comparison against the vendor GEMM are outstanding. [Execution receipt](independent_cpu.json) · [Export manifest](validation.json)

Target dispatch requires SM90, the supported packed layout for both projections, positive cluster occupancy from the CUDA runtime, and at least four route slots per global expert. At width eight with top-eight routing and 256 experts, four users produce 256 slots and sixteen users produce 1,024. Outside the selected shape the existing expert kernels run. The caller receives the original row map and local expert IDs, applies the existing W2 global scale, per-route normalization, top-k weights and external reduction. Physical remote traffic and cluster residence under contention determine whether fusion saves time on H200. [Dispatch fixture](dispatch.json) · [Work model](work_model.json)
