# V229 sharded target projections and packed draft candidates

V229 combines V228’s target projection sharding with V225’s single-gather DFlash selector on the V224 serving stack. At TP8 with 128 target rows, two eligible projections read 16 MiB of BF16 weights per GPU per sparse layer, down from 128 MiB. Each output uses the complete input width, and the native router and expert all-reduce retain their order. For a 16-user draft step, each rank contributes 7,168 bytes to one gather, down from 21,504 bytes across two gathers. The selector still computes the full vocabulary projection, score order and global top-K. [Projection design and caveats](../v228_sharded_verify_projections/README.md) · [Selector design and caveats](../v225_packed_draft_candidates/README.md)

**Four-load performance remains unmeasured.** The 6.78 GiB reduction per rank per eligible 62-layer target pass is nominal projection weight traffic. At eight target rows, native multicast may already shard the unpooler, leaving 3.39 GiB of incremental savings. Gather time, overlap with the router, CUDA GEMM tiling and memory traffic determine the wall-clock result. At 128 rows, the standalone H200 timings gave 53.15 µs per layer for the original pair. The replacement pair and its two gathers would need to finish within 32.50 µs per layer for an illustrative 1.63% gain in V64’s verification period.
