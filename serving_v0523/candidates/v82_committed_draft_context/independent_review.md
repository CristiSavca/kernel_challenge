# V82 independent source review

Frozen patch SHA-256 `669689a36ae624158cf3706a061d0605eaa982cfcf62e4d16c1de6ac21e1b9d7`. Its four changed sections relative to V80 match the additive delta. The full patch reverses against the export checkout. Every patched Python file compiled. The new launch flag selects a tree-commit implementation and leaves the checkpoint, sampler and target logits intact.

The tree accept kernel supplies a permutation and a committed prefix length for each request. The planner reads the permutation in live destination order. Its source row is the request's base plus its original tree node. The GEMM loads the complete BF16 hidden vector and the local output-channel weights, accumulates each 40,960-element dot product in FP32 and stores to a BF16 destination. The incumbent draft TP group reconstructs the global channel order before RMSNorm. Idle destinations start at zero, and both fused and sequential prefix writers consume the same per-request lengths. The worker records its commit event after the writes. Deterministic mode, ineligible geometry, linear verification and incompatible projection modules retain the dense path. The selector-tree checks already restrict request modes before the permutation exists.

An independent CPU execution of the production planner and GEMM covered 16 cases with 677 committed rows. Cases included empty, fully committed, alternating and heterogeneous lengths, nonidentity permutations, non-power-of-two widths and a full 40,960-element dot product. The run used the final runtime row argument and minimum 256-lane scan. All destinations matched the oracle, the largest relative L2 between FP32 pre-cast accumulators and a float64 reference was 4.67e-7, and all invalid destinations stayed zero. This simulation uses float32 representations of rounded BF16 operands. Hardware instruction selection and final serving agreement need H200 validation.

The incumbent local weight shard still represents 80 MiB per GPU. A 16-by-32 output tile traverses up to 640 K tiles, and each surviving row tile visits its relevant shard. Fewer output rows can improve high-batch compute efficiency, but the kernel can lose on occupancy, effective memory bandwidth and first-use compilation. Single- and four-user runs at width eight have fewer than 64 target rows and take the fallback. Acceptance, decode throughput and TTFT require a same-load comparison with V80.
