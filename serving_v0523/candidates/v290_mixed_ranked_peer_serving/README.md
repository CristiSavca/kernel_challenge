# V290 combines ranked decode and peer-packed mixed prefill

V290 gives the same model two ways to bring expert inputs to their destination. During eligible decode graph capture, the router prepares expert rows on a side stream while the pooler gathers BF16 columns on the main stream. A fused RMSNorm then writes directly into the routed rows. During a long sequence-parallel prompt, the server publishes each rank's shard into alternating peer buffers. The local expert reads the requested rows from their owners. The expanded prompt graph also admits genuine verified decode rows alongside a full prompt chunk. All target and draft weights, precisions, requested attention keys and expert assignments follow the parent paths. [Full patch](patch.diff) · [Changes from V289](delta.diff)

## Where the changes apply

| Forward | V290 operation | Boundary checked |
| --- | --- | --- |
| Short native verification | Overlap route planning and the rank-major gather. Apply the checkpoint's weighted BF16 RMSNorm directly to sorted expert staging. | Matched capture vote, original row maps and outputs. |
| Long captured prompt | Alternate two registered BF16 peer buffers. A full unavailable allocation or registration falls back across the entire group. | Received BF16 words, re-use order and single-buffer fallback. |
| Full prompt with an eligible running cohort | Expand the graph to include authentic DFLASH verification rows and commit the ordinary verified chain. | Physical slot planning, capacity, stale proposals, recapture and declined joins. |
| Eligible direct prompt attention | Produce the public parent query's FP8 bytes during QK normalization and rotary embedding. | Actual callback and FA3 wrapper saw identical query bytes. |

At the 16,640-row capacity and TP8, one 2,080 × 4,096 BF16 peer slab occupies 16.25 MiB per rank. Two occupy 32.5 MiB. The ability to reuse a slab after another rank reads it depends on synchronization across the group. V290 retains V233's earlier route eligibility planner and uses V286's two-slot publication and unanimous single-slot fallback. The combined implementation was exercised directly. The second slab, larger prompt graph keys, decode buffers, allocator sizing and interleaved activity all contribute to actual peak memory.
