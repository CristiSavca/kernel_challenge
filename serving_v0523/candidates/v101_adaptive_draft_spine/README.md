# V101 adaptive native-prefix depth

V101 lets each greedy request choose how many verifier rows to reserve for its native DFLASH continuation. The remaining rows check alternative paths from the same draft forward. At width eight this gives eight possible minimum depths, compared with V99's choice between the original tree and the full seven-token chain. V101 uses the same eight target rows and the existing full-vocabulary greedy target verification. The launch stack adds `--speculative-dflash-adaptive-spine` to V99. ## Building the proposal

For a minimum depth *s*, insert the anchor and the first *s* native draft tokens, then fill the remaining rows from the original selector tree in its existing prefix-probability order. Skip each already-inserted node by following its actual parent and token. Every extra's parent is either on the native spine or earlier in the selector order. Relative order between retained extras is preserved, and their parents and ancestor masks are reconstructed. If the original tree already contains the required prefix, its exact row ordering is preserved.

With a width of *W*, at most *s* of the original *W*−1 draft nodes have already been inserted. There are always enough remaining nodes to fill the tensor. Since the original selector enumerated the highest-mass prefixes, choosing its earliest remaining nodes also maximizes the sum of their modeled prefix probabilities subject to the forced prefix. The intermediates are useful when the model's estimated prefix mass and actual greedy target agreement diverge. A perfectly calibrated selector would already maximize expected acceptance with its original tree.

## What the request learns

Increasing the minimum depth by one either leaves the tree identical or adds one native leaf and drops one optional leaf. Two neighboring policies can therefore differ by at most one committed token on any continuation. The verifier reveals the accepted tokens and a bonus. When a neighboring pair gives different bounded commit lengths on that prefix, their signed difference is exact. When both match all revealed tokens and could still commit beyond the known bound, their existing margin is held. Already identical policies, definite ties and complete observations update normally.

A small signed integer for each adjacent depth tracks these differences with decay. Maximizing the cumulative sum selects the next proposal, with ties going to the smallest minimum depth. New requests begin with the original tree. Only these integer margins travel with the request across filtering, merging or scheduler overlap. Verified token IDs are read from the existing commit buffers during the current update and are never stored in the policy state. Rank zero selects and broadcasts the same four proposal planes used by V99. The new flag defaults off, and the existing eligibility checks still control greedy graph execution.

V101 has no H200 correctness, memory or throughput measurement and used no challenge quota. The selection and feedback kernels do more work than V99's binary policy kernels. Changed physical slot order can also expose finite-precision behavior in the inherited attention backend. Its mechanism targets decode, while the four-load score includes prefill.
