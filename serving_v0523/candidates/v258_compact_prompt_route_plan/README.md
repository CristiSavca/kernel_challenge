# V258 compacts long-prompt expert routing on V256

V258 replaces the stable full-slot sort in the sequence-parallel Humming prompt dispatcher. On TP8, a 16,384-token prompt produces 131,072 global routing slots. With eight valid routes per token, exactly 16,384 slots belong to each rank on average. The parent allocates a 64-bit permutation over every slot on every rank. V258 emits only the live sorted expert IDs and writes the inverse row directly where the peer packer and finalizer consume it. Each local expert sees the same token and top-k order as V256. [Official patch](patch.diff) · [Changes from V256](delta.diff)

The first GPU pass maps native int32 router IDs through the resident expert map and counts each local expert in tiles of 256 slots. The second pass scans tile counts and supplies the live count to the existing CPU vote. Once every rank agrees, the third pass sorts each tile by expert and original lane, then scatters the inverse indices and compact expert IDs. A rank with zero live routes still publishes its hidden-state shard and joins both barriers. This runs on the existing Humming long-prompt path when the Hopper peer workspace and ordinary runtime guards qualify. The V256 route gather, expert projections, weighted finalizer and source-token reduction retain their existing operation order. Int64 IDs take the parent planner.
