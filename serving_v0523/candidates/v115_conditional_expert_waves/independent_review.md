# Independent V115 CUDA graph review

I reviewed the three production changes relative to the frozen V102 index. The source hashes, in the order of the wave implementation, Humming setup and graph-cache code, were `e8ba29060f9e51e54d6eb530f06a4240c5672e3fdd25b2bb937f203910663a24`, `3e05d39fb9b6b0ef97158844524c95d3803648c3bbb7ca2802c93f2641705064` and `26c14383bf709c457a7e7dda0a608e237a6f2e49ee9e9775f2e8bdc4bbb2c494`. The normal data path and the allocator-configuration fallback pass source review.

- The first metadata kernel sets the cursor to zero on every replay. The WHILE body advances it exactly once, publishes the new bounds, and then updates the CUDA conditional handle. The final advance clamps every table address and clears the predicate. Since token starts are monotone, a first token equal to the batch length rules out every later interval. An all-remote batch still runs wave zero, giving the finalizer the entire token interval and producing zero outputs. Trailing remote tokens in a valid interval also reach the finalizer. The parent owns each workspace, active flag, cursor and interval while the child is recorded.
- Pinned PyTorch 2.14.1 retrieves the current graph using its capture ID. The Python binding returns a borrowed reference. In breakable capture SGLang retains the real graph as its current segment during body capture, and later retains it in its segment or executable registry. PyTorch records the handle initialization and inserts a dependency into the parent, takes an owning reference to its temporary child stream, begins capture into the CUDA-provided WHILE body and installs a CUDA stream guard. End-capture restores the parent's stream and allocator filter. Consequently the prior metadata is ordered before the first body access, and subsequent parent collectives wait for loop completion. [PyTorch CUDAGraph implementation](https://github.com/pytorch/pytorch/blob/v2.14.1/aten/src/ATen/cuda/CUDAGraph.cpp#L482) · [Stream ownership](https://github.com/pytorch/pytorch/blob/v2.14.1/aten/src/ATen/cuda/CUDAGraph.h#L208) · [Python binding](https://github.com/pytorch/pytorch/blob/v2.14.1/torch/csrc/cuda/Graph.cpp#L122)
- Humming 0.1.12 passes its host-encoded TMA descriptors by value to an ordinary launch on PyTorch's current stream. Its output TMA descriptor update is compiled out under V102's grouped setting. The SiLU wrapper's `LaunchKernel` resolves `TVMFFIEnvGetStream`. The pinned Apache TVM FFI 0.1.11 PyTorch fallback calls `torch._C._cuda_getCurrentRawStream` on the first CUDA tensor, and its native adapter calls `at::cuda::getCurrentCUDAStream`. Both paths set and restore the FFI environment stream around the function call. The raw Humming, Triton and SiLU kernels therefore use the guarded child stream. The fixed metadata and all expert inputs and outputs are device-local. [Humming source release](https://pypi.org/project/humming-kernels/0.1.12/) · [Apache TVM FFI source release](https://pypi.org/project/apache-tvm-ffi/0.1.11/) · [CUDA conditional body requirements](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/cuda-graphs.html#conditional-node-body-graph-requirements)
- The TP-wide vote in V102 still selects the outer breakable-graph boundary uniformly. Conditional support and the number of required waves may differ by rank. All five body operations and the cursor advance are local; each rank reaches the same following collective in the same order. The setup probe exercises a two-iteration replay and a zero-iteration replay once per device. It catches PyTorch's unsupported conditional configurations, including its explicit prohibition on `graph_capture_record_stream_reuse`. The graph-cache signature now distinguishes every live conditional node handle and recurses through ordinary child graphs. The registry retains raw graphs until closure, preventing handle reuse between live entries and bypassing whole-graph updates across these conditional captures. [CUDA whole-graph update restrictions](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/cuda-graphs.html#graph-update-limitations)
- H200 execution, full captured-stack numerical agreement, memory cost of retaining separate graph executables and serving latency remain open. The scalar setup probe only validates CUDA conditional control flow. A full-stack replay is needed to validate capture, JIT registration, PyTorch graph-pool ownership and driver interaction together.

## Isolated startup capture

The final probe uses a fresh non-default stream, a default-constructed CUDAGraph with its own graph pool, and direct `capture_begin(capture_error_mode="thread_local")`. Tensor initialization, the first predicate, capture and both replays are ordered on that stream. The two scalar reads synchronize its results. This avoids the global synchronization and allocator-cache clearing performed by the general graph context. The tuple check reads the PyTorch CUDA build version. The probe exercises the actual driver. [PyTorch capture wrapper](https://github.com/pytorch/pytorch/blob/v2.14.1/torch/cuda/graphs.py#L576)

With `graph_capture_record_stream_reuse=True`, PyTorch throws at CUDAGraph.cpp line 489 before it creates a conditional handle or child, or changes the allocator filter or current stream. The parent remains active. The probe's `finally` closes the parent on its original stream, the outer exception handler selects the existing V102 loop and the graph releases its pool at destruction. Thread-local capture scopes CUDA's checks for potentially unsafe calls and does not override PyTorch's allocator-setting check. [Pinned allocator check](https://github.com/pytorch/pytorch/blob/v2.14.1/aten/src/ATen/cuda/CUDAGraph.cpp#L482) · [Parent capture cleanup](https://github.com/pytorch/pytorch/blob/v2.14.1/aten/src/ATen/cuda/CUDAGraph.cpp#L208)

Both the startup probe and the production grouped body now close each successfully opened child inside its own `finally`. The probe closes the parent in its outer `finally`. An independent CPU error-injection fixture executed the final startup function with a modeled rejection before child creation, an exception during the child body, and an exception from the conditional-handle setter. All three selected V102. The pre-entry case ended only the parent. The latter two ended the child before the parent. Physical CUDA replay remains the deployment gate.
