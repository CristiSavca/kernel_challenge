# V154 backup dispatch and potential impact

The scored V64 TP0 startup allocates staging for the 16 full, 46 sliding, and 5 draft layers. Its submission enables hierarchical cache. The launch transcript truncates the write-policy fields. The pinned defaults resolve to write-through, kernel I/O, and page-first host layout. The team's separately archived V41 eight-H200 server reports those three settings explicitly. Each K (or V) all-layer payload per physical page is 2,048 B, 5,888 B and 1,280 B respectively at page size one. This puts all three below the 128 KiB CUDA batched-copy threshold. [Scored startup](../../runs/abd217baf0ed49fd.log#L153) · [V41 server settings](../../../experiments/modal_node/20261113T204343Z-bench/results__20261113T204343Z-bench__v41__server_info.json)

The pinned host allocator hands out a prefix of initially consecutive page IDs. Freed runs return after previously unused pages. The scored run configured 22.7M full and draft host locations and 5.68M sliding locations. The GPU gather can reorder arbitrary physical source pages before coalescing consecutive host destinations within each 64-page staging chunk. In the independent fixture a 133-page fragmented allocation with four contiguous regions reduced 266 descriptors to 12. Singleton fragmented pages retained one descriptor per plane and page. The fixture exercised three pool geometries, offsets and views, 63/64/65 boundaries, four host layouts/six dispatch branches, and 13,699,104 bytes of K/V. The actual Python host backup, allocator and transfer wrapper ran against CPU tensors and an emulated native transfer. H2D restore retained the stock entry. [Independent source](independent_dispatch.py) · [Recorded cases](independent_dispatch.json)

A size scenario illustrates which latency must disappear to matter. Assume 74,160 first-prompt tokens, twelve later inputs of 753 tokens, thirteen outputs of 220 tokens, every token backed up once by all three pools, contiguous runs, and perfect initial chunk alignment. The 86,056 token locations save up to 508,266 per-rank host copy descriptors per conversation. The same data bytes still go over the link. For the official V64 mean per-user throughput, raising each rung from its measured speed relative to stock to 3× requires net *critical-path* savings of approximately 22.3/11.6/6.7/5.5 µs per removed descriptor at 1/4/16/32 users. At 4× they become 25.9/13.9/8.5/7.1 µs. Ranks operate concurrently. Sliding eviction, interrupted chunk runs, repeated backups and asynchronous overlap can all change this calculation. Reported cache hits alone reveal neither backup volume nor restore cost. The C++ output parity establishes correctness; a matched V154c private /16 versus measured V64 /16 is the useful timing experiment.
