# V154 coalesces small HiCache backups on V151

SGLang first gathers scattered device pages into a contiguous staging tensor. For small pages, its next step submits a separate asynchronous device-to-host copy for every page of K and every page of V. V154 scans the existing CPU destination indices and sends each consecutive range with one copy on the original transfer stream. A gap, reversal or repeated destination ends a range. Source ordering, destination ownership, cache contents and completion events follow the original backup. The 128 KiB batch-copy threshold is checked before building the descriptor lists. Large-page CUDA batch transfers keep their existing selection. [One-header change](delta.diff) · [Full patch](patch.diff)

The scored V64 worker prepared the 64-page staging buffers for its 16 full-attention, 46 sliding-window and five draft layers. At page size one, their K pages are 2,048, 5,888 and 1,280 bytes respectively. For a 16,384-page backup of any one of these pools with contiguous host destinations, the original helper issues 32,768 small D2H calls. V154 issues 512 and moves the same bytes. Completely fragmented destinations still require 32,768 calls. The score receipt does not report how many pages were actually backed up, the run lengths of their host slots, or how much transfer submission overlapped model execution. The measured 92% prefix-hit rate cannot establish any of those quantities. The host fixture executed the original and candidate C++ functions under four simulated runtime configurations, covering both copy paths, failed batch submissions, byte offsets, ragged allocation order, repeated fallback destinations and unmodified guard bytes. A Linux run exercised the same cases under AddressSanitizer and UndefinedBehaviorSanitizer. The separate pool test used SGLang’s allocator, frees and normal backup entry, then compared 13,699,104 bytes. All six TVM-FFI entry variants compiled with CUDA 12.9 for both SM90 and SM90a. Physical H200 transfer cost, overlap and serving metrics remain unmeasured.
