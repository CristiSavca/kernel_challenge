# Cross-expert overlap in V224 decode

**Keep V224’s two expert projections.** We tested whether W2 could begin on completed expert rows while W13 still runs for other experts. This schedule would preserve every BF16 intermediate and the existing FP32 K reductions. It would also preserve the number of packed weight requests. On the two available H200 route histograms, the native phases already fill enough SM waves that the proposed schedule saves zero waves in the model. At one user it has some modeled headroom, small relative to the observed complete verification period. V226 is a feasibility result. ## What the active path does

On V224, the planner and gather stage the target token rows. The fused W13 kernel produces one scaled BF16 SiLU product per live route and intermediate feature. W2 reads those activations and writes its BF16 result into the retired W13 input arena. The finalizer performs the per-expert scale, RMS and ordered weighted sum. We compared seven decode source sections directly with V213. All matched its frozen patch, including the live K-reduction, gate/up epilogue, paired stage release and W2 launcher. The pinned Humming executor launches a persistent grid and strides over output tiles. V224’s custom W13 launcher uses the device SM count. [V224 full source](../v224_packed_prefill_serving/patch.diff) · [V213 compiled resources](../v213_live_decode_expert_reduction/sm90a.json) · [Published launcher and scheduler checks](native_grid.json)

Both projections assign exactly 32 output-channel CTAs per live row tile. W13 covers 8,192 channels in 256-channel tiles and W2 covers 4,096 in 128-channel tiles. At M = 8, 16 and 24 both have 640 threads and 96 registers per thread. Two identical CTAs would require 122,880 registers on a 65,536-register SM. Each live row tile reads 18 MiB of W13 and 9 MiB of W2 packed weights and scales. At one-user target verification each of eight input rows selects eight distinct experts. Every selected expert fits in one M8 tile. A second output tile reads a disjoint channel range. [W13 tuner](../v191_decode_gate_up_epilogue/config.json) · [W2 tuner](../v205_steady_decode_weight_pipeline/configs.json) · [Hardware histogram and memory counters](../../../experiments/iterations/20261104-moe-hardware-profile-recovered.json)

Eliminating the remaining intermediate requires coordinating all W13 output channels before a W2 owner has the full input for its K reduction. At one user and balanced TP8 routing, the BF16 write and read amount to **0.125 MiB per rank per layer**, versus **193.80 MiB** of unique expert weights. At 32 users they amount to 4 MiB versus 863.74 MiB. The observed 32- and 256-row rank histograms give 0.609 and 5.531 MiB of intermediate payload versus 432 and 891 MiB of packed requests. V122 already exchanges these intermediate features in cluster shared memory. Its eight-CTA implementation exposes few clusters at low load. V126 increases parallelism by splitting K and demonstrably changes rounded output on legal inputs. V86/V89, V141, V161 and V174 instead change the input and packed-data loaders or the number of live rows sharing each fetch. V216 covers multicast across repeated *row* tiles. None of these mechanisms removes the first packed sweep for a selected expert. ## Cross-expert scheduling result

A W2 tile may run after all 32 W13 channel jobs for its own expert-row tile complete. Other expert-row tiles remain independent. The constructive scheduler assigns free SMs to outstanding W13 jobs first and then to ready W2 jobs. In the model there are 132 identical, work-conserving SMs. With durations 2 for one W13 job and 1 for one W2 job, T live expert-row tiles give a native bulk time of `3 ceil(32T / 132)`. Any feasible schedule must take at least `ceil(96T / 132)` for the work, and at least `2 ceil(32T / 132) + 1` for the last W13 job and its dependent W2 job. Our schedule attained the larger of those lower bounds at every T from 1 through 512. The source also tests four alternate duration ratios. Real H200 CTA service times and memory contention can depart from these assumptions. [Rank and dependency simulation](check.py)

A merged persistent implementation would need to publish each expert-row tile’s complete activation with device-wide release/acquire ordering, ensure waiting W2 jobs cannot displace their required producers, and retain full-K rounding and V224’s fallback contracts. The potential return at the high-load rungs does not justify that production change on this evidence. A matched, phase-resolved W13/W2 trace on an actual low-load V224 serving run would distinguish idle-tail recovery from bandwidth already consumed by the other active CTAs. This investigation used host simulation and read the public pinned wheel in memory. No compiler VM, remote GPU, judge check or campaign change was required.
