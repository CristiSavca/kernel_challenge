# V142 sharded expert input and output projections

V142 gives each tensor-parallel rank its own output rows of the two BF16 matrices that project tokens into and out of a Muse NVFP4 expert layer. The native checkpoint loader installs each rank's slice. Each dot product still uses the full input width. The new switch is disabled by default. Eligible H200 ranks agree on the checkpoint layout before creating the model layers. The patch extends V139 and takes its four launch flags plus `--muse-shard-expert-projections`. [Patch and flags](validation.json) · [Parent](../v139_integrated_experts_verify/README.md)

At TP8 with dimensions 8,192 and 4,096, the two weights occupy 16 MiB per GPU per sparse layer, down from 128 MiB. That saves 112 MiB per layer, or 6.78 GiB for the source configuration's default 62 sparse layers. This is parameter storage. The serving memory allocator, KV capacity and graph pools determine observed process peak. At eight verification rows V64 can already project a local eighth of the output matrix on its multicast path. In that case the potential cold weight reads fall from 72 to 16 MiB per rank for the pair. At larger replicated shapes that previously ran both full GEMMs, the corresponding figures are 128 and 16 MiB. Physical HBM traffic and kernel time depend on caching and the chosen GEMM kernels. [Geometry](geometry.json)

Replicated inputs use a local GEMM followed by an output-column gather. An eligible fused feed-forward boundary takes the local output columns directly. During sequence-parallel prefill, small token shards gather the inputs, project local columns, then exchange the result back to each token owner. Large shards gather a matrix and project each rank's local tokens. At the stock dimensions the switch happens above 481 local rows for the input projection and 819 for the output projection. The long path can add 112 MiB of collective ring payload per GPU per sparse layer and temporarily materialize a 64 MiB matrix. Long-prompt latency and graph memory therefore matter to promotion. [Projection delta](delta.diff)

The real Muse loader and forward methods ran over BF16 CPU Gloo at TP2, TP4 and TP8 with synthetic weights, distinct rank/token contents, strided inputs and checkpoint reloads. Across the ranks, 784 projection pairs matched a full-matrix reference for 3,338,496 intermediate and output elements. Another 84 checks verified the column slices consumed by the fused FFN boundary. Independent tests exercised the native capture and PyNccl wrappers with a CPU pointer transport across 420 peer exchanges, including the regression that requires flat contiguous buffers. H200 collectives, numerical agreement, throughput, time to first token and peak memory still need a judge run. V142 has no private reservation.
