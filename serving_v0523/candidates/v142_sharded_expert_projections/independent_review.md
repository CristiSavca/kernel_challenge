# V142 projection and collective review

The sequence-parallel activation path now passes contiguous flat BF16 views to the pinned PyNccl exchange. The producer stores each destination's token rows contiguously; on receipt the source rank indexes the output-column shard. Transposing source and token dimensions before reshaping recovers each token's original column order. The original two-dimensional call failed inside PyNccl because it divides the element count by the world size and uses that count to narrow dimension zero. The focused regression executes the actual projection, graph-capture context, group dispatch, stream selection and PyNccl send/receive methods with host-side pointer transport. It checked 15 layouts at TP2/4/8, 70 rank projections, 420 peer exchanges and 1,732,752 BF16 words including signed zero and NaN payloads. All 70 old matrix-shaped calls failed the native narrow check. Physical CUDA/NCCL replay and elapsed H200 time remain unmeasured. [Test](py_nccl_check.py) · [Receipt](py_nccl_check.json)

The constructor selects the same TP rank order as attention TP, performs one CPU-group readiness vote before partitioning weights, and uses ColumnParallelLinear's original full-checkpoint output-row loader. Both projections retain their full input dimension. The sequence-parallel conversion restores the rank's own token rows before routing or the FFN residual. The post-expert branch performs the ordinary expert reduction first and defers its local projection shard only when the existing FFN gather/normalization boundary accepts it. The decoder checks the returned width before using this boundary. This preserves the existing small-batch fused path on multicast-enabled machines. Different GEMM shapes can change last-bit rounding and require the official correctness check.

For each 8,192→4,096→8,192 projection pair at TP8, resident weights fall from 128 to 16 MiB/rank. At one user and width eight, the incumbent H200 post-expert projection can already read its 8 MiB output-channel shard. The pre-expert projection alone can avoid 56 MiB/rank of distinct weight reads at this load. At higher decode loads where the original H200 post-projection does full work, both halves can benefit. At a 16,384-token prefill chunk (2,048 local rows), both V142 calls choose to gather full weights. Each rank then receives 112 MiB of peer weight payload per sparse layer, with a temporary full weight matrix of 64 MiB for each call. These are element counts for individual operations.
