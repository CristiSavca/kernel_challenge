# V129 routed projection pair

V129 replaces V64’s indexed expert execution at low routing density with three ordinary CUDA launches. A planner groups the original route slots by expert. The first projection reads each selected token directly from the hidden-state matrix and writes the scaled SiLU activation to the route’s original slot. The second projection reads that slot and writes its scaled BF16 output at the same position. The existing V64 finalizer normalizes and combines the outputs in the original route order. The official V64 parent has a measured full score of 1.4119×. V129 has no H200 measurement. [Official V129 patch](patch.diff) · [Three-file delta](delta.diff) · [Parent handoff](../../../CODEX_HANDOFF.md)

Each warp owns 64 output channels and applies one tensor-core MMA per channel fragment for each consecutive 16-element K tile. A single FP32 accumulator for each output covers the full K dimension. Two warps form an independently scheduled 128-channel block. W13 rounds its projection result to BF16 before and after scaling, then runs the stock CUDA SiLU helper and rounds the product with up to BF16. W2 also rounds both before and after global scaling. The packed E2M1 weight codes and E4M3 scales come directly from V64’s existing Humming bank. V64 uses vendor WGMMA in applicable configurations, so matching the mathematical reduction and BF16 boundaries still leaves hardware instruction-level rounding and model agreement to check. [Numerical test](warp_check.py) · [Cancellation examples](order_check.py)

V86 and V89 split W13’s K reduction across warps. V90 and V94 fused SiLU into the later W2 phase at higher routing density. V125 put each complete expert tile in one eight-block cluster, and V126 spread it across multiple clusters with FP32 reduction partials. V129 distributes output channels among ordinary blocks and writes only the BF16 intermediate needed by the next projection. This removes global or shared K partials, cross-block barriers, explicit activation gathering, the materialized gate/up matrix and two scale sweeps. A different physical weight swizzle would also require changing every Humming consumer or keeping a second packed bank. At 864 MiB per routed layer and 62 layers, retaining two full topologies would add more than 52 GiB per GPU. ## Work and storage

The device planner assigns a warp to each local expert in turn. It packs valid slots into groups of eight in original slot order. Each warp atomically reserves space for its records. Their cross-expert order can vary freely since every route owns its activation and output. Both projections read the job count written by this invocation and grid-stride through skewed or concentrated routes. Their three kernels run on the same stream. Invalid slots and the unused plan tail can retain values from a previous graph replay. [Independent planner and dispatch review](independent_review.md)

The intended gains are fewer launches and more independently schedulable blocks at small batch sizes. The cold packed bank still takes at least 42 µs or 120 µs per eligible layer at peak H200 bandwidth. Each output warp issues its own input loads, totaling 4 or 16 MiB of logical reads per projection. Cache behavior, small-block occupancy and vendor pipelining determine whether the new path wins against V64. A fourfold increase in the number of blocks relative to a clustered geometry is a scheduling property. [Reproducible work model](work_model.py) · [Numbers](work_model.json) · [H200 specifications](https://www.nvidia.com/en-us/data-center/h200/)

The adapter checks Hopper capability, the WGMMA-packed bank ABI for both projections, storage and scale types, width and stride constraints, input alignment, and deterministic runtime and environment settings. The dispatch admits at most one route slot per global expert on average, 1,024 total slots and 64 local experts. With the native eight verification rows and top-eight routing it covers full batches at one and four users. Full 16- and 32-user verification batches use V64’s existing indexed path. A module build failure selects V64 at initialization. The local switch `SGLANG_ENABLE_MUSE_SPARK_ROUTED_PROJECTION_PAIR=0` disables the new path. The candidate uses V64’s exact four accepted launch flags. [Manifest and flags](validation.json) · [Dispatch cases](dispatch.json)

## Verification

- CUDA 12.9.86 compiled the production TVM FFI wrapper and all three kernels for SM90 and SM90a. W13 uses 63 registers/thread, W2 uses 40 and the planner uses 32. The compiler reports zero spill loads and stores throughout. W13’s inner K loop has 328 static instructions including eight HMMA sites. W2 has 170 including four HMMA sites.
