# Owner reduction on Hopper

Triton 3.8 compiled the final 5,677-byte production module `c2ddd4d8…09fe2` for every rank in worlds of 2, 3, 4, 5, 7, 8, 13 and 16. Three additional TP8 builds used a 64-bit runtime receive stride. All 61 SM90 cubins used 16–32 registers per thread, zero spill bytes and zero shared memory. At four warps per block these resources admit up to 16 blocks per H200 SM. No H200 execution time has been measured. [Compiler receipt](sm90.json)

The CPU interpreter ran the production JIT on 464 BF16 output cases plus 464 diagnostic FP32 output cases. Inputs included zero-length rows, nonuniform pitches, offsets and tails around a 256-element boundary, cancellation, and negative zero on every contributing rank. All 7,330 output canaries for each destination type and all 3,419,460 input words survived. Each of 328,164 FP32 accumulator results matched the reference bit for bit in ascending source-rank order. All 19,314 all-negative-zero lanes retained their sign. Reversing the source order changed 18,760 final BF16 outputs. Rounding to BF16 after each source changed 108,077. [Fixture](kernel_check.py) · [Interpreter receipt](interpreter.json)

The stock Triton CPU interpreter truncates an implicit BF16 store. Its BF16 destination matched the nearest-even oracle on 235,344 values and the truncating oracle on the other 92,820. Applying nearest-even rounding to the independently observed FP32 accumulators matched the expected BF16 bits for all values. With three or more ranks every tested compiled kernel used FP32 additions and a final nearest-even conversion. The two rank-pair kernels folded the operation into a native BF16 add with default nearest-even rounding. None of the 61 emitted PTX variants used a flush-to-zero modifier. Exact integer arithmetic confirmed the direct and FP32-intermediate two-input operations agree on 134,640 finite pairs, including every exponent gap, subnormal and overflowing results. Results establish the compiled local reducer’s operand order, boundary behavior and instruction/resource profile. Agreement with the incumbent collective depends on its actual reduction order. End-to-end throughput, allocator behavior and effective GPU occupancy still require physical measurements.
