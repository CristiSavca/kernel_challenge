# V131 exact target verification pruning

**Keep the native width-eight target pass for the measured V64.** Splitting verification preserves every accepted token in the CPU oracle, but nearly all of the one-user cold-weight saving disappears when the second pass rereads the dense projections. At the other three official loads the model predicts more bytes per sparse layer. The measured score remains 1.4119×. V131 is a feasibility study with no production patch or judge submission. ## Two target passes with exact continuation

Run target rows zero through r−1 with native causal semantics. If any of the r predictions differs from the corresponding proposal, the earliest mismatch yields the ordinary bonus token. If all r match, run the remaining 8−r rows for those requests, reusing the just-computed causal KV. This retains the possible eighth committed token. Across every native seven-comparison pattern and every r from one through seven, the CPU oracle agreed with the pinned accept-and-commit functions on all returned IDs and lengths (896 comparisons). This validates the decision for identical target predictions. Changing GPU GEMM and attention shapes can change rounding, and a continuation requires correct per-request physical KV, request and graph state. Each row minimizes projected bytes among the seven split positions. The model fits independent proposal-match probability to the rounded V64 mean commits at that load and samples distinct top-eight expert IDs uniformly across 256 experts, independently by target row. For m target rows, the expected number of distinct local experts is 32×(1−(31/32)ᵐ). The model charges 27 MiB per touched local expert per nonempty stage. The gated QKV and attention output matrices occupy 36+16 MiB/rank, the FP32 router 8 MiB, and the V64 pre-expert projection 64 MiB. Its post-expert projection adds 8 MiB for at most eight rows when SM90 multicast GEMM is available, otherwise 64 MiB. Attention output depends on the QKV result and cached keys/values, so these two full-K projections cannot be combined as one linear map. An independent graph stage can reread each dense bank, even though it processes fewer rows. The table excludes repeated full/SWA KV traversal, launch and decision time, and cache hits. The H200 wall time for these operations remains unmeasured. A full-attention layer has two local FP8 KV heads of width 64, or 256 bytes of unique keys and values per history token per rank. The added history read can matter on long turns. Measured mean acceptance alone permits **0–60%** continuation at split five. The table’s 30.1% is an assumption. ## Exact target-head mismatch witnesses

Even a partial candidate set can prove that a greedy proposal fails. If any candidate has a strictly higher native **post-softcap** target score than the proposal at row j, no later row can affect this step. All candidates before the first proven failure still need their native global winners, including the failure row to obtain the correct bonus. A witness-only prepass never removes a necessary result in 2,187 combinations of matches, witnessed mismatches and unwitnessed mismatches. This assumes finite native scores and the stock tie behavior. A different sparse-dot reduction cannot certify a close decision without a rigorous error bound. [Witness cases](check.py) · [Stock reduction, NaN, ties and rounding examples](../v121_target_head_feasibility/README.md)

Even an oracle identifying the earliest mismatch leaves an average 4.0 of eight target-head rows at one user, and 4.2 at 32 users. Every remaining target row still has a dot product against every vocabulary weight. A batched dense GEMM can reuse the same 394.625 MiB local weight bank across rows. Saving half the row-wise operations does not halve those distinct bytes. At one user, all eight rows total 3.31 GFLOP/rank, while the illustrative pass period from V64’s mean commitments and median decode throughput is 19.7 ms. A threefold reduction of that period requires saving about 13.1 ms. The judge provides no evidence that the head consumes that time, and a perfect twofold improvement of the entire head alone cannot triple the pass. ## Reusing the draft vocabulary head as a certificate

The draft uses the target output weight on another hidden vector. If u bounds the largest omitted draft logit, B bounds every omitted weight-row norm, and Δ is the target minus draft hidden vector, every omitted raw target logit is at most u + B‖Δ‖. A strict gap versus the best rescored draft top-16 entry can certify the target winner. The implementation would need a valid upper bound on native rounded scores, one that includes the draft projection’s BF16 output, the target's FP32 accumulation, monotone scaling, softcap saturation and ties. Native DFLASH exposes only seven corresponding draft prediction rows and transforms unary scores for its selector. [Draft head and selector](../../sglang/python/sglang/srt/models/dflash.py) · [Target numerical requirements](../v121_target_head_feasibility/README.md)

In 32 synthetic runs at the full 202,048-token vocabulary and 8,192 hidden dimensions, target winners belonged to draft top-16 in all 32 trials at cosine similarity 0.999, but the global-norm certificate succeeded zero times. At 0.9999 it succeeded once, and it reached 29 successes at 0.99999. These are Gaussian weight rows, fixed correlated hidden vectors and optimistic real arithmetic. Official checkpoint weights and activation correlations were unavailable. A checkpoint trace showing frequent strict certificates after conservative numerical margins would justify revisiting this approach. The competition requires lossless output and prohibits approximate or skipped model work. None of the synthetic tests establishes judge eligibility for a surrogate winner.
