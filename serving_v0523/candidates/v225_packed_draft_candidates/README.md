# V225 packs the native draft selector's candidate exchange

V225 reduces the selector's proposal exchange from two tensor-parallel all-gathers to one. The judge's eight-position DFlash block has an anchor and seven prediction positions. Each position still runs the complete target-head projection and the native deterministic local top-16. The captured selector sends each BF16 score's original 16 bits and its shard-local vocabulary index in one 32-bit word. The receiver reconstructs the same ordered FP32 score matrix, calls the original global `torch.topk`, and adds the sender's actual vocabulary offset to the winning indices. [V224 parent](../v224_packed_prefill_serving/README.md) · [Patch](patch.diff) · [Two-file change](delta.diff)

For 202,048 vocabulary entries across eight ranks, the 25,256 local entries fit in 16 bits. Each rank now contributes four bytes per candidate. V224 contributed twelve, comprising an FP32 score and an int64 global ID. The table counts logical peer bytes per rank for a ring all-gather at the four judge loads. Actual NCCL wire traffic and timings depend on its selected algorithm. [Vocabulary dimensions](../v91_reduced_target_argmax/README.md) · [Prior judge capture log](../../runs/04b01f958aa5487c.log)

The captured implementation gathers directly on dimension zero. Three small integer kernels pack words, order score bits for the global top-16, and reconstruct the winning IDs. The original ATen widening and top-16 remain separate. V224's two last-dimension gathers each reordered rank-major data into row-major form. The public head still has 394.625 MiB of BF16 weights per GPU. A wall-clock gain requires the saved collective and reordering to outweigh the new integer operations. The private V68 log records use of the captured selector, but has no per-kernel breakdown for this exchange. V225 has no H200 timing, correctness result or score. The official four-load best remains V64 at 1.4119×. [V68 result](../v68_grouped_decode_verify/README.md)

The captured selector gathers the rank-ordered offsets and eligibility once on its existing CPU group. Eligibility requires the native compute method, a CUDA dense BF16 head, disabled autocast, a valid local vocabulary with at least K and at most 65,536 entries, compatible K across ranks, and representable int64 offsets. A nonqualifying peer returns the whole group to the native path. Eager proposals, single-rank execution and LiLiCorr's partition function use the existing code. Captured graphs own their offset tensor and fetch new metadata on a fresh sampler build. The graph continues to read updated in-place head weights.

## Validation

- Four real CPU Gloo ranks ran the production model's candidate projection, rank merge, lattice and registered selector callback. Across 12 forwards per rank at B1, B4, B16 and B32, they matched 1,113 output tokens, 17,808 candidate IDs and 17,808 greedy/sampled proposal probabilities per rank. Eight asymmetric startup cases declined across all four ranks. The native partition path kept three gathers. [Distributed replay](distributed.json) · [Fixture](distributed.py)
- The actual CPU Inductor compiled all three integer kernels. The comparison covered 89,280 candidate words and all 65,536 BF16 bit patterns and local IDs, including signed zeros and signaling NaNs. Both score bits and the original top-16 slot indices matched. An earlier local draft exposed a compiler canonicalization of signaling NaNs. The final version keeps tensor dtype reinterpretation outside the integer kernels. [Compiled result](compiled_words.json) · [Reproduction](compiled_words.py) · [Original failure](compile_regression.json)
- An independent replay covered all bit patterns over 327,680 score/ID pairs. Across 108 TP2, TP4 and TP8 cases, 32,616 winning token IDs and FP32 scores matched V224 bitwise. An independent capture audit traced the sampler to the pinned FlashInfer implementation and CUDA int32 collective. [Independent transport](independent_transport.json) · [Production reach](independent_reach.json)
- The full official CLI export reconstructs from the public pin and V224 by both routes and applies in reverse. It has 52 changed paths, 370,398 bytes and exactly the six V224 launch flags. All 720 flag permutations passed, and Pyflakes found zero new undefined names in 45 Python files. [Rules and hashes](validation.json) · [Flags](flags.json) · [Names](global_names.json)

V88a's fused proposal head changed the local implementation and could change proposal order at ties or near rounding boundaries. V225 preserves the native GEMM and both top-16 operators. V184's off-path KV and V200's guessed next-block inputs cannot substitute for target-confirmed prefixes while preserving native proposals. The full dense head and the trained selector still process every required prediction position.
