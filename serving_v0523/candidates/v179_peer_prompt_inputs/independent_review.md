# Peer reads, setup and synchronization

Triton 3.8 compiled ten production reader shapes for Hopper. PTX retained raw 16-bit global loads and stores and signed 64-bit source division or remainder. PTXAS reported 20–38 registers per thread and zero spill. The production host wrapper and interpreted kernel copied 1,648,425 BF16 words in 105 cases, checked all 65,536 encodings and preserved 1,890 guard words. Two address probes read valid host allocations with global token IDs over three billion and row-element offsets over two billion. The tests use 2/4/8 separate peer addresses, empty lists, permutations, repetition, padded rows, base offsets and hidden widths straddling the 2,048-element tile. [Compile results](independent_compile.json) · [Interpreter results](independent_interpret.json) · [Fixture](independent_kernel.py)

The final startup allocates one raw symmetric segment on each participating device and votes on equal width, minimum capacity and local allocation success before rendezvous. The rank-local peer view must match the published storage address and have zero offset. The raw allocation avoids sharing a signal pad with an implicitly pooled tensor. The pinned native bindings accept the exact arguments, expose the offset and map peer tensors relative to the allocation. The vote reuses the existing all-gathered eligibility byte. Every rank takes the same communication branch and keeps the original sparse return width. Within eligible eager graph breaks, a dedicated per-model stream waits on the caller, publishes the copy, executes the peer read and retires it before the next layer reuses storage. Empty receivers participate in both barriers. The calling stream joins before consuming the result. The retained handle, peer views, stream and per-call input references cover the queued work. The pinned CUDA barrier launches on the current stream for the handle's device. V64's scored trace reported working multicast and pull at TP8. Model initialization and the data-dependent branch establish source reachability. A physical H200 execution is still needed for time, peak memory and inter-rank behavior.
