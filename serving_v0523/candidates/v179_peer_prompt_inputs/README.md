# V179 reads routed prompt inputs directly from peer GPUs

Each participating rank publishes its shard of the BF16 expert input to a private symmetric allocation. A Triton kernel copies just the rows this rank's experts need, in their original order. The original expert return and accumulation follow. A unanimous admission check covers allocation, address and capacity on every rank. All participating ranks enter both device barriers, including ranks with zero rows to read. The copy, peer read and retirement use an ordered model-owned stream. [Implementation delta from V176](delta.diff) · [Source and transport review](independent_review.md)

At a 16,384-row prompt with uniform distinct top-eight routing across eight ranks, the model reduces logical tensor traffic from 338.86 to 201.43 MiB per rank per eligible layer. The estimated remote payload is 74.13 MiB in both paths. The difference comes from removing packing and intermediate copies. The new path requires up to 16 MiB of resident workspace per rank for this shape. Actual routing, barrier latency, NVLink reads and allocator peak determine the benefit on H200. The scored V64 run used 1.9 GB/GPU above stock against a 2.0 GB limit. [Traffic assumptions and trace](traffic.json) · [Scored V64](../../runs/abd217baf0ed49fd.json)

Distributed CPU tests exercised 672 rank-local replays at TP2/4/8, comparing 2,123,520 BF16 owner elements, including ranks with no live input. Startup testing covered 84 declined rank cases. A separate Triton interpreter copied 1,648,425 words and every BF16 encoding exactly. Ten Hopper shapes compiled with zero spills. These tests use host substitutes for physical symmetric memory and CUDA inter-rank synchronization. Throughput, peak memory, exact completions and both TTFT guards require physical execution.
