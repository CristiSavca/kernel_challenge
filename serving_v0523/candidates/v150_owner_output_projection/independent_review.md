# Independent projection and transport checks

The regular `RowParallelLinear.forward` method selected the candidate through V150’s actual sequence-parallel row helper. Four and eight Gloo ranks reproduced an independent reference for 403,188 elements across 132 rank cases. Each source performed a full-K projection into BF16 before the reference summed rank contributions in ascending order in FP32 and rounded the local output. Tests covered noncontiguous inputs, zero-padded tails, 1,024 input channels, 8,192 output channels, irregular multistripe writes, dispatcher and ordinary GEMMs, ineligible shapes and the ordinary non-SP route. Synthetic small cases exercised the production operation after overriding its size threshold. The two production thresholds and the 16,384-row, 4,096-channel stripe were also checked directly. [Fixture](cpu_check.py) · [Results](cpu_result.json)

A vector-clock model instrumented real Gloo peer sends and receives on the two emulated streams. All 748 sends had the expected destination and matching source. Each send buffer survived until the allocating stream had ordered its reuse after the simulated transfer read. The test checked all 84 startup rejection cases across four and eight ranks, including a fault or incompatible mode on just one rank. Runtime tests entered autocast and deterministic mode uniformly across ranks. The fixture used PyTorch 2.5.1 CPU and mocked the CUDA transport and Triton epilogue. The physical GPU still determines numerical agreement with V64’s actual all-reduce algorithm, GEMM tile selection, overlap, memory high-water and speed. [Fixture](cpu_check.py)

V64 uses its original all-reduce dispatcher followed by a token slice when NVLS is enabled or unset, graph compilation is active, symmetric memory is enabled, or another accelerated method applies. The remaining path can issue a conventional reduce-scatter. Both return a token shard. For 16,384 × 8,192 BF16 output elements, V150 sends 224 MiB per rank across all seven peers. Eight-way ring all-reduce would send 448 MiB per rank. The official run did not record which NCCL algorithm ran or provide a warm per-layer time. PyTorch 2.14.1’s own fused symmetric-memory operation also makes BF16 rank-local partials, then accumulates the rank dimension in FP32 with a final BF16 store. [Pinned PyTorch implementation](https://github.com/pytorch/pytorch/blob/v2.14.1/torch/distributed/_symmetric_memory/__init__.py#L1401-L1429)

A rank-local change to mutable precision or determinism settings after startup can select different collective routes when transport depends on those settings. The normal service drives a shared runtime configuration. The fixture covers asymmetric startup and uniform runtime settings. An instrumented deployment that changes them on individual ranks needs group agreement before choosing another collective sequence.
