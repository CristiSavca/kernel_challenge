# V119 decode collective feasibility

Keep the V83 output-sharded pooler, router and unpooler for decode. A token-owned replacement would increase the distinct dense weight data read on each rank by 119 MiB per layer when those weights are cold. Across the 62-layer target this is 7.21 GiB per rank per pass. The measured four-user workload has only 32 verification rows. Even with ideal native reduce-scatter at both boundaries, the replacement saves about 0.68 MiB of logical ring send volume per rank per layer at that load. With V64's actual default reduce-scatter helper, it saves just the difference between dense router logits and sparse routing metadata, 26,880 bytes. This is sufficient evidence to decline a private check for this change. [Reproducible source and arithmetic](check.py) · [CPU receipt](check.json)

The model gives both designs the same full-K projection work across TP8. V83 gives a rank 1/8 of each output-channel weight bank for all rows. Token ownership gives each rank all three weight banks for 1/8 of the rows. The latter performs attention reduce-scatter, pooled-feature and routing gather, expert reduce-scatter, and a gather for the next layer’s attention input. Each ideal ring gather or reduce-scatter sends 7/8 of its tensor bytes per rank. The model assumes 32-bit expert IDs and FP32 weights for the eight chosen routes. It measures logical per-rank sends and distinct weight footprints. Actual multicast fabric traffic, cache residency, and elapsed time require hardware measurements. V64’s precision-preserving helper performs the stock all-reduce then narrows under its default NVLS and accelerated communicator conditions. The target attention output all-reduce and the following Muse normalization are separate kernels. The stock SM90 JIT already enables programmatic dependent launch on both. The consumer performs post-RMS, BF16 rounding, an FP32 gated residual, and another RMS. The wider existing cluster variant forms the second RMS denominator from expanded moments prior to that BF16 rounding. With a valid zero gate parameter, a repeating BF16 branch pair of 1 and 2 and an FP32 residual stream, the materialized hidden value is 0.30078125 and the cluster formula produces 0.306640625 in the CPU fixture. This is a legal numerical counterexample for switching the cutoff on Hopper. It establishes a difference in arithmetic, with no inference about its frequency on judge requests. At one user, 62 attention-boundary fusions could eliminate 15.5 MiB of local intermediate writes and reads per rank per verification pass. A specialized fused operation would still need the full peer reduction, its BF16 result, and the small-row router output. Stock one-shot push uses a grid sized to the GPU's SM count while the Hopper norm kernel uses one CTA per row, just eight CTAs at one user. Replacing both with eight independent CTAs trades away most collective parallelism. A cooperative exact redesign could instead exchange true moments of the rounded gated residual. Its next decision point is an isolated H200 timing of the attention reduction and immediately following norm on the actual captured M=8 and M=32 shapes. A crude pass-period estimate from V64's acceptance and median decode rate implies that this boundary alone would need to save approximately 159 and 287 microseconds per layer, respectively, to double current decode throughput. These estimates combine aggregate metrics and do not constitute a kernel profile. New exact expert or acceptance-path experiments take priority in the private queue.
